1Page-level re-ranking and exploration were added at the end of ranking — X

Source xai-org/x-algorithm@5ed7963 — xAI, 2026-10-28, code. In these notes' numbering, this is Gen4+Gen51.4+N is the number these notes assigned in sequence to commits after the 2026-08-13 Gen4 release).

Background In X For You, Phoenix (a Grok-based ranking Transformer) outputs action probabilities for each candidate, and VMRanker (a service that re-selects the slate with DPP) sets the order. The 2026-10-14 commit released training code for the page decoder (an RL re-ranking model that picks, slot by slot, the posts for one page from a pool of top-scored candidates), but it did not show where home-mixer (the service that handles For You requests) uses the result. To train RL re-ranking offline, the log must also contain the probability with which the serving policy chose each order, that is, the propensity (the probability that the policy that wrote the log chose that action). This commit adds a scorer that consumes the decoder result, an exploration scorer that records the probabilities, and a serving log that stores those probabilities, all off by default.

What we learnedA. Page decoder results take the top of the ranking in the stage after VMRanker

  • Two scorers were added at the end of the scorer chain verified — phoenix_candidate_pipeline.rs:466-472.

    • The order is PhoenixScorer, ImmersiveVideoScorer, vm_ranker, PageDecodeRerankScorer, PageRlExplorationScorer.

  • When decoder re-ranking is on, home-mixer sends the decoding settings and the current ranking weights together in the Phoenix request verified — page_decode_rerank_scorer.rs:22-49.

    • The 13 weights, from favorite through min_video_duration_ms, use the cron mirror values as they are (a parameter file that copies production defaults every day). This answers the question the 2026-10-16 commit left open about "the caller that fills RankingScoreWeights".
    • diversity_weight is sent as None.

  • The picks Phoenix returns are placed at the top in slot order, and the remaining candidates follow in their original score order verified — page_decode_rerank_scorer.rs:80-110.

    • No new score values are created. The existing set of scores is reallocated in descending order, giving higher scores in pick order.
    • If there are no picks, the scores stay as they are and the fail_open metric is incremented.
    • A test fixes that candidates 1, 3, and 5, assigned slots 2, 0, and 1, receive the top scores in the order 3, 5, 1.
    • The block above is an abridged copy of params/param.rs:313-365, one line each. The serving slot count in the 2026-10-14 training code was 12, while the default number of steps here is 64.

What we learnedB. The exploration scorer shuffles the order of the top 64 at random and records per-slot probabilities

  • When exploration is on, the top 64 by score are re-ordered with Plackett-Luce sampling (picking one slot at a time without replacement using softmax probabilities, to set the order) over score/temperature verified — page_rl_exploration_scorer.rs:29-110.
    • The default temperature is 0.2, floored at 1e-6. A test checks that when the temperature is close to 0, the original score order comes out unchanged.
    • Candidates outside the top 64 keep their scores and order.
    • Each candidate gets page_rl_exploration_prob, the probability of being picked at that slot.
  • Exploration is not applied to requests where decoder re-ranking is on and a decoder pick exists verified — page_rl_exploration_scorer.rs:129-142.
  • The new serving log writes the scores and per-slot probabilities of the first 64 posts of the feed that was actually served, per request, to Redis in two data centers verified — phoenix_request_cache_side_effect.rs:201-305.
    • The switch EnablePageLogging of this side effect (a stage that only writes logs without changing the response) is false by default, and the default TTL is 3600 seconds.
    • The exploration probability goes into the proto field rewardRerankSlotProb, the decoder sampling probability into pageDecodeSlotProb, and whether the decoder was applied into the new field pageDecoded.
    • Both the For You and Ranked Following pipelines register this side effect.
  • We infer that this probability is the source of the rl_rerank_prob read by the 2026-10-14 training code inferred. The evidence is that the training code reads the same rewardRerankSlotProb field as the logged probability.

What we learnedC. The Brazil election filter was deleted and the target of the new-user NSFW filter was widened

  • The Brazil election filter file and its pipeline registration were deleted verified — README.md #october-26th-2026.
    • This filter removed posts from accounts reported to the Brazilian Electoral Court from For You unless the viewer followed the account. It was deleted after the October 25 runoff.
    • The pre-scoring filters went from 22 to 21.
  • The target of the new-user soft NSFW (non-explicit sexual content) filter, which is off by default, was widened from accounts under 1 day old to accounts under 7 days old verified — params/param.rs:863-879.
    • The account age cap changed from 86400 seconds to 604800 seconds.
    • Instead, users whose scoring sequence length is 100 or more are excluded. A cap of 0 turns this condition off.
  • Eight reported-heuristic label rules were deleted from VF (visibility-filtering, a service that decides per post whether it may be shown to this viewer) verified — rules/tweet_rules.rs.
    • The deleted rules are 6 NSFW_REPORTED_HEURISTICS rules (blur, age-verification tombstone, app-update tombstone, and others) and 2 GORE_AND_VIOLENCE_REPORTED_HEURISTICS rules.
    • Posts that carry only these labels likely no longer get blur or warning-screen treatment in VF inferred. The code does not show whether the labels themselves are no longer generated.

2Andromeda now scores all eligible ads on the GPU — Facebook

Source Meta Andromeda: Powering the Next Generation of Ads Retrieval Through Model-System Co-Design — Meta Engineering, 2026-10-28, blog post.

Background Andromeda is Meta's ads retrieval engine that narrows Facebook and Instagram ad candidates within a few milliseconds. The 2024 post described organizing ads into a trained hierarchical index that outperformed two-tower and ANN (approximate nearest neighbor search). Because of cost, retrieval usually uses a simpler model than ranking, so the balance between accuracy and throughput has always been a problem. This post describes the model structure and GPU co-design of the 2026 version of Andromeda.

What we learnedA. The retrieval model became an MoE and scores all eligible ads on one GPU

  • The retrieval model changed to Mixture-of-Experts (a structure that routes each input to a subset of expert networks for computation) verified — Meta blog post.
    • On the user side, a single tower became an ensemble of several specialized user towers.
    • The ad tower also encodes the real-time serving context.
    • The interaction layer changed from a dense network to a gating network based on MoE attention.
  • The blog post says this model reaches near ranking-level performance at about 1/300 of the inference FLOPs of the 2024 model verified — same blog post.
  • It puts targeting rule application (index matching), scoring, and top-K selection on the same GPU and scores every eligible ad in the candidate pool verified — same blog post.
    • The hardware is NVIDIA GH200, and one server processes more than 1 billion ads per second. The post says network traffic fell about 100×.
    • In this post, index matching is the stage that applies advertiser-defined targeting conditions across dozens of feature categories.
  • The 2024 hierarchical index is mentioned only as a starting point, and its role in the new pipeline is not described verified — same blog post.

What we learnedB. The online result is a 2.4% increase in Facebook conversions since 2025

  • The only online result the blog post reports is a 2.4% increase in Facebook conversions verified — same blog post.
  • Whether this figure is an effect of the 2026 version alone or a cumulative effect since 2025 cannot be determined inferred. The evidence is the period phrase "Since 2025".
  • This post also does not state that the same stack is used for organic feed retrieval verified — same blog post.

"model performance approaches ranking-level in a typical retrieval-then-ranking system, at approximately 300x fewer inference-time FLOPs than the 2024 Meta Andromeda retrieval model."
