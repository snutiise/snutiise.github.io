1Filter that cuts candidates by the same ratio per source is turned on — X

Source xai-org/x-algorithm@989fb91 — xAI public repository, commit of 2026-10-22 06:49 UTC, code. In these notes' numbering, this is Gen4+47. Gen4+N is the number these notes assign in sequence to X commits after the Gen4 release (2026-08-13). The cron mirror (a file that syncs production feature-switch defaults daily and publishes them) has a sync time of 2026-10-21T16:00:32Z. The commit changed 80 files, +3,436/−1,462 lines, and more than half of them are cleanup of the hydration layer in visibility-filtering.

Background X For You sends candidates gathered from several sources to Phoenix (a Grok-based ranking Transformer) for scores, and a request can score at most 2800 candidates. The previous day's commit (Gen4+46) added a filter, off by default, that cuts the same ratio from each served type (the source path a candidate came in through) when candidates exceed this budget. Before that, only the first 2800 of the concatenated candidate list were sent, so sources appended at the end of the list could be cut entirely. This commit turns this filter's switch on in the cron mirror and adds a soft NSFW filter for new users and safety rules for reaction posts.

What we learnedA. The same-ratio-per-source filter is on by default from this commit's cron mirror

  • The mirror default of EnableFairShareRanking changed from false to true verified — home-mixer/params/param.rs:1206-1211.

  • The filter's position is unchanged: the very end of the pre-scoring filter list verified — phoenix_candidate_pipeline.rs:443.

  • So for requests over the budget, each source is now cut by the same ratio instead of all sources at the back of the list being cut inferred. The evidence is that the filter's budget equals the 2800 cap at which the Phoenix request truncates, and that a test pins the same ratio per source (daily 2026-10-22).

  • The mirror value is only the production default, and per-experiment-bucket overrides are not in the public code verified — caveat of the x.md weight mirror. So we do not assert that it is on for all traffic.

What we learnedB. A filter that drops soft NSFW OON posts for users under one day old was introduced, off by default

  • When on, it removes posts labeled soft NSFW (sexual content that is not explicit) from OON (accounts the viewer does not follow) in For You for viewers whose account age is under one day verified — filters/new_user_soft_nsfw_filter.rs.
    • The switch EnableNewUserSoftNsfwFilter is false, and the account age cap NewUserSoftNsfwFilterMaxAccountAgeSecs is 86400 — params/param.rs:804-815.
    • Account age is computed from the creation time embedded in the user ID (snowflake). It does not apply to topic requests, Following, or score-only requests.
    • In the list, it was placed right after CoreDataHydrationFilter — phoenix_candidate_pipeline.rs:416.
  • The label comes from a new hydrator, which fetches it from the safety label service of VF (visibility-filtering, a safety layer that decides per post whether it may be shown) verified — candidate_hydrators/new_user_soft_nsfw_label_hydrator.rs.
    • It does not look up followed accounts, the viewer's own posts, or cached candidates that already have a label.
    • If the lookup fails or the label is unknown, the post is kept. The tests lookup_failure_keeps_the_post and failed_call_keeps_every_post pin this fail-open behavior (pass the post when there is no verdict).
  • There are now two OON filters for new users: the engagement threshold filter and this one verified. We infer it is a device to avoid showing borderline sexual content as OON recommendations in a new user's first-day feed inferred. The evidence is that it targets only OON and the age cap is one day.

What we learnedC. Reaction posts now inherit the safety label of the original post

  • If the original post has an adult content or violence label, a post made in reaction to it is also blurred (hidden behind a warning screen) verified — visibility-filtering/rules/tweet_rules.rs.
    • For adult content it checks the NSFW_HIGH_PRECISION label; for violence, the GORE_AND_VIOLENCE_HIGH_PRECISION and GORE_AND_VIOLENCE_REPORTED_HEURISTICS labels.
    • If both labels are present, the adult blur wins. Even if the reaction post itself has a violence label, the original's adult label applies first.
  • If the original author has a protected account, the reaction post is dropped verified — PROTECTED_ORIGINAL_AUTHOR_DROP in the same file.
  • The three rules were added only to TimelineHomeHydration among the SafetyLevels (the rule bundles VF uses per surface) verified — rules/levels.rs.
    • The golden corpus (a test table pinning the expected verdict per rule) also pins that the same post is allowed in TimelineHome — rules/golden_corpus/reaction_video.rs.
  • If the original label or author lookup fails, the reaction post is shown as is verified — rules/rule_spec/laws.rs.

"the default shows the reaction post unblurred, as Tweetypie does on a failed lookup" — visibility-filtering/rules/rule_spec/laws.rs, 2026-10-22 (code comment)
