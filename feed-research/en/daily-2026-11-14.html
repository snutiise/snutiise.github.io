1Generative retrieval reached unpopular items — Alibaba

Source ReSID: Rethinking Long-Tail Retrieval in Generative Recommendation through Item Reachability — Alibaba International Digital Commerce Group, 2026-11-12 v1, paper.

Background Generative retrieval represents an item as a SID (semantic ID, an identifier that expresses an item as a short token sequence derived from its content), and the model picks candidates by generating the SID token by token. At serving time it generates with beam search (a search that keeps only a few high-scoring prefixes at each step), so prefixes of popular items survive while paths to long-tail items (unpopular items with few interactions) are cut early. The authors redefined this problem across the SID construction, decoding, and matching stages as "can the item be reached (reachability)". This paper presents ReSID, which fixes all three stages together, and reports an A/B result from an ads surface where it replaced existing TIGER-style generative retrieval.

What we learnedA. Replacing the existing generative retrieval with ReSID raised both ad revenue and unpopular-item impressions

  • In a 12-day A/B test, the ReSID arm recorded ad revenue +1.3%, CTR +1.1%, GMV +0.8%, and long-tail impression share +4.0% verified — paper HTML.
    • The experiment ran on a large-scale e-commerce ads platform from 2026-07-01 to 07-12, with 15% random traffic assigned to each bucket.
    • The control is a TIGER-style system (TIGER is an SID generative retrieval model proposed by Google). Other retrieval channels and downstream ranking were left unchanged, and only this channel was swapped.
    • Long-tail items were defined by the same cumulative click criterion as in the offline experiments.
  • The paper states that ReSID serves main traffic, and the authors released the code and checkpoints on GitHub verified — Gabriel-reina/ReSID.

"Online, ReSID is deployed in our production system to serve main user traffic, improving ad revenue (+1.3%), CTR (+1.1%), GMV (+0.8%), and long-tail exposure share (+4.0%)." — ReSID (paper), 2026-11-12

What we learnedB. The causes of missing unpopular items are how SIDs are built and exact-match matching

  • It reports that at equal code length, parallel SIDs are consistently better than sequential SIDs on unpopular items verified — paper HTML.
    • Sequential SIDs work like residual quantization, where each layer inherits the error of the preceding tokens. The paper analyzes that popularity bias accumulates layer by layer in this approach.
    • It writes that parallel SIDs split the embedding into independent subspaces and quantize each one, so an error in one slot does not spread to the others.
  • It reports that even when full SID generation misses, some of the generated tokens are often correct, so partial matching can recover relevant unpopular items verified — same paper.
    • However, it writes that this recovery is also impossible if beam search prunes every prefix that could still be completed within the allowed mismatch range.
  • ReSID uses two things together on top of long parallel SIDs verified — same paper.
    • It keeps promising paths with a beam search that removes popularity bias and reflects user semantics.
    • It recovers items by partial SID matching on the remaining tokens.

"Built on long parallel SIDs, ReSID pairs popularity-debiased and user-semantic-aware beam search to keep promising paths alive with partial SID matching to recover items from surviving tokens." — ReSID (paper), 2026-11-12

Why it matters Popular-path concentration in SID generative retrieval has become an operational problem that has now received a production A/B test for the third time, after Youku SPAR and Alibaba 1688 HERO. The three sources approach the same problem from different places by fixing decoding, the training signal, and the matching rule respectively. Because the surface is e-commerce ads, it is unknown whether this will move to feed surfaces, so it stays in the radar only.
