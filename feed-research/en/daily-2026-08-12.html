1An LLM writes executable ranking strategies instead of scores — Taobao

Source MetaStrategy: Generative Ranking with Executable LLM Strategies — arXiv 2608.09440, 2026-08-10, paper (Alibaba/Taobao, 15 authors)

Background The production statements this repository has tracked on how to put an LLM in the serving path fall into two families. In Netflix GenRec, the LLM itself becomes the scoring function and scores items (services/netflix.md GenRec section). In Yandex Music Gryphon-v2, the LLM generates Semantic-ID sequences and replaces retrieval and ranking in one step (radar.md new this month). In both families, the LLM is a function that runs in real time on the online serving path, which means the LLM must run on every request. This paper's MetaStrategy is a third approach: the LLM is not in the serving path, and it writes and deploys the ranking strategy itself.

What we learnedA. The LLM outputs an executable policy bundle, not a score

  • What the LLM outputs is an executable policy bundle, not a score verified.

    • The LLM takes the request context and emits a typed JSON bundle. The bundle contains objective weights, content/category preferences, experience constraints, and position policies.
    • Put plainly, the bundle says, "for this slot, set the objective function weights like this, the category preferences like this, and the position policy like this."
    • A deterministic validator and compiler instantiate this bundle as an isolated Generator. This Generator is compiled deterministically into the Generator role of the Generator-Evaluator (GE) architecture.
    • The GE architecture is a re-ranking structure in which a Generator builds a candidate list and an Evaluator scores the list. Here, the list-level Evaluator makes the new Generator compete atomically with the incumbent (the existing strategy).

    "a large language model (LLM) policy emits a typed JSON bundle controlling objective weights, content and category preferences, experience constraints, and position policies. A deterministic validator and compiler instantiate an isolated Generator that competes atomically with incumbents under the list-level Evaluator of the Generator-Evaluator (GE) architecture." — MetaStrategy abstract, 2026-08-10

What we learnedB. LLM inference runs nearline, and there is no observable increase in the response time of synchronous ranking

  • LLM inference runs nearline (precomputed close to real time, separately from request handling) verified. There is no observable increase in the response time (RT) of synchronous ranking verified.

    • It was deployed on the Taobao homepage "Guess You Like" surface using diff-triggered nearline generation.
    • LLM inference does not run synchronously with the request. The LLM runs outside the serving request, and only the compiled strategy is applied online.

    "We deploy MetaStrategy in Taobao Homepage Guess You Like through diff-triggered nearline generation; LLM inference remains outside synchronous ranking, with no observable increase in response time (RT)." — same abstract, 2026-08-10

What we learnedC. In a user-level A/B, clicks, item detail views, and transaction value all improved

  • In an A/B with users randomly assigned for 7 days, click PV, item-detail PV, and transaction value all improved verified. This is a statement obtained in the production environment.
    • MetaStrategy beat the incumbent in 27.93% of treatment-group GE calls.
    • Click PV improved by +2.11%, item-detail PV by +3.12%, and transaction value by +2.83%.

What we learnedD. The policy is trained in an environment that replays real requests, and compressed into a small student model

  • The policy is trained in a production-path replay environment verified. It is an environment that re-executes requests actually left in the logs through the current re-ranking stack without exposing them to users.

    • The reward is built by combining three kinds: selection, relative-rank, and baseline-lift.
    • It applies a self-competitive curriculum, which feeds frequent strategies back in as competitors, together with Evaluator-routed on-policy distillation, and compressed two 4B teachers into one 0.8B student.

    "self-competitive curriculum that feeds frequent strategies back as competitors, and Evaluator-routed reward-augmented on-policy distillation that transfers complementary 4B-parameter Teachers into a compact 0.8B-parameter Student." — same abstract, 2026-08-10

Canon update None. Added as a new entry under "new this month" in radar.md. Appended the line "a third angle, different from GenRec/Gryphon" to the LLM-native ranking open thread.

Why it matters MetaStrategy presents, with a production statement, a third way of using the LLM as an offline policy compiler. This repository's LLM-in-recsys topic has so far covered two ways of putting an LLM in the serving path (scoring function and generator).

  • The approach has two advantages. LLM latency is not exposed to users, so a large and slow model can be used. And because the output is typed JSON, it combines naturally with the deterministic guardrails of the existing ranking stack.
  • In exchange, it pays the cost that the LLM cannot react to per-request detail. The GenRec/Gryphon side is bound to be ahead in reading real-time intent within a session.
  • DREAM, published at Taobao within the same three days, addresses real-time intent, the problem that remains as that cost, in a different way. That is why the symmetry of the two approaches is interesting.

2Generate the SID first and attach explanatory copy only when needed — Kuaishou

Source PushDualGen: Enabling LLMs to Generate Semantic IDs with Interpretable Copy for Industrial Push Recommendation — arXiv 2608.07989, 2026-08-08, paper (Kuaishou, 12 authors)

Background Kuaishou is one of the few platforms publicly pushing LLM-native recommendation in production. The first generation, OneRec, performs end-to-end user personalization with SIDs, and the second generation, OneRec-Thinking, adds CoT before generating the SID to leave a reasoning trace. The problem with OneRec-Thinking is clear. CoT generates many tokens, so inference cost is high, and the burden grows on surfaces with heavy request volume such as large-scale push recommendation. This paper's PushDualGen is the third generation that fills that role.

What we learnedA. It generates the SID first, and generates the explanatory text at serving only when needed

  • PushDualGen is a duo generation structure that produces the SID first and the explanatory text afterward verified.

    • The explanatory text (copy) is an additional output that can be skipped at serving time, so it is generated at serving only when needed. That lets the whole model stay a lightweight generator.
    • Thanks to this structure, it can trace "why this item was recommended" without paying the cost on every request the way CoT does.

    "PushDualGen, a lightweight generator, which first generates the SID and then produces a copy as a skippable explanation." — PushDualGen abstract, 2026-08-08

What we learnedB. Deployed to Kuaishou push recommendation; in the online A/B, effective play rate rose and dissatisfaction rate fell

  • It stated that it was deployed to production on the Kuaishou push recommendation surface verified.

    • In the online A/B, the effective play rate rose by a relative +8.50%, and the dissatisfaction rate fell by a relative 37.70%.
    • In the long term, exposure of long-tail videos also improved.

    "The effective play rate for videos recommended to users has relatively increased by 8.50%, while the dissatisfaction rate has relatively fallen by 37.70%. In the long term, PushDualGen optimises the content ecosystem, providing more exposure for long-tail videos." — same abstract, 2026-08-08

What we learnedC. The previous day's HD-Rec reported only benchmark results, and PushDualGen was deployed to production

  • Following HD-Rec, which passed the previous day, Kuaishou's SID extension family passed the acceptance criteria two days in a row (the radar criteria: platform-company authors or production deployment/A/B claims, mechanism novelty, and large-scale results).
  • HD-Rec is a cross-domain SID study using a hierarchical codebook and a domain sparse MoE (mixture of experts, a structure that uses only some expert networks for each input), and it presents only benchmark results. PushDualGen, by contrast, was deployed to production.
  • The two papers are different directions of development that branched out of the same family.

Canon update None. Appended the line "2026-08-12 additional evidence" to the radar.md generative retrieval / semantic ID open thread.

Why it matters The signal strengthens that Kuaishou keeps releasing the SID family (OneRec → OneRec-Thinking → PushDualGen) generation by generation. If this line continues, the early judgment in the LLM-native thread that only Netflix GenRec was validated by a large-scale A/B will change before long.

  • We have not yet confirmed whether the HD-Rec authors (Ruiming Tang, Guorui Zhou, Han Li) overlap with the PushDualGen authors.
  • If they overlap, one team is pushing SID; if they do not, the company is pushing SID along two branches.

3Leave the pipeline as is, and an agentic layer on top tunes the parameters — Taobao

Source DREAM Technical Report — arXiv 2608.09408, 2026-08-10, paper (Alibaba/Taobao, 75 authors)

Background The existing industrial recommendation pipeline has a classic bottleneck. Retrieval → ranking → re-ranking are split into modules, so information and objectives are fragmented, rules are rigid, and the pipeline cannot react to real-time intent. This paper's DREAM solves the problem with a policy layer added on top of the pipeline without changing it. An intent engine made of three layers (L0/L1/L2) compresses on-device signals into structured intent and sends it to the cloud, and the MetaModel reasons over that intent in the M1-M2-M3 stages of summary, strategy planning, and parameter translation, then adjusts the pipeline parameters.

What we learnedA. It filters device signals by trigger conditions and greatly reduces what is sent to the cloud

  • The edge-cloud trigger chain compresses reporting volume to about 8.7% verified.
    • Instead of sending all on-device signals, it filters them by trigger conditions.
    • Greatly reducing the load on the cloud side was the precondition for deployability.

What we learnedB. IPV and GMV rose in the A/B without changing the pipeline models

  • In the A/B, controlling re-ranking alone improved the metrics, and extending control to fine ranking widened the improvement verified.

    • With re-ranking control alone, IPV improved by +2.06%, Core IPV by +2.39%, and GMV by +0.88%.
    • Extending control to fine ranking raised them to +2.71%, +3.06%, and +1.31% respectively, and PV also improved consistently by more than +1%.
    • These results were obtained without replacing the models and without compromising serving stability.

    "Large-scale A/B tests on Taobao's homepage feed show that re-ranking control alone improves IPV by 2.06%, Core IPV by 2.39%, and GMV by 0.88%. Extending control to fine ranking raises these gains to 2.71%, 3.06%, and 1.31%, respectively... These gains require neither replacement of pipeline models nor compromise of serving stability, supporting agentic meta-control as a viable paradigm for industrial recommendation." — DREAM abstract, 2026-08-10

What we learnedC. A dual loop of offline simulation and online feedback optimizes the two modules together

  • A dual loop called Reward Dual Loop optimizes the intent engine and the MetaModel at the same time verified.
    • One loop is an offline simulation that explores the strategy space, and the other is online feedback that calibrates the results.

Canon update None. Added as a new entry under "new this month" in radar.md.

Why it matters DREAM and MetaStrategy are two approaches from the same company (Taobao), aimed at roughly the same surface (the homepage feed), so the symmetry is clear. MetaStrategy is a policy compiler, and DREAM is a real-time adjuster.

  • MetaStrategy has the LLM compile policy JSON nearline and inject it into the ranking stack. DREAM has an agentic MetaModel receive on-device intent and adjust pipeline parameters.
  • Judging from the substantially overlapping author lists, the same organization is likely experimenting along two branches. For example, Chengyu Lai, Jiuning Lin, Bin Zhang, and Han Zhu are among those named on both papers.
  • It is worth watching whether the two approaches converge into one or are each deployed in parallel.

Radar

Of the 30 new papers skimmed today, 4 passed the acceptance criteria (3 from Alibaba, 1 from Kuaishou). The scope is new arXiv cs.IR submissions, filtered through a triage stage that looks only at titles and abstracts. Three papers from the same company (Alibaba) within three days is an unusual cluster, so it is recorded separately. In effect, large Chinese platforms disclosed, as one bundle, how they serve the LLM/SID family from different angles.

  • Added MetaStrategy (section 1 above) as a new entry in radar.md new this month and added one line to the LLM-native thread.
  • For PushDualGen (section 2 above), added one line, "2026-08-12 additional evidence", to the SID thread.

  • IntHQ (arXiv 2608.09634, 2026-08-10) gets no radar entry and is only recorded in the daily.
    • It is a paper from Amap (Alibaba Maps, travel recommendation).
    • It presents a three-pronged method for fusing multi-task into generative recommendation: Dual-Stream Decoupling, Task-Interactive Modeling, and Hierarchical Querying.
    • It reports that UVCTR improved by +1.60% in the production A/B.
    • However, its mechanism novelty is relatively low; it is closer to tidying up an existing combination of generative and multi-task. That is why no radar entry was created.

  • The remaining 26 were dropped from the acceptance criteria as purely academic increments (RAG optimization, academic retrieval, medical/legal/edu domains, POI, RISC-V ANNS, etc.).
