1A mode that combines scores by multiplication was added, off by default — X

Source xai-org/x-algorithm@a284320 — xAI, 2026-11-17, code. In the numbering these notes use, it is Gen4+65 (Gen4+N is the number these notes assigned, in order, to commits after the Gen4 release on 2026-08-13).

Background X's For You ranking model Phoenix (a Grok-family Transformer) outputs the probability of actions such as like, reply, and report for each candidate post. Until now, the final score was a weighted sum of these probabilities multiplied by per-action weights. In a weighted sum, a "post nobody reacts to but people watch for a long time" and a "post that is skipped immediately but has many likes" can offset each other on the same axis. This commit added, off by default, a combination mode that multiplies skip, engagement, and dwell time together.

What we learnedA. The multiplicative score is the product of a skip term, an engagement term, and a dwell-time multiplier

  • The new mode computes the score as "degree of not being skipped × engagement value × dwell-time multiplier" verified — xai-value-model/scoring.rs:75-110.

    • The engagement term is the weighted sum of all heads except the dwell and not_dwelled heads, plus the constant engage_bias.
    • The skip term is (P(not_dwelled) + offset)^exponent. The offset does not go below 0.01.
    • The dwell-time multiplier is 1 + max(cont_dwell_time weight × expected dwell seconds, 0).

  • A candidate whose engagement term is negative is not multiplied but sent to the existing negative-offset path verified — same file.

    • This keeps posts with a high report or block probability from being inflated by the dwell multiplier.
    • The negative sum used for normalization counts only four heads: not_interested, block_author, mute_author, and report. not_dwelled is left out.

  • A test in the same commit pins the expected behavior with numbers verified — scoring.rs:603.

    • Because the exponent is negative, the larger P(not_dwelled) is, the smaller the skip term becomes.

What we learnedB. The switch is off, so current scores are unchanged

  • The default of the mode switch is the existing weighted sum, and the exponent and bias defaults are also 0.0 verified — home-mixer/params/param.rs:577-600.
    • The parameters are rust_home_mixer_value_model_mode (default "weighted"), ..._not_dwelled_power_exponent, ..._not_dwelled_power_offset, and ..._multiplicative_vm_engage_bias.
    • This file is a cron mirror that syncs production defaults daily and publishes them. The last sync in the header is 2026-11-16T16:00:37Z.
  • home-mixer (the service that receives For You requests), VMRanker (the slate reordering service), and the page decoder (an RL re-ranking model that picks a page's posts in slot order) read the same switch verified — scorers/page_decode_rerank_scorer.rs.
    • When the multiplicative mode is on, cached weighted-sum scores are not used and scores are recomputed each time, and cached scores are also left out of VMRanker requests.

What we learnedC. The DPP history transmission switch turned on two days ago is off again

  • The switch that makes home-mixer send posts it served within the previous 10 minutes to VMRanker went back from true to false verified — params/param.rs:657-662.
    • The switch was turned on in the 2026-11-14 commit (30647a8, Gen4+64). VMRanker reads this history only in the window mode, which is off by default, so the order did not change while the switch was on.
  • The same commit added to the window-mode penalty a term that adds a fixed amount for each history post with the same first SID level, and its default is 0.0 verified — vm-ranker/dpp.rs.
    • SID (semantic ID) is an ID that represents a post as a code sequence from coarse to fine levels. The first level is the coarsest topic group.
    • The penalty is min(cos² + (sid_lambda if same L1), 1), and the parameter is rust_home_mixer_vm_ranker_dpp_window_sid_lambda.
    • A client and cache were newly added for VMRanker to look up the SID of history posts.

What we learnedD. Ad volume control by user activity level and an ads-only timeline were added, off by default

  • The For You slot-spread ad blender (an approach that first places ad slots evenly across the page) can now drop some ad slots by user activity level verified — home-mixer/ads/user_load.rs.
    • The eight levels are new, near_zero, very_light, light, medium_tweeter, medium_non_tweeter, heavy_non_tweeter, and heavy_tweeter.
    • Each level sets the share of slots to keep (fixed at 50–100%) and the ad gap (minimum 3). Which slots to drop is decided by a hash made from the request id.
    • It does not apply to Premium and Premium+ subscribers or to requests outside For You.
  • The per-level value lists are empty by default, so current ad volume is unchanged verified — params/param.rs:1099-1110.
  • A switch that sends a timeline containing only ads to specified viewer ids was added, off by default verified — models/query.rs:295-301.
    • When on, both For You and Following turn off organic post sources and serve only ads in order.
    • Because it turns on only through an id list, we infer it is a mechanism for ad-review accounts inferred.

  • Added a config to the page RL re-ranker that trains only the critic (the RL component that estimates a page's long-term value) verified — phoenix/xrex/models/page_critic_only.py
  • Added an option to immersive two-tower (a retrieval model that embeds users and posts separately) training that removes cases where the user only clicked and stayed over 10 seconds from the long dwell label, and turned it on in that preset verified — phoenix/xrex/data/recsys/recsys_batch.py
  • Re-review by PtOS (the policy-violation verdict of the Grok-based safety pipeline) for media-heavy posts runs only when the post has 256 or more likes or an earlier verdict included an adult content violation. It is skipped if the post is already NSFW verified — grox/flows/ptos/task_safety_ptos_many_media.py:52-68
  • Home frames (such as the Grok recommended-task card) respect the user's dismissal record even when the impression fatigue time is 0 verified — home-mixer/frames/catalog.rs
  • Added a video completion weight slot to the page decoder ranking weights, with a value of 0.0 verified — scorers/page_decode_rerank_scorer.rs

2The interest layer behind Instagram Your Algorithm was published as a paper — Instagram

Source CLEAR: Legible and Steerable Recommendation via Grounded Natural-Language Interests — Meta, submitted to arXiv 2026-11-14 (date in the text 2026-10-24), paper. All authors are affiliated with Meta.

Background Instagram Your Algorithm is a screen that shows a summary of interests that affect recommendations and lets users write what they want to see more or less of. This repository had left open how that screen connects to ranking and how fast changes take effect. Typically, a recommender's preferences live in embeddings that people cannot read, so edits users make are easily overwritten silently in the next training. This paper published a system that stores interests as human-readable natural-language labels and uses those labels as the unit of retrieval and ranking.

What we learnedA. The Your Algorithm screen is the window for viewing and editing Meta's interest layer

  • The paper states that Instagram's Your Algorithm and Tune Your Explore screens let users view and edit this interest layer verified — CLEAR §3.1.
    • The system spans four surfaces across the two apps, Instagram and Facebook. We could not confirm the list of the four surfaces.
    • The paper states that the components had run in production for over 1 year.
  • Interests that users add or hide are stored separately from model output and take precedence over model inference until the user changes them again verified — same paper §3.1, §3.2.
    • Hidden interests are read by the removal path at serving time (§5.2).

"Instagram's Your Algorithm and Tune Your Explore interfaces expose the interest layer for inspection and editing." "Explicit state is stored separately from model output and takes precedence until the user changes it." — CLEAR, 2026-11-14 (paper) §3.1

What we learnedB. One interest label is used together as the unit of retrieval, ranking, and impression cap

  • Each interest carries a label, evidence events, an embedding projection, and a fixed id, each serving a different path verified — same paper §4.2, §5.
    • The label becomes a lexical search query rewritten as a user profile.
    • Evidence events (the user's own actions that led to inferring this interest) become the seed of co-engagement-based retrieval.
    • The embedding projection queries an ANN (approximate nearest neighbor search) index.
    • The fixed id is the key for cached candidates, contribution tracking, and impression aggregation.
  • Candidates must pass a strict topic-match check, and ranking gives a temporary bonus term to declared interests and can reserve top slots verified — same paper §5.
  • Realized impressions per interest are counted with a decaying counter (Fireball) so that no single interest floods the feed verified — same paper §5.
  • A newly added interest skips the evidence requirement for inferred interests even without behavioral evidence, and gets its first candidates through the lexical and embedding paths verified — same paper §4.1, §4.2.

What we learnedC. A randomized experiment and production averages show the responsiveness effect

  • In an experiment that randomly split supplementary supply, interest responsiveness by the 3-second engagement criterion rose +8.34% [+8.07%, +8.61%] verified — same paper Table 1.
    • For user-days when an explicit interest was actually delivered, it was +2.43% [+2.24%, +2.63%].
    • Exposure control cut the days when one interest flooded the feed by 15.4% [13.4%, 17.4%].
  • For the one-week Instagram production average, the paper reported same-day responsiveness of 79.6%, declared-interest load of 82.6%, and topic match of 87.2% verified — same paper Table 1.
    • Topic match is the value from the most recent twice-weekly LLM judge run. We could not confirm the exact definitions of the three metrics.
  • In the experiment removing components one at a time, the losses were 8.7 pp for the interest ranking term, 11.1 pp for top-slot reservation, and 13.7 pp for interest-conditioned candidate sourcing verified — same paper abstract.
    • The paper states that these figures are conditional on the tested removal sequence.

"8.7 percentage points for added-interest ranking terms, 11.1 for reserved top-slot insertion, and 13.7 for interest-conditioned candidate sourcing, conditional on the tested removal sequence." — CLEAR, 2026-11-14 (paper) abstract
