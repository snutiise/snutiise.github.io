1teacher 점수 저장이 서빙 점수로 바뀌어 켜졌다 — X

자료 xai-org/x-algorithm@b551517 — xAI, 2026-11-19, 코드. 이 노트들이 붙인 번호로는 4세대+67이다(4세대+N은 2026-08-13 4세대 공개 뒤의 커밋에 이 노트들이 차례로 붙인 번호다).

배경 X For You는 Phoenix(Grok 기반 트랜스포머 랭커)가 후보 포스트마다 좋아요, 답글, 신고 같은 행동별 확률을 내고, 이 값을 가중합해 순서를 정한다. 하루 전 커밋은 home-mixer(For You 요청을 조립하는 서비스)에 teacher 재채점 경로를 기본 off로 넣었다. teacher는 증류(큰 모델의 예측을 다른 모델의 학습 목표로 쓰는 방법)에서 정답을 주는 쪽 모델을 가리킨다. 이번 커밋은 그 경로를 별도 모델 호출 없이 서빙 점수를 저장하는 방식으로 고치고 기본 on으로 바꿨다.

새로 알게 된 것A. 프로덕션 랭커가 낸 확률이 그대로 teacher 라벨이 된다

  • teacher 라벨은 이제 별도 클러스터에 다시 묻지 않고, 서빙 때 Phoenix가 이미 낸 확률을 옮겨 적은 값이다 확인 — teacher_score_side_effect.rs:48-79

    • 새 함수 served_prob가 행동 이름마다 후보의 phoenix_scores 필드(예: favorite_score, reply_score, report_score)를 골라 돌려준다.
    • 테스트 이름이 served_probs_are_the_scores_the_ranker_returned이다.
    • teacher 클러스터 이름, 표본 비율, 상위 64개, 타임아웃 2초 파라미터는 지워졌다.

  • 저장 대상은 실제로 나간 포스트뿐이고, 같은 원본 포스트는 한 번만 남는다 확인 — 같은 파일 teacher_entry

    • 전날 판은 탈락 후보 가운데 가중합 상위까지 합쳐 최대 64개를 다시 채점했다.
    • 전날 판은 후보별 입력도 함께 캐시에 썼지만, 이번 판은 헤드별 확률 묶음 하나만 쓴다.

  • 이 경로는 기본 on이고, 저장할 헤드 21개가 기본값으로 채워졌다 확인 — params/param.rs:1269-1286

    • TTL은 3000초(50분)로 전과 같다.

  • 표본 추출 없이, 해석된 Phoenix 클러스터가 프로덕션 클러스터인 요청마다 돈다 확인 — teacher_score_side_effect.rs:132-141

    • 조건은 is_prod(), 캐시 재사용이 아닌 요청, 학습 요청 캐시 스위치 on(기본 on), is_prod_cluster(resolve_cluster)다.
    • 프로덕션 클러스터는 Experiment1Fou와 Experiment2Fou이고, 판정 함수가 phoenix_scorer.rs로 옮겨 공유됐다.

새로 알게 된 것B. 참여 유도 라벨을 VMRanker에 보낼 자리가 생겼다

  • home-mixer가 답글·공유·클릭을 유도한다는 안전 라벨을 조회해, 해당 후보에 표시를 달아 VMRanker(DPP 슬레이트 재정렬과 가중합을 맡는 랭커 서비스)에 보내는 경로가 기본 off로 생겼다 확인 — vm_ranker_engagement_labels.rs
    • 라벨은 PROMOTES_REPLIES, PROMOTES_SHARES, PROMOTES_CLICKS 세 가지이고, 각각 reply_ineligible, share_ineligible, click_ineligible로 실험 페이로드에 실린다.
    • 스위치는 VMRankerSendEngagementIneligible(기본 false)이고, 가중합 상위 200개 후보만 조회한다(param.rs:663-674).
    • 조회 타임아웃은 80ms이고, 실패하면 아무 표시도 달지 않는다.
  • 이 표시를 받은 VMRanker가 무엇을 하는지는 공개되지 않았다 확인 — 같은 커밋에 vm-ranker 디렉터리 변경이 없다.
    • 필드 이름이 ineligible이라 해당 행동 헤드의 확률을 가중합에서 빼는 용도로 본다 추정. 근거는 필드 이름과 라벨 이름뿐이다.

새로 알게 된 것그 밖의 변경

  • 광고 슬롯을 덜어 낼 때 남은 슬롯을 페이지에 다시 고르게 펴는 방식이 기본 off로 생겼다 확인 — ads/slot_spread_blender.rs
    • 스위치는 AdsUserLoadEvenSpread(기본 false)이고, 남길 개수는 기대값의 소수점 부분을 요청 id 해시로 올림해 정한다.
  • 알림 지면의 멘션 알림에서, 뷰어가 알림용으로 뮤트한 키워드가 든 포스트를 떨어뜨리는 규칙이 생겼다 확인 — visibility-filtering/rules/tweet_rules.rs
    • "팔로우하는 계정 제외" 옵션이 걸린 키워드는 작성자를 팔로우하지 않을 때만 적용한다.
  • Phoenix 학습 데이터에 유저의 장기 작성자 프로필 피처(작성자별 참여 횟수, 강한 참여 횟수, 마지막 참여 경과 시간, 평균 체류 시간)를 읽는 로더가 생겼다 확인 — long_term_author_profile.py
  • 광고 proto에 광고주 첫 집행 시각 필드가 추가됐고, abuse-enforcement-service의 행동 제어 코드가 정리됐다 확인 — 커밋 diff

정본 반영 services/x.md ## 한 줄 요약의 기준 커밋을 b551517로 올렸다. ### 학습·서빙 인프라 도입 문장과 teacher 단락을 "서빙 점수 저장, 기본 on"으로 다시 쓰고 이전 형태를 그 절의 변경 이력 불릿으로 옮겼다. ## 용어 표의 teacher 재채점 정의를 고쳤다. Phoenix 절 debias 불릿 아래에 참여 유도 라벨 전송 불릿을, ## 광고에 균등 재배치 불릿을 추가했다. ## 출처 기준 sha 표와 변경 이력 요약표에 한 행씩 추가했다.

의미 ⚠ 주장 변경: teacher 경로는 "기본 off, 별도 큰 모델로 재채점"에서 "기본 on, 프로덕션 랭커 점수 저장"으로 바뀌었다. 그래서 teacher는 더 큰 모델이 아니라 지금 서빙하는 Phoenix 자신이다. 이 라벨로 학습하는 student가 retrieval이나 경량 랭커일 것으로 보지만, 소비하는 쪽 코드가 없으므로 추정으로 둔다.

검증에서 뒤집힌 것

  • 어제 x.md는 teacher 경로를 "큰 모델의 예측을 작은 서빙 모델의 학습 목표로 쓰는 증류용 데이터"로 추정했다. 하루 만에 teacher가 프로덕션 서빙 모델 자신으로 바뀌어, 추정을 "프로덕션 랭커의 예측을 다른 모델의 학습 목표로 쓰는 데이터"로 고쳤다. topics/와 radar.md에는 X teacher를 다룬 문장이 없었다.
