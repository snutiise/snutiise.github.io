LLM-native 랭킹의 확산 — GenRec 이후 누가 따라오나

  • 무엇: 추천 파이프라인의 어느 한 자리를 LLM으로 바꾸는 흐름이다. 2026-08 현재 프로덕션 배포까지 간 1차 진술은 다섯 건이고, 메커니즘이 서로 다르다 확인. → llm-in-recsys.md
    • 세부: 다섯 건과 각각의 메커니즘은 다음과 같다 확인.
      • Netflix GenRec: 채점 함수
      • Yandex Gryphon-v2/Sona: 생성 retrieval과 rank의 통합
      • Alibaba MetaStrategy: 오프라인 정책 컴파일러
      • Meta ConnectionMind: 그래프 경로 추론기
      • Meta AMBER: 입력 토큰화
    • 세부: 이 가운데 AMBER만 온라인 A/B 수치를 공개하지 않았고, 나머지 네 건은 A/B 수치를 밝혔다.
    • 세부: 스레드를 열 때에는 서빙 경로의 채점 함수만 보았다. 그 뒤에 들어온 진술들이 서로 다른 자리를 건드리면서 범위가 넓어졌다. 새 진술이 들어오면 이 목록에 더하고, 본문에서는 순서를 세지 않는다.
  • 왜 주목: X(LLM을 주석에 쓴다)와 Meta(LLM을 피처 인코더로 쓴다)가 같은 길을 갈지가 향후 1년의 최대 분기점이었다. 그런데 Meta가 2026-08에 ConnectionMind로 진입했다(⚠ 기존 명제가 절반 뒤집혔다).
  • 지켜볼 것: 타사(Google/YouTube, TikTok)가 서빙 경로에 LLM을 배포했다는 1차 진술, GenRec 전면 롤아웃의 후속 소식, ConnectionMind의 지면 확정과 서빙 비용을 다룬 후속 글을 기다린다.
  • 2026-08-12 추가 근거: Taobao MetaStrategy(arXiv 2608.09440, 2026-08-10)는 LLM을 서빙 경로에 두지 않고 오프라인 정책 컴파일러로 쓰는 세 번째 각도다. "Guess You Like" 지면의 7일 A/B에서 click PV +2.11%, IPV +3.12%, GMV +2.83%를 얻었다 확인.
    • 세부: LLM이 typed JSON(목적 가중치, 카테고리 선호, 위치 정책, 가드레일)을 nearline으로 생성한다. validator와 compiler가 이것으로 결정론적 Generator를 인스턴스화하고, 이 Generator는 GE(Generator-Evaluator) 아키텍처 안에서 기존 전략과 원자적으로 경쟁한다.
    • 세부: LLM inference가 sync 랭킹 밖에 있어서 RT 영향이 0, 다시 말해 동기 경로의 지연 증가가 없다.
    • 세부: GenRec(채점 함수)이나 Gryphon-v2(생성 retrieval과 rank)와 달리, LLM을 동기 랭킹 경로 밖에 두는 메커니즘이다.
  • 2026-08-13 추가 근거 (레이더가 아니라 정본 반영): Meta ConnectionMind(arXiv 2608.10187, 2026-08-10)에서는 Llama 3.1-8B가 그래프 위 경로 추론기로 쓰인다. Netflix GenRec은 "채점 함수"이고 ConnectionMind는 "그래프 경로 추론기"이므로, 자리 3(LLM을 랭커로 쓰는 자리)의 실체가 회사마다 다르다는 새 관전 포인트가 생겼다. → services/facebook.md, topics/llm-in-recsys.md
    • 세부: 이 LLM은 헤비 유저 5–10%의 온라인 hot path에 서빙되고, 나머지 90–95%는 그 LLM이 offline으로 발견한 meta-path로 학습된 Student GNN이 맡는다.
    • 세부: 논문은 지면을 공개하지 않고 "short-form video platform"이라고 썼지만, 그래프 스키마로 보아 Facebook일 가능성이 높다. watch time은 +0.43% 올랐다.
  • 2026-08-28 추가 근거: Meta AMBER(arXiv 2608.25546, 2026-08-26)는 상호작용 이벤트 하나를 Event Token 하나로 압축해 LLM 입력에 넣는, 입력 토큰화(input tokenization) 쪽 메커니즘이다. Facebook surface에서 하루 수십억 건의 이벤트를 online encoding으로 서빙한다 확인.
    • 세부: "AI at Meta" 소속 저자 15인이 썼다. Event Tokenization이라는 각도로, 각 이벤트에서 유저·아이템·컨텍스트·outcome 신호의 temporal snapshot 전체를 compact Event Token 하나로 압축하고, 이를 LLM 입력의 새 토큰 유형으로 도입한다.
    • 세부: 산업 규모의 랭킹·retrieval 벤치마크에서 compute-quality Pareto 전선을 개선했고, non-LLM 랭커에도 feature로 이식할 수 있다(통계적으로 유의하다). Online A/B 수치는 abstract에 공개하지 않았다.
    • 세부: GenRec(scoring), ConnectionMind(graph reasoning), MetaStrategy(offline policy compiler) 어느 것과도 다른 자리를 건드린다. 즉 Meta 안에서도 LLM 기반 recsys 접근이 최소 두 축(그래프 추론기와 입력 인코더)으로 갈라졌다.
  • 2026-09-07 추가 근거: Spotify GLIDE와 LinkedIn Follows는 모두 fine-tuned LLM 임베딩을 후보 생성기 채널로 두는 자리에 해당한다. 두 자료로 스레드가 여섯 회사, 진술 일곱 건으로 늘어난다(Netflix·Yandex·Alibaba·Meta 2건·Spotify·LinkedIn). 자세한 분석: daily/2026-09-07.md
    • 세부: Spotify GLIDE(From Models to Products: LLMs for Recommendation at Spotify Scale, 2026-08-03 블로그)는 1B LLM과 Semantic ID 기반의 후보 생성기다. Semantic ID(SID)는 아이템을 의미 토큰 열로 나타낸 식별자를 말한다. GLIDE는 Spotify Home 팟캐스트 발견 지면에 배포됐고, 후단 랭킹 파이프라인에 후보를 공급한다.
    • 세부: GLIDE는 21일 A/B에서 ~20M impression 규모로 non-habitual podcast listening +5.4%, new-show discovery +14.3%를 얻었고, 지연·engagement 요구사항은 유지했다 확인.
    • 세부: LinkedIn Follows의 출처는 Rebuilding LinkedIn's Follows Recommendations with LLM-Based Semantic Retrieval and Ranking(2026-08-24 블로그)이다. fine-tuned bi-encoder LLM으로 프로필을 자연어 문장으로 재구성(narrative prompting)한 뒤 임베딩한다. 크리에이터 임베딩은 야간 FAISS batch로 만들고, 뷰어 임베딩은 온보딩 시 Proxima로 실시간 추론한다.
    • 세부: Follows는 MyNetwork tab과 Home Feed 두 지면에 배포됐고, 프로덕션 A/B에서 follow rate가 통계적으로 유의하게 올랐으며 new member 세그먼트의 lift가 가장 컸다 확인. 구체적인 uplift 백분율은 공개하지 않았다.
    • 세부: 두 자료는 Pinterest CLR(Home Feed 후보 생성기의 user tower를 retrieval 컨텍스트로 조건화하는 방식)과 상보적이다. Pinterest는 조건화로, LinkedIn은 프로필의 자연어화로, Spotify는 SID 생성으로 접근한다.
  • 2026-10-12 추가 근거: Pinterest User Journeys(From Activity to Intent, 2026-10-09 블로그)에서는 LLM이 유저 단위 자연어 질의를 생성하며, 동기 경로 밖이라는 점에서 MetaStrategy와 같은 쪽이다. 클러스터링 대비 A/B에서 email CTR이 +1.1%, push open이 +1.3% 올랐다 확인. 자세한 분석: daily/2026-10-12.md
    • 세부: frontier teacher에서 distillation한 Qwen3-4B가 360일 활동 로그를 읽고 journey 이름 목록을 배치로 생성한다. 각 이름은 알림 지면의 embedding-based retrieval 질의가 된다.
  • 2026-10-19 추가 근거: Spotify·NVIDIA TensorRT LLM 협업(Advancing Generative Recommendation Inference, 2026-10-16 블로그)은 2026-01부터 프로덕션에 있는 팟캐스트 LLM 추천의 서빙 비용을 다룬다. Qwen3 1.7B 기준으로 beam search 비용이 최대 54%, 채점 비용이 최대 7% 줄었다고 쓴다 확인(비교 기준은 본문에서 명확하지 않다). 자세한 분석: daily/2026-10-19.md
    • 세부: beam search로 상위 Semantic ID 시퀀스를 뽑아 카탈로그 아이템으로 바꾸는 생성 워크로드와, 후보 마스킹으로 한 요청에서 여러 후보를 채점하는 워크로드를 나눈다 확인.
    • 세부: 기존 유저 임베딩을 단일 soft token으로 투영해 개인화한다 확인.
    • 세부: 서빙 경로의 LLM을 "되는가"가 아니라 "얼마에 되는가"로 다룬 진술이다.

추천 모델 스케일링 법칙 — 회사별 독립 확인이 쌓이는 중

  • 무엇: 추천 모델도 "데이터·파라미터를 늘리면 LLM처럼 예측 가능하게 좋아진다"는 주장을 교차 검증한다. 지금까지의 근거는 아래 세 갈래다. → sequence-transformer-ranking.md
    • Meta HSTU(유기 피드 쪽 계보의 시퀀스 모델)·Wukong 확인
    • Netflix FM(회원 표현을 중앙에서 만드는 Foundation Model)의 "일관된 개선"과 2M→1B shadow 연구 확인
    • Meta ads LLaTTE("semantic feature가 전제조건") 확인
  • 왜 주목: 스케일링이 성립하면 추천도 "더 큰 모델 + 더 긴 시퀀스" 군비 경쟁이 된다. 다만 semantic feature가 전제조건인지를 두고 LLaTTE와 HSTU의 주장이 정반대이고, 이 쟁점은 아직 해소되지 않았다.
  • 지켜볼 것: 반박 사례와 파라미터 수를 공개하는 사례를 기다린다.
    • 세부: Meta·Netflix 밖의 진술을 arXiv 제출일 순으로 놓으면 ByteDance TM20K(2026-08-07), Ant Densing Law(2026-08-24), Alibaba TransRetrieval(2026-08-26)이다.
    • 세부: 그 뒤로 ByteDance ReST(2026-09-01)와 HELIX(2026-09-29, [추정] TikTok)가 붙었다.
  • 2026-08-28 추가 근거: Alibaba/Alimama TransRetrieval(arXiv 2608.25528, 2026-08-26)은 Meta HSTU·Wukong·LLaTTE에 이어 스케일링 법칙을 진술한 회사이자 첫 retrieval 쪽 진술이다. Alibaba 디스플레이 광고 플랫폼에서 한 달 동안 프로덕션 A/B를 돌려 revenue +2.53% (95% CI [2.22, 2.70], p<0.0001), RPM +1.28%를 얻었다 확인.
    • 세부: Taobao & Tmall Group 6인과 RUC 4인이 함께 썼다. field heterogeneity 때문에 생기는 token-norm divergence를 weighted average aggregation으로 억제해서, Transformer가 scaling되도록 만든 광고 retrieval 프레임워크다.
    • 세부: target token compression으로 후보당 compute를 85% 줄였고, position-style domain embedding으로 여러 도메인을 통합했다.
    • 세부: 같은 A/B에서 지연은 동일하게(P99 ~40ms) 유지했고, 도메인 4개로 나눠 보면 A +1.72% / B +2.51% / C +5.39% / D +0.87%였다 확인.
    • 세부: LLaTTE는 "semantic feature가 필요하다"고 보고 HSTU는 "scaling만으로 된다"고 본다. 여기에 "field heterogeneity를 명시적으로 다루면 scaling이 가능하다"는 세 번째 답이 더해졌다.
  • 2026-09-09 추가 근거(뒤늦은 발견): Shopify Foundational Generative Recommender(Shopify Engineering, 2026-02-25)는 HSTU를 바탕으로 e-commerce에 맞게 고친 자기회귀 시퀀스 트랜스포머를 상품 추천에 프로덕션 배포했다. HSTU 라이선스가 다른 회사도 프로덕션에 채택할 수 있을 만큼 접근 가능하다는 것을 확인한 e-commerce 도메인의 첫 진술이다. 자세한 분석: daily/2026-09-09.md
    • 세부: 배포 지면은 Shop app과 머천트 스토어프론트의 상품 추천이다.
    • 세부: 다만 Baseline 모델의 정체와 파라미터 규모를 공개하지 않아, 이 스레드에 붙는 세기는 약하다.
    • 세부: Buyer 이벤트 시퀀스(검색·조회·장바구니·구매)를 원시 그대로 입력으로 쓴다. RoPE 기반 rotary encoding과 relative attention bias, batch 공유 negative, positive-aware hard negative, boosting 기반 recall 최적화를 조합했다.
    • 세부: 프로덕션 A/B에서 Shop orders +0.94% relative, high-quality CTR +5% relative, conversion rate +0.71% relative, final product recall@4 +4.8% relative를 얻었다 확인.
    • 세부: CUDA 커널 최적화로 훈련 파이프라인을 7.3x 빠르게 했다.

GEAR (Douyin / ByteDance) — generative end-to-end ad retrieval이 Douyin Ads 수억 DAU 프로덕션에 배포, representation collapse(BasisVQ orthogonal basis)와 item collision(context-conditioned reranking head) 두 병목 동시 해결

    • 세부: 생성형 retrieval은 아이템을 ID 임베딩이 아니라 의미 토큰(Semantic ID) 시퀀스로 표현하고, autoregressive 생성으로 검색을 대체한다. 산업 규모에서는 알려진 병목이 두 가지 있다.
      • 표현 붕괴: tokenizer가 분포 변화 아래 degenerate하게 수렴해 end-to-end 적응이 불안정해지는 문제다.
      • 아이템 충돌: 거대한 후보 풀에서 서로 다른 아이템이 같은 토큰 시퀀스를 공유해 retrieval 정밀도가 떨어지는 문제다.

      • prefix-aware BasisRQ로 확장해, 같은 asymptotic time complexity 안에서 codebook 표현력을 키운다.

GRP v0.1 (Snap) — retrieval · ranking · reward를 단일 encoder-decoder로 통합하는 generative recommendation 프레임워크, 프로덕션 A/B view time +0.82% · shares +2.56% · serving latency −69%

  • 무엇: GRP(Generative Recommendation Platform으로 추정)는 generative recommendation 프레임워크다. 산업 추천의 retrieval → pre-rank → fine-rank → reward 다단 cascade를 단일 encoder-decoder 모델로 통합한다. 같은 모델이 후보를 만들고, 채점하며, RL 학습의 보상 신호를 제공한다.
    • 세부: 프레임워크의 기둥은 둘이다.
      • multimodal Semantic ID 생성: 후보 아이템을 discrete SID token sequence로 나타내고, autoregressive decoder가 이를 생성한다.
      • joint Multi-Head Prediction(MHP): 후보 스코어링을 맡으면서 RL post-training의 frozen reward를 겸한다. 이 RL post-training은 mGRPO(reference-anchored margin GRPO)다.

PEAR (익명 e-commerce, [추정] Alibaba 라인) — 산업 검색용 progressive-verifier autoresearch, 4-계층 verifier ladder + hypothesis-guided per-task state, A/B 두 건에서 Main Order/DAU +2.7336% · +3.2957%

  • 무엇: PEAR는 산업 검색 시스템에서 후보 정책(candidate modification)을 자동 탐색하고 A/B로 검증하는 리서치 오케스트레이션 프레임워크다. 이름은 Progressive Evidence-Based AutoResearch의 약자다.
    • 세부: 논문은 기존 방식의 두 문제를 두 축으로 해결한다고 주장한다.
      • keep-if-better 규칙이 non-stationary traffic 아래에서 transient 이득을 persistent 이득으로 오인하는 문제
      • 개별 신호에 의존하는 평가 방식이 evidence를 통합해 탐색을 유도하지 못하는 문제
    • 세부: 첫째 축은 Evidence-driven AutoResearch다. 전략 태스크마다 predefined objective와 intervention scope 안에서 독립적인 hypothesis-guided research state를 가진다. 이 상태는 Plan → Execute → Evaluate → Update 루프로 진화하며, 실험 결과를 context-aware하게 해석해 hypothesis를 갱신한다.
    • 세부: 둘째 축은 Confidence-Gated Verifier Ladder다. 평가를 신뢰 순으로 4-계층으로 나누고, unified confidence-based gate가 통계적으로 유의한 양성이 확보될 때만 다음 계층으로 promote한다. 계층은 Offline Replay → Shadow-Traffic Evaluation → Rapid Online Evaluation → Decision-Grade Online Evaluation 순이다.
  • 왜 주목: 실제 산업 검색 시스템의 A/B 두 건에서 Main Order/DAU가 +2.7336%, +3.2957%로 기록됐다 확인.
    • 세부: 두 자릿수 자릿까지 준 정밀도와 "Main Order/DAU"라는 지표(주문 수 / DAU)는 e-commerce 지면의 표준 KPI다.
    • 세부: 2026-09에 리서치 자동화 각도가 명시적으로 이름 붙어 나온 세 번째 자료다. 세 자료는 자리가 서로 다르다.
      • Meta VDD EvoPilot: 검색 retrieval 각도
      • Kuaishou 추정 AgentX-Model: recommender 리서치 루프 전체 각도
      • PEAR: 산업 검색 자동화의 verifier 계층 각도
    • 세부: AgentX-Model이 리서치 오케스트레이션을 dual-agent(Research와 Model)로 분해했다면, PEAR는 평가 신뢰도를 계층으로 분해했다. 두 축은 상호 배타적이지 않으므로, 이 각도의 프로덕션 진술이 어디까지 확장되는지를 관찰한다.

KuaFu (Tencent 추정) — behavior item 단위 two-axis 압축으로 프로파일링 파이프라인을 대체, 주간 10억 유저·100K QPM 규모에 10개월 배포, GMV +1.37% (95% CI [0.71%, 2.03%]) · 190 GPU 절약

  • 무엇: KuaFu는 산업 규모 추천 시스템의 유저 프로파일링 파이프라인을 위해 raw 행동 시퀀스를 압축하는 표현 레이어다. 태스크별 모델이 시퀀스를 따로 자르는 관행 대신, behavior item 하나를 최소 압축 단위로 잡고 item마다 독립적으로 압축한다. downstream profiling 태스크들은 이 캐시를 공유한다.
    • 세부: Two-axis projector가 각 item 임베딩을 2–4 tokens × width 128–256으로 줄인다. 그 결과 per-item 캐시가 10 KB → 0.5 KB로 감소한다(토큰 축 10×, width 축 20×).
    • 세부: 훈련은 4단계로 쌓인다.
      • understanding: 재구성
      • post-training: 42 태스크 유형의 layered-difficulty 데이터
      • co-training: 압축과 생성을 동시에 다루고, reconstruction에 sequence-length curriculum을 쓴다.
      • hallucination-aware RL: 압축과 projector는 freeze하고, decoder만 DAPO로 업데이트한다.
    • 세부: RL의 reward는 네 hallucination 유형에 harm 가중치를 준다. 가중치는 fabrication 0.45, date misattribution 0.24, broken logic 0.24, missed detection 0.07이다.
  • 왜 주목: 주간 10억 유저, aggregate 100K QPM 규모의 profiling 파이프라인에 배포됐다. 추가 10개월 관측에서 GMV +1.37% (95% CI [0.71%, 2.03%])가 나왔다. 오프라인에서는 per-GPU throughput +37–350%, GPU 190대 절약을 기록했다 확인.
    • 세부: A/B는 unique visitor 단위였다. 4주 내 0% → 100% rollout 후 5% 홀드아웃을 남겨 관측을 이어 갔고, 두 arm은 동일 GPU·스토리지 예산 아래에 있었다.
    • 세부: 오프라인에서는 4개 프로덕션 profiling task의 5 headline metric 전부에서 uncompressed single-task 프로덕션 모델과 매치되거나 상회했다 확인.
    • 세부: 공개 벤치마크로는 MRQA out-of-domain에서 기존 compressor 대비 최대 +17.7 EM을 기록했다. RecBench에서는 KuaFu 4B가 8B보다 1.90 point 높았다.
    • 세부: Hallucination-aware RL은 fabrication hit rate를 33.5 → 4.5(~29 pp 감소)로 낮추고, fully-correct rate를 +34.0 pp 올렸다.
    • 세부: 저장소 코퍼스에서 ChronicleRec (Tencent PCG)은 랭커의 입력 캐시(target-independent Chronicle Token)에 집중한다. KuaFu는 profiling 파이프라인 자체를 공유 압축 위에서 재구성한다는 점에서 자리가 다르다.
    • 세부: 입력 tokenization을 다룬 Meta AMBER, 오프라인 factorial 비교인 Comcast LLM profiling과 대비되는 profiling 축의 첫 대규모 프로덕션 A/B 진술이기도 하다.

Pinterest 3-Tower Engagement Co-Train — 광고 lightweight ranking을 two-tower 밖으로, 프로덕션 A/B에서 CTR·gCTR30·oCTR 각 ~1% 상승·CPC ~1% 감소로 launched

  • 무엇: Pinterest 광고 스택의 표준 광고 lightweight ranking 모델이다. 기존 two-tower 모델의 query·Pin 두 tower는 그대로 두고 cross tower와 inter module을 더해, 같은 모델이 후보 전량에는 빠른 two-tower 점수를, 최상위 서브셋에는 정확한 three-tower 점수를 동시에 낸다.
    • 세부: Cross tower는 세 종류의 유저 시퀀스와 네 종류의 후보 피처를 입력으로 받는다. 후보 피처로 만든 query token이 유저 시퀀스와 cross-attention을 수행한다.
      • 유저 시퀀스: organic engagement, ads engagement, search history
      • 후보 피처: advertiser ID, campaign ID, GraphSAGE 임베딩, Pin PinnerSAGE 임베딩
    • 세부: Inter module은 query·Pin·cross 세 임베딩을 shared-bottom MLP로 합쳐 세 태스크의 logit을 생성한다.
      • pCTR: 클릭 확률
      • pGCTR30: 30초 이상 지속되는 good click 확률
      • pOCTR: 광고주 사이트로의 outbound click 확률
    • 세부: 서빙은 두 stage로 나뉜다.
      • Stage 1은 co-train된 two-tower head로 후보 전량을 채점한다.
      • Stage 2는 utility 상위 40K만 three-tower로 재채점한 뒤, 두 점수를 blending해 최종 top-K를 뽑는다. 이 상위 구간은 Home Feed·Related Pins에서 70퍼센타일, Search에서 90퍼센타일 수준이다.
    • 세부: Loss는 three-tower인 main 항에 강한 가중치를, two-tower인 co-train 항에 보조 가중치를 준다.
      • 식은 L = (100·L_main_ctr + 5·L_main_gctr30 + 1·L_main_octr) + (10·L_cotrain_ctr + 5·L_cotrain_gctr30 + 1·L_cotrain_octr)이다.
  • 왜 주목: 표준 광고 프로덕션 A/B에서 CTR·gCTR30·oCTR은 각각 ~1% 오르고 CPC는 ~1% 줄었으며, 모델은 GPU 지출이 modest하게 느는 선에서 launched됐다 확인.
    • 세부: 오프라인 손실은 three-tower 예측에서 ~30% 줄었다. baseline은 기존 프로덕션 two-tower 모델이다.
    • 세부: 서빙 최적화 결과는 정량으로 나와 있다.
      • BF16 도입: 50K 후보 기준 P99 103ms → 56ms, 20K 후보 기준 45ms → 26ms
      • user feature의 late expansion: 100K 후보에서 -15ms
      • pre-layer normalization: -3ms
      • Pin 전처리를 Pin tower로 이동: -2ms
    • 세부: 이들을 합쳐 P99 모델 추론이 200ms 이상 → 30ms로 줄었고, 프로덕션 대비 지연 증가는 1-2ms에 그쳤다.
    • 세부: 저장소 코퍼스에서 Pinterest CLR은 유기 Home Feed의 후보 생성 축을, PinDCO는 광고 creative 선택 축을 다뤘다. 3-Tower Co-Train은 광고 lightweight ranking 축의 진술이라 자리가 다르다.
    • 세부: 특히 "co-train으로 fast + slow 두 헤드를 한 모델에 담고 서빙에서 두 stage로 나누는" 패턴은 저장소의 lightweight ranking 자리에서 처음 나온 프로덕션 진술이다.
    • 세부: Nexus 서빙 스택(Part 1)이 candidate generation과 scoring을 분리했고, 이번 Part 2가 그 위에서 스코어링을 확장했다는 시퀀스로 읽힌다.
  • 근거: 확인 Beyond Two Towers: Launching the 3-Tower Engagement Co-Train Model (Part 2), 2026-09-17, Pinterest Engineering. 저자는 8인이고, 마지막 저자는 Manager II, Ads Lightweight Ranking이다.
    • 세부: 저자는 Longyu Zhao·Gwendolyn Zhao·Peng Yan·Yuanlu Bai·Yuan Wang·Yao Cheng·Ang Xu·Zhaohong Han이다.
  • 상태: 관찰. Pinterest는 추적 서비스가 아니므로 services 정본은 만들지 않는다. Part 1(Nexus)은 저장소에서 아직 다루지 않았다. 자세한 분석은 daily/2026-09-28.md에 있다.
    • 세부: 다음 관측 지점은 Nexus의 candidate generation·scoring 분리 아키텍처다. 두 번째 회사가 광고 lightweight ranking 자리에서 co-train fast·slow 패턴을 진술하는지도 지켜본다. 3-Tower의 후속 방향(더 긴 시퀀스, engagement 이외 objective로의 확장)에 대한 회사의 후속 진술이 나오는지도 본다.

AgentX-Model (Kuaishou 추정) — 산업 recommender 리서치 루프를 dual-agent(Research + Model)로 자동화, 프로덕션 A/B 5건에서 acquisition +10-15% · ad spend +15-20% · watch time +0.3-0.8% · FLOPs −10%

  • 무엇: AgentX-Model은 프로덕션 recommender 팀의 리서치 순환(제안 → 실험 → 다음 질문)을 두 에이전트로 자동화하는 프레임워크다. Research Agent가 논문과 이전 실험에서 독립적으로 리뷰된 제안을 만들고, Model Agent가 그 제안을 코드·측정·미해소 질문으로 옮긴다.
    • 세부: Research Agent는 결과를 다시 받아 시작 구현을 선택하고 다음 질문을 짜서, 후속 실험이 이전 결과 위에 쌓이게 만든다.
    • 세부: 리서치 액션은 4개다.
      • Reproduce: 재현
      • Follow-up: 확장
      • Composition: 결합
      • Diagnose: 온라인 평가에서 발견된 이슈나 PCOC로 측정된 예측 편향 같은 문제에 대해 진단·수리 후보의 근거를 수집한다.
  • 왜 주목: 프로덕션 A/B에서 acquisition efficiency +10-15%, target-segment advertising spend +15-20%, watch time +0.3-0.8% (5건 평균)를 기록했다. watch-time 모델은 FLOPs와 파라미터를 약 10% 줄였다. 그리고 완료된 model-changing 실험 636건 중 560건(88%)이 비즈니스 baseline 대비 오프라인 AUC를 넘어섰다 확인.
    • 세부: 2026-09에 리서치 자동화 각도가 명시적으로 이름 붙어 공개된 두 번째 사례다. 첫 번째는 Meta VDD MBR·EvoPilot의 "37일 human-gated autoresearch 캠페인이 evaluator output-depth 3000/600 결함을 잡아 offline +3.20pp 회복"이다.

    • 세부: dependency-aware historical-replay 벤치마크도 함께 냈다. 초기 결과는 "에이전트가 이미 구체 후보를 분석·선택하는 경우 더 복잡한 스케줄링이 일관된 효율 이득을 주지 않는다"고 진술한다.

OneTrans-V2 — 산업 추천의 retrieval + pre-rank + fine-rank 캐스케이드를 단일 Transformer로 통합, GMV +9.74% · throughput 3.2×

  • 무엇: OneTrans-V2는 산업 추천 시스템의 3단 캐스케이드(retrieval → pre-rank → fine-rank)를 하나의 Transformer로 통합하는 접근이다. user behavior sequence는 shared context로 한 번만 인코딩하고, stage별 candidate feature와 computation은 유지한다.
    • 세부: Joint training으로 세 stage가 상호 강화되고, in-model knowledge distillation이 fine-rank에서 pre-rank로 흐른다.
    • 세부: 백본은 sparse MoE로 확장하고, μP-style parameterization으로 스케일링을 안정화한다.
    • 세부: objective별 retrieval 채널을 따로 두는 대신 DCGR(Decision-Conditioned Generative Retrieval)로 통합한다. DCGR은 decision prefix를 먼저 예측한 뒤, 그 prefix에 조건화해 아이템을 생성한다.

  • 왜 주목: 프로덕션 A/B에서 GMV +9.74%, 같은 하드웨어 예산에서 3.2× throughput을 기록했다 확인.
    • 세부: 저장소 코퍼스에서 stage 간 통합을 다룬 최근 프로덕션 진술로는 UNIQUE (Baidu, RecSys 2026)와 UniRec (Kuaishou)가 있었다. OneTrans-V2는 여기에 3-stage 전체를 하나의 Transformer로 묶었다는 세 번째 각도를 더한다.

Spotify Robust Fusion — QSS + dual-sample dropout으로 LLM reranker의 behavioral 과의존을 억제

  • 무엇: Robust Fusion은 Spotify 개인화 검색의 LLM cross-encoder reranker가 semantic 신호와 behavioral 신호를 융합할 때 생기는 shortcut learning을 억제하는 학습 절차다. 저자들은 deterministic dual-sample feature-dropout을 제안한다.
    • 세부: QSS(Query Slice Stats)는 쿼리-후보 쌍의 과거 성공률을 요약한, 상호작용에서 유래한 피처다. 이 피처를 프롬프트에 그냥 실으면 QSS가 있는 슬라이스에서는 랭킹이 올라가지만, QSS가 없는 rare/unseen 쿼리에서는 성능이 떨어진다.
    • 세부: dual-sample feature-dropout은 각 학습 예를 QSS 포함 1회, QSS 제거 1회로 두 번 넣는다.
    • 세부: 오프라인에서는 QSS가 있을 때 랭킹 품질이 +13.3% 올랐고, QSS-removed 슬라이스에서는 naive QSS 대비 +4.0% 개선됐다. 온라인 A/B에서는 QSS-aware 두 변형 모두 live search success ≈+2%를 기록했다.
    • 세부: aggregate test는 dual-sample과 features-only 학습을 구분하지 못하지만, cold-start 비교는 오프라인 결과와 방향이 일치한다고 진술한다.
  • 왜 주목: cross-encoder LLM reranker가 프로덕션 검색에서 A/B로 검증됐다는 진술 자체가 흔치 않다. 다수 논문이 오프라인 지표에서 멈춘다.
    • 세부: Spotify는 GLIDE에서 LLM candidate generator를, SPDD에서 inference-time decoding을 배포했다. 이번에는 LLM reranker의 shortcut learning 대응책까지 프로덕션 A/B로 옮겨진다.
    • 세부: dual-sample dropout이라는 조절 수단은 behavioral feature가 없거나 stale한 슬라이스에서의 robustness와, 있을 때의 이득을 동시에 확보하는 프로덕션 방법론이다. LLM reranker를 도입하려는 다른 회사에도 그대로 적용 가능한 형태다.
  • 근거: 확인 arXiv 2609.25825, 2026-09-22 v1, USRW Workshop @ RecSys 2026 accepted. 저자 7명 전원의 이메일 도메인이 @spotify.com이다(HTML 판에서 확인).
  • 상태: 관찰. Spotify는 추적 서비스가 아니므로 services 정본은 만들지 않는다. 자세한 분석은 daily/2026-09-24.md에 있다.
    • 세부: 관측 지점은 behavioral feature의 dropout이 유기 피드 recommendation의 LLM reranker에도 이관되는지다. 다른 검색 엔지니어링 조직(Amazon·eBay·Booking 등)에서 유사한 dual-sample 학습이 발표되는지도 본다.

    • 세부: 저자는 이 접근이 효율적인 후보 생성을 유지하면서 long-tail·cold-start 문제를 겨눈다고 쓰고, 서빙 측정치로 P99 89ms와 온라인 추론 MFU 44.23%를 보고한다.

Meta Search Hybrid GPU-CPU Retrieval — trillion-doc source corpus를 GPU billion / CPU tens-of-billions 두 경로로 co-serving, deployed in production

  • 무엇: Meta의 personalized search retrieval 계층을 프로덕션 아키텍처 수준에서 처음 밝힌 진술이다. GPU와 CPU 두 하드웨어 경로가 각자 따로 고른 문서 snapshot을 함께 서빙한다.
    • multi-trillion 규모 source corpus의 문서는 policy·quality·language·freshness·dedup을 통과한다. 그 뒤 하드웨어별 selector가 GPU snapshot과 CPU snapshot을 독립으로 만든다. GPU snapshot은 billion-scale이고, CPU snapshot은 tens-of-billions로 대략 20배다.
    • GPU pathway는 two-tower retrieval과 interaction pre-ranking을 하나로 합쳐(fuse) 인터랙션 pre-ranking을 서빙 경로에 넣는다. 그리고 후보 224개를 shared ranker에 넘긴다.
    • CPU pathway는 dense embedding index, eager term-at-a-time scoring, bulk scanning, finer clustering을 조합하고, dot product만 쓴다.
    • 요청마다 두 경로 중 하나만 켜거나, 둘 다 켜거나, 끌(disable) 수 있다. 두 경로의 결과는 aggregator에서 중복을 제거(dedupe)한다.
    • legacy CPU-only 구성과 비교한 full-system A/B에서 model-scored relevance와 substantive engagement가 함께 오른다고 진술한다.
    • CPU pathway는 dense retrieval baseline보다 capacity가 4배 개선됐다고 주장한다. 이 수치는 vector op에 한정된다.
  • 왜 주목: Meta의 search 인프라 논문은 2020년의 EBR과 2021년의 Que2Search 이후 오랜 공백이 있었다. depth–breadth heterogeneous co-serving을 프로덕션 A/B 수치와 함께 다룬 진술로는 이 저장소의 코퍼스 안에서도 첫 각도다.
    • 기존 topics는 랭킹·retrieval 모델 층에 집중되어 있고, 서빙 하드웨어 분업 층은 다루지 않았다.
    • 이 논문은 Good Search Result Rate, 즉 GSRR이라는 같은 지표를 쓰는 VDD/EvoPilot 논문과 인프라(Xue et al., 2026 "existing GPU platform")를 상당 부분 공유하는 것으로 보인다.
    • Meta 검색·discovery 지면의 retrieval 스택 계층 정보가 두 편에 걸쳐 함께 열린다는 점이 이번 관측의 축이다.
  • 근거: 확인 arXiv 2609.21281, 2026-09-18 v1 제출, KDD 2027 accepted. 저자 21인 전원이 Meta Platforms(Menlo Park) 소속이며, HTML 판에서 확인했다.
  • 상태: 관찰 (심층 분석 필요). 이 저장소가 추적하는 Facebook Feed와는 지면이 다르지만, 인프라를 공유할 가능성이 있다. 자세한 분석은 daily/2026-09-22.md에 있다.
    • Xue et al., 2026 참조가 어느 논문인지 확인해서 저장소 topics의 계층 정보에 이어 붙인다.
    • Google/Bing/Yandex 계열에서도 depth–breadth heterogeneous co-serving을 프로덕션 A/B 수치와 함께 발표하는지 지켜본다. GPU pathway의 P99 팽창을 이후에 줄였다는 진술이 나오는지도 다음 관측 지점이다.

Meta VDD Model-Based Retrieval + EvoPilot — seed video + pivot query + user context MBR, 온라인 따라잡기 37일 캠페인, GSRR +0.66% relative

  • 무엇: VDD(Video Deep Dive)는 Meta의 online follow-on discovery 지면이다. 유저가 seed 비디오를 열면, 그 뒤로 볼 만한 비디오를 검색과 랭킹 방식으로 이어 준다. 이 논문은 VDD의 retrieval 모델 MBR과, 그 위 캠페인 층에서 돌아가는 LLM 실험 프로토콜 EvoPilot을 다룬다.
    • 논문은 VDD의 서빙 규모를 이렇게 적었다: "hundreds of millions of users".
    • 요청은 세 요소 (s, q, u)로 이뤄진다: seed video s, machine-generated pivot query q, user/context u.
    • 그 위에 두 타워 dense retrieval인 MBR(model-based retrieval)이 놓여 있다. request tower Q는 pivot query, user context, request-side seed feature를 받고, candidate tower D는 candidate video feature만 받는다.
    • primary loss는 out-of-session in-batch InfoNCE다. 같은 세션의 예시는 negative에서 뺀다.
    • candidate-conditioned interaction head G(h_r, h_d, a(d))는 click과 engagement auxiliary label에 대해 weighted BCE를 낸다.
    • 인덱스는 hundreds of millions of videos 규모로 매시간 재발행되지만, 가중치는 매시간 재학습하지 않는다.
    • 베이스라인은 P=K=3000, interaction head를 끈(disabled) 구성이다.
    • EvoPilot은 human-gated LLM autoresearch 프로토콜이다. 위쪽 캠페인 층에서 37일 동안 7 direction 캠페인을 돌린다.

PCap (Meta Facebook Marketplace) — retrieval-stage 다양성 캡핑을 유저별 Shannon entropy 버킷으로 개인화, Marketplace Feed에 launched, VPV +0.30% + PDP +0.22% + Sessions +0.17%

  • 무엇: PCap은 Meta Facebook Marketplace의 후보 생성 단계에서 유저별 다양성 제약을 카테고리별 상한(cap)으로 강제하는 프레임워크다.
    1. 유저 u의 최근 클릭 카테고리 분포로 Shannon entropy $S(u) = -\sum p(c|u)\log p(c|u)$를 계산해, 다양성 선호도의 프록시로 삼는다.
    2. 유저를 6개 버킷으로 정렬해 bucket-1부터 bucket-6까지 나눈다. bucket-1은 가장 좁게 클릭하는 유저이고, bucket-6은 가장 넓게 클릭하는 유저다.
    3. multi-source 인덱서 shard마다 카테고리별 상한을 걸어, scanning과 aggregation 두 단계에서 함께 캡핑한다. 상한은 retrieval source fetch count × 튜닝된 multiplier fk × 유저 버킷의 다양성 multiplier mu다.
    • 카테고리를 묶는 키는 Facebook Product Taxonomy(FPT)의 수백 개 카테고리다.
    • 파라미터 탐색에는 새 방법인 Parameter Tuning Sequence(PTS)를 쓴다. PTS는 control arm을 고정한 채 후보 arm들에 소량의 트래픽을 며칠씩 노출하는 sequential range-narrowing A/B 절차로, 온라인 grid search를 대체한다.
  • 왜 주목: Marketplace Feed 프로덕션 A/B에서 유의미한 lift를 유지하면서, carrier metric인 Marketplace Sessions까지 함께 오른다 확인. 서빙 지연 팽창이 0.8ms에 그친다는 점, capping이 랭킹 단계가 아니라 retrieval scanning에 붙는다는 점이 새로운 각도다. 기존 MMR·DPP는 랭킹·재순위 층에 있다.
    • Phase 1은 uniform cap과 무캡을 비교했고, 결과는 VPV +0.3088%(p<0.01), Latency +8.6 ms다.
    • Phase 2는 PCap과 uniform cap을 비교했고, 결과는 VPV +0.2243%, PDP clicks +0.2250%, Marketplace Sessions +0.1708%, Latency +0.8 ms다.
    • 버킷별로 갈리는 다양성 점수 변화(bucket-1 −1.05%, bucket-6 +0.25%)는 "좁게 클릭하는 유저는 좁게, 넓게 클릭하는 유저는 넓게"로 개인화됐다는 근거다.

  • 근거: 확인 arXiv 2609.16452, 2026-09-15 제출. 저자 11인 전원이 Meta(Menlo Park·Boston) 소속이며, @meta.com 도메인을 HTML 판에서 확인했다.

UniRec (Kuaishou) — 캐스케이드 pre-ranking + ranking fusion을 two-stage joint learning으로 정렬, app usage duration +0.616%

  • 무엇: UniRec(Unified Cross-stage Recommendation Fusion)은 industrial recommender 캐스케이드의 두 stage에 있는 fusion agent를 joint learning으로 정렬한다. 두 stage는 pre-ranking과 ranking이다. 두 agent는 input embedding을 부분 공유하고, single computation graph에서 함께 학습되어 gradient가 stage 사이를 흐르게 한다.
    • Dual-axis preference alignment는 두 축으로 작동한다. vertical 축에서는 downstream pairwise preference를 upstream fusion score에 전이한다.
    • horizontal 축에서는 이질적 prior signal에 대한 수십 개 pairwise objective를 bidirectional preference evidence로 재편한다.

  • 왜 주목: HSTU와 OneRec 양쪽을 프로덕션 베이스라인으로 대체한 첫 사례다. SID 라인(→ 생성형 retrieval / semantic ID 스레드)에 회사 규모로 두 번째로 큰 진술이 붙었다.
    • 논문은 OneRec과의 관계를 명시적으로 밝혔다: "aligned with the one-model direction of OneRec at Kuaishou".
    • CCFormer는 Scenario 1과 2에 전면 출시(fully launched)돼 프로덕션 전체 트래픽을 담고 있고, HSTU와 DLRM을 대체했다. CTR은 +3.57%, ad revenue는 1.71% 올랐고, HSTU 대비 GFLOPs는 절반, 훈련은 2.21x다.
    • BARGE는 generative retrieval channel로 전면 롤아웃(fully rolled out)됐고, OneRec 대비 Hit@5가 +10.2–16.9%다.
    • HiGR은 OneRec 대비 slate quality +15.9–21.3%, 추론 속도 5x를 기록했다(A/B 세 시나리오).
    • TGR-Reason은 콜드스타트 new-user Hit@1에서 +477.8%를 기록했다.
  • 근거: 확인 arXiv 2609.00986, 2026-09-01 v1. 소속은 HTML로 확인했다.
  • 상태: 관찰. SID 스레드에 강한 근거로 편입한다. HSTU/OneRec를 한 프레임에서 통합하는 세 번째 회사 진술이 나오면 topics/llm-in-recsys.md나 새 topic(one-model recommendation)으로 승격할 후보다.
    • 심층 분석이 필요한 항목은 BARGE OSQ-VAE codebook 구조, HiGR PCRQ-VAE와 OneRec SID의 실질 차이, Think 모델 백본과 reason token 코퍼스 규모, Scenario→Tencent 제품 매핑이다.

ReST (ByteDance / TikTok Shop Ads) — behavior-sequence Transformer scaling을 광고 랭킹에 프로덕션 배포

  • 무엇: TikTok Shop Ads에 배포한 rec-native Transformer 랭킹 프레임워크다. 신호 품질 축과 계산 비대칭 축의 구성 요소를 조합한다.
    • 신호 품질 축: Dual-gated attention, rotary positional and temporal embedding, stabilized residual normalization, training-only auxiliary objectives
    • 계산 비대칭 축: heavy reusable encoder와 lightweight cross decoder with projection-free KV attention
  • 왜 주목: TikTok Shop Ads 1주 A/B에서 AUC +1.31%, Advv +11.93% (p<0.01)를 얻었고, 50 ms P99 지연을 유지했다. 논문은 fully deployed in production이라고 명시했다. Meta HSTU·Wukong, LLaTTE, Alibaba TransRetrieval에 이어 스케일링 법칙 스레드에 ByteDance의 진술이 붙었다.
    • 저자들은 LLM 스타일 Transformer 블록이 saturate하는 sequence length·depth·width에서 ReST가 일관되게 scaling된다고 주장한다.
    • 크기는 ReST Base 5.69M, Large 22.64M 파라미터다. 두 값 모두 시퀀스 모델링 부분만 센 것이다.
    • 추천 모델 스케일링 법칙 스레드에 근거로 편입한다.
  • 근거: 확인 arXiv 2609.01240, 2026-09-01 v1, HTML. 저자 12명 전원이 ByteDance 소속이다.
  • 상태: 관찰. 이 논문에서 LLaTTE 대 HSTU의 "semantic feature 필요성" 논쟁에 대한 조건부 확인은 명시적으로 서지 않았지만, LLM 블록 대신 rec-native 설계가 필요하다는 방향으로 정렬된다. TikTok Shop Ads가 광고 도메인이어서, 유기 피드로 확장되는지가 관전 포인트다.

CAMIE (Snap DPA) — I2I retrieval의 공유 인코더 + 공동참여 신호

  • 무엇: Snap Dynamic Product Ads(DPA, 광고)의 item-to-item 검색이 가진 두 문제를 다룬다. abstract에서 프로덕션 DPA 배포를 진술했다.
    • 별개로 학습된 시각·텍스트·멀티모달 인코더가 임베딩 공간을 분절시켜, 서로 다른 아이템 유형 사이의 검색 품질이 떨어진다.
    • co-engagement 신호(같은 유저가 두 아이템을 함께 본 관계)를 대칭 대조로만 다루면, 아이템의 상호작용 문맥을 반영하지 못한다.
  • 왜 주목: 광고 도메인의 I2I retrieval에서 Snap이 프로덕션 진술을 낸 최근 사례가 드물다. Snap의 다음 진술이 이 라인을 이어갈지가 다음 관전 포인트다.
    • 같은 그룹이 비슷한 시점에 SetMIR(multi-interest retrieval as set prediction)도 냈다. 하지만 SetMIR abstract에는 Snap 프로덕션 진술이 명시되지 않아 그쪽은 보류한다.
  • 근거: 확인 arXiv 2608.30255, 2026-08-31 제출. 저자는 12인(Xiaodong Liu, Siman Wang, Congfei Zhang, Hsiang-wei Chao, Xiao Bai 외)이고, HTML 판이 전원의 소속을 Snap Inc.로 표기한다.
  • 상태: 관찰. I2I retrieval 스레드는 아직 정본에 없다. Snap이 후속 진술을 내거나, 두 번째 회사(Pinterest·Meta 광고 등)에서 공유 인코더와 co-engagement를 함께 쓴 비슷한 진술이 나오면 topic 승격 후보가 된다.

VK Friend Recommendation GNN — 194M 유저·28B 엣지 프로덕션 소셜 그래프에서 message-passing GNN을 스케일한 사례

  • 무엇: 수억 유저와 수백억 엣지에 이르는 프로덕션 규모의 소셜 그래프에서 message-passing GNN의 학습과 서빙을 붙일 때 부딪히는 시스템 문제와 모델링 문제 두 가지를 정면으로 푼다 확인.
    • 친구 추천은 다중 홉 소셜 컨텍스트가 유저 속성보다 결정적이라서 message-passing GNN이 자연스럽다.
    • Multi-hash user embeddings는 유저 ID마다 여러 해시 함수의 임베딩 lookup을 조합한다. 이렇게 해서 ID 임베딩 테이블 크기를 98% 이상 줄이면서도 ranking quality를 유지한다.
    • Temporal neighbor sampling은 timestamp-sorted CSR 저장과 binary search로 이웃 샘플링을 O(deg(v) + k)에서 O(log(deg(v)) + k)로 줄인다. 슈퍼노드(팔로우가 극단적으로 많은 계정)의 이웃 순회 비용이 로그 시간으로 억제된다 확인.
  • 왜 주목: 194M users · 28B edges 규모의 소셜 그래프에서, 강한 프로덕션 베이스라인 대비 friend additions from recommendations +16%, unique friend adders +11.5%를 얻었다.
    • 강한 프로덕션 베이스라인 대비 두 자릿수 uplift는 GNN 논문에서 드물다.
    • Meta ConnectionMind가 그래프 위에서 경로를 추론하는 LLM이라면, 이쪽은 순수 GNN을 소셜 그래프의 스케일 한계까지 밀어붙인 사례다.
    • GNN이 실무에서 결국 살아남는 도메인은 친구 그래프나 follow 그래프처럼 완전히 명시적인 그래프라는 관찰이 강화된다.
    • X의 SimClusters(SVD 기반), Meta의 GNN·LLM 이중 스택과 대조해 볼 수 있는 자료이기도 하다.
    • 서빙 지연 없이 적용했다는 말은 abstract에 명시되어 있지 않다. 다만 테이블 축소와 이웃 순회의 로그화라는 두 최적화의 목적이 정확히 그것이다.
  • 근거: 확인 arXiv 2608.27413, 2026-08-27 v1, CIKM 2026 accepted. 저자는 3명(Maksim Utushkin·Andrei Ovsiannikov·Alexander D'yakonov)이다.
    • 소속은 저자 이름과 본문에 언급된 규모로 보아 VK로 추정한다 추정. HTML abstract에는 소속 표기가 없고, 코드 릴리스는 언급되어 있다.
  • 상태: 관찰 중이다. VK는 이 저장소의 정본(canon)이 추적하는 서비스가 아니어서 승격은 보류한다. 학회 발표 슬라이드(CIKM 2026 10월)가 나온 뒤에 소속과 인프라 세부가 추가로 공개될 가능성이 있다.
    • 두 번째 회사(Meta가 아닌 곳)에서 비슷한 프로덕션 GNN 진술이 나오면 topics/embedding-retrieval.md나 새 social-graph-gnn topic의 후보가 된다. LinkedIn 친구 추천이나 Facebook People You May Know의 GNN 갱신이 그런 예다.

SWIM (Kuaishou 메인 피드) — Generator-Evaluator 재순위의 Evaluator를 세션 survival process로 재설계

  • 무엇: 산업 재순위의 G-E(Generator-Evaluator) 아키텍처에서 리스트를 채점하는 Evaluator를 다시 설계한다. SWIM은 유저 행동을 finite-horizon prefix session-level survival process로 모델링한다 확인.
    • 종전 evaluator는 단일 요청 metric(예: expected watch time)만 보기 때문에 세션 관점을 놓친다.
    • 현재 리스트가 세션 목표에 얼마나 기여하는지는 recursive survival distribution과 reached-position conditional rewards로 factorize한다 확인.
  • 왜 주목: Kuaishou short-video app(>400M DAU)의 메인 피드 재순위에 프로덕션 배포했다. 7일 동안 5% 트래픽으로 A/B를 돌려 App stay time +0.351%, 7-day retention +0.048%를 얻었다 확인.
    • 신뢰구간은 App stay time이 95% CI [0.27%, 0.42%], retention이 CI [0.01%, 0.09%]다 확인.
    • 이전 evaluator인 CAVE를 교체했고, upstream retrieval과 generator는 유지했다.
    • DrEM, HD-Rec, PushDualGen에 이어 Kuaishou가 8월에만 네 번째로 낸 프로덕션 진술이다. evaluator 자체를 재설계했다는 점에서 새 갈래다.
  • 근거: 확인 arXiv 2608.25104, 2026-08-25, 저자는 Kuaishou Technology 6인과 USTC 2인, 그리고 무소속인 Kun Gai다.
  • 상태: 관찰 중이다. evaluator 자체를 세션 survival로 재설계한 다른 회사의 진술이 나오면 topics/feed-diversity.md나 재순위 topic의 후보가 된다.
    • 같은 달에 Kuaishou가 서로 다른 알고리즘 라인 네 편에서 프로덕션 진술을 냈다는 점이 회사 차원의 관전 포인트다. 네 라인은 SID(아이템을 이산 토큰 ID 시퀀스로 나타낸 semantic ID) cross-domain, SID+CoT 푸시, ensemble ranking noise, G-E evaluator survival이다.

MetaStrategy (Alibaba/Taobao) — LLM이 채점하지 않고 "실행 가능한 랭킹 전략 JSON"을 생성한다

  • 무엇: LLM 정책이 요청 컨텍스트를 받아 typed JSON 번들을 생성하면, 결정론적 validator와 compiler가 이를 격리된 Generator로 인스턴스화한다 확인. 이 Generator는 GE(Generator-Evaluator) 아키텍처의 list-level Evaluator 아래에서 기존 전략과 원자적으로 경쟁한다 확인.
    • JSON 번들은 objective weights, content/category preferences, experience constraints, position policies로 이뤄진다.
    • 훈련은 4B×2 teacher에서 0.8B student를 만드는 방식이다. production-path replay, 3종 reward, self-competitive curriculum, Evaluator-routed on-policy distillation을 조합한다.
    • production-path replay는 로그된 요청을 사용자 노출 없이 재실행한다. reward는 selection, relative-rank, baseline-lift 세 가지다.
  • 왜 주목: Taobao Homepage Guess You Like에 diff-triggered nearline 방식으로 배포했다. 7일 유저 랜덤화 A/B에서 click PV +2.11%, IPV +3.12%, 거래액 +2.83%를 기록했다 확인.
    • LLM inference가 동기 랭킹 밖에 있어서 RT 영향은 관측되지 않았다.
    • 같은 A/B에서 처리군은 GE call의 27.93%를 이겼다 확인.
    • Netflix GenRec은 온라인에서 채점하는 LLM이고 Yandex Gryphon-v2는 온라인에서 생성하는 LLM인데, MetaStrategy는 이들과 대비되는 오프라인 정책 컴파일러 각도다. 그래서 LLM-native 스레드의 세 번째 메커니즘에 해당한다.
  • 근거: 확인 arXiv 2608.09440, 2026-08-10.
  • 상태: 관찰 중이다. 세 번째 회사에서 비슷한 nearline LLM 정책 컴파일러 진술이 나오면 topics/llm-in-recsys.md에 절을 신설할 후보가 된다.
    • 같은 지면(Taobao 홈피드)을 다루는 DREAM과 대칭 관계다. MetaStrategy는 정책 컴파일러이고, DREAM은 실시간 파라미터 조정이다.

DREAM (Alibaba/Taobao) — 기존 파이프라인 위에 agentic 메타 제어 레이어를 추가한다

  • 무엇: retrieval/rank/re-rank 파이프라인을 그대로 두고, 그 위에 policy layer를 추가하는 아키텍처다 확인.
    • 3층 Intent Engine(L0/L1/L2)이 온디바이스 신호를 구조화된 인텐트로 융합한다. 엣지-클라우드 트리거 체인으로 리포팅 볼륨을 ~8.7%까지 압축한다.
    • 그러면 MetaModel이 M1, M2, M3 순서로 추론해 파이프라인 파라미터를 조정하고, 안전 가드레일을 통과한 뒤에 배포한다.
    • M1은 인텐트를 요약하고, M2는 Strategy Memory를 참조해 전략을 계획하며, M3는 파라미터로 번역한다.
    • Reward Dual Loop(오프라인 시뮬레이션과 온라인 피드백)로 이중 최적화를 수행한다 확인.
  • 왜 주목: 모델을 교체하지 않고 파라미터 조정만으로 얻은 이득이라는 점이 특이하다. Taobao 홈피드 A/B에서 re-ranking 제어에만 적용했을 때 IPV +2.06%, Core IPV +2.39%, GMV +0.88%였다 확인.
    • fine ranking까지 확장했을 때는 각각 +2.71%, +3.06%, +1.31%였고, PV는 일관되게 +1% 이상 올랐다 확인.
    • 저자들은 파이프라인 모델을 교체하지도, 서빙 안정성을 해치지도 않는다고 밝혔다: "neither replacement of pipeline models nor compromise of serving stability".
    • MetaStrategy와 저자가 상당수 겹치므로 같은 조직의 두 실험선일 가능성이 있다. 겹치는 저자는 Chengyu Lai, Jiuning Lin, Bin Zhang, Han Zhu 등이다.
  • 근거: 확인 arXiv 2608.09408, 2026-08-10.
  • 상태: 관찰 중이다. MetaStrategy와 함께 "산업 추천 파이프라인 위의 LLM/agentic 제어 레이어"라는 흐름을 이룬다. 두 접근이 하나로 수렴하는지, 아니면 따로 병렬 배포되는지가 다음 관전 포인트다.

TM20K (ByteDance 광고) — 20K 시퀀스 랭킹을 teacher/student KD로 프로덕션 배포

  • 무엇: teacher가 무거운 훈련으로 정답을 만들고, token merge로 시퀀스를 압축한 student를 KD(지식 증류)로 끌어올린다 확인.
    • teacher와 student 모두 full attention을 유지한다. target-only attention이 아니다.
  • 왜 주목: Meta HSTU/GEM(광고)와 LLaTTE 계열이 주장한 "긴 시퀀스 = 더 좋은 랭킹"이라는 명제에 대해 ByteDance가 낸 프로덕션 진술이다. ByteDance 광고에서 20K까지 실제로 돌렸다.
    • 배포 결과는 시퀀스 길이 20K, ADSS +1.036%, 서빙 지연 +5.6%다.
    • 훈련과 서빙 비용은 기존 SOTA와 거의 같다고 밝혔다: "nearly the same".
    • 스케일링 법칙 스레드에 더해지는 새 데이터 포인트다. 다만 순수한 파라미터 스케일이 아니라 시퀀스 스케일을 KD로 뽑아낸 접근이라 방향은 다르다.
  • 근거: 확인 arXiv 2608.07055, 2026-08-07.
  • 상태: 관찰 중이다. 세 번째 회사 이상에서 초장기 시퀀스 진술이 쌓이면 topics/sequence-transformer-ranking.md에 절을 추가한다.
    • Meta LLaTTE와 HSTU 사이의 미해소 논쟁에 20K 시퀀스 KD 라인이 제3의 접근으로 합류한다.
    • 논쟁의 한쪽인 LLaTTE는 "semantic feature가 없으면 스케일링이 안 된다"는 입장이고, 다른 쪽인 HSTU는 "scaling만으로 된다"는 입장이다.

Progressive Alignment (Webtoon) — recsys foundation model에 RL post-training 도입

  • 무엇: 추천 파운데이션 모델(FM)을 서빙 지면별로 SFT할 때 click/like 목표가 사업 지표와 어긋나는 문제를 LP, FFT, RFT의 3단계로 푼다.
    • 먼저 LP(Linear Probing)는 프리트레이닝된 표현을 얼려 두고, 무작위로 초기화된 downstream head만 안정화한다.
    • 다음으로 FFT(Full Fine-Tuning)는 전체 모델을 target task로 특화한다.
    • 마지막으로 RFT(Reinforcement Fine-Tuning)는 학습된 reward model로 사업 지표에 정렬한다.
    • 핵심 요령은 policy를 dense implicit feedback으로 학습하고, sparse business target은 reward model에만 쓰는 것이다 확인.
  • 왜 주목: 추천 파운데이션 모델의 downstream 정렬에 LLM식 RLHF 파이프라인을 그대로 옮긴 프로덕션 진술이다. 대규모 online A/B에서 non-FM 베이스라인보다 개선했다고 주장하지만, 구체적인 숫자는 abstract에 없다.
    • Netflix Foundation Model이 downstream head를 붙이는 방식과 대비할 수 있다. Netflix는 서빙 서피스별 head를 학습으로 붙이고, Webtoon은 그 위에 RL 정렬 단계를 하나 더 추가한다.
  • 근거: 확인 arXiv 2608.06792, 2026-08-06 (RecSys '26 Industry Track).
  • 상태: 관찰 중이다. Netflix FM과 Meta GEM의 downstream 적응 절을 교차 확인할 때 쓸 자료다. 추가 프로덕션 사례가 나오면 topics/multi-task-ranking.md나 새 topic(recsys post-training)의 후보가 된다.

Gryphon-v2 (Yandex Music) — generate-and-rank 단일 모델이 캐스케이드를 대체

  • 무엇: retrieval과 rerank, rank를 단일 모델로 처리한다 확인.
    • 유저 이력을 한 번 인코딩하고, autoregressive 디코더로 Semantic-ID 후보를 생성한다.
    • 생성한 후보를 카탈로그 아이템으로 매핑한 뒤, 공유 인코더 상태를 재사용하는 item-level 랭커로 넘긴다.
  • 왜 주목: 프로덕션 A/B에서 기존 캐스케이드를 대체했고, active users는 +1.41%였으며, 서빙 지연은 캐스케이드와 비교할 만한 수준이다.
    • 대체한 캐스케이드를 저자들은 이렇게 적었다: "replaces the production cascade of 15+ candidate generators, pre-ranking and final ranking".
    • Netflix GenRec 계보에 정면으로 대응하는 프로덕션 진술이다. GenRec은 랭킹 경로의 LLM인 반면, Gryphon-v2는 retrieval과 ranking을 통합한다.
  • 근거: 확인 arXiv 2608.06213, 2026-08-06.
  • 상태: 관찰 중이다. 음악 도메인이지만 메커니즘은 도메인과 무관해서 정본 topic(llm-in-recsys, embedding-retrieval)으로 승격할 후보다. generate-and-rank 단일 모델이 캐스케이드를 대체했다는 진술이 다른 플랫폼에서 또 나오면 topic 승격을 판단한다.

    • Yandex Music이 짧은 기간에 프로덕션 논문 두 편을 냈다는 사실 자체가, SID와 LLM을 통합한 랭커 계열에 회사 차원의 자원이 투입되어 있다는 신호다.

DrEM (Kuaishou 단편 비디오) — pxtr 노이즈 이중 보정 ensemble ranking

  • 무엇: 앙상블 랭킹 단계에서 상위 멀티태스크 모델이 내는 행동별 예측 확률(pxtr)의 노이즈를 supervision side와 feature side 양쪽에서 보정한다.
    • pxtr의 예로는 pctr/pvtr/pcmtr/pftr가 있다.
    • 예측 노이즈는 두 가지 문제를 일으킨다. proxy preference 라벨을 뒤집기도 하고, feature-side 입력으로 유입되어 순위 스코어를 흔들기도 한다.
    • supervision side에는 쌍별 라벨이 뒤집힐 확률(pairwise flip probability)로 empirical risk를 정정하는 robust loss를 쓴다.
    • feature side에는 예측 노이즈 분포에서 샘플링한 perturbation에 대해 preference-preserving ranking consistency regularizer를 쓴다.
    • 이론적으로는 뒤집힐 확률의 추정에 오차가 있어도 robust loss가 basic pairwise loss보다 우월하다는 것을 증명했다 확인.
  • 왜 주목: Kuaishou의 산업 규모 단편 비디오 플랫폼에서 EMER·EASQ production 백본 위에 적용해 7일 유저 랜덤화 A/B를 돌렸다. 메인 트래픽의 5.1%를 배정했고, 모든 지표가 p<0.005였다.
    • EMER 백본 기준 처리군 지표는 Follow +1.197%, Comment +1.388%, Video View +0.691%, Long View +0.401%다. 나머지 지표는 Like +0.625%, Forward +0.683%, App Stay Time +0.116%, LT7 +0.017%다.
    • 저자들 스스로 팔로우·댓글 같은 sparse behavior가 뷰·롱뷰 같은 dense behavior보다 gain이 크다고 관찰했다.
    • 이 관찰은 이론적 예측과 일치한다. 그 예측은 스파스 태스크가 예측 분산이 커서 라벨이 뒤집힐 확률이 높고, 그만큼 robust correction의 여지도 크다는 것이다.
  • 근거: 확인 arXiv 2608.12778, 2026-08-13, 저자 8명(Kuaishou Technology Beijing과 Shenzhen University의 협업).
    • HTML에서 소속 표기를 확인했다. Kaiqiao Zhan / Xiaoxiao Xu / Tiantian He 등이 Kuaishou 라인이다.
  • 상태: 관찰 중이다. topic 승격은 두 번째 회사의 유사한 진술이 나오면 판단한다.
    • Kuaishou가 HD-Rec/PushDualGen SID 라인에 이어 pxtr ensemble 라인에서도 프로덕션 진술을 내면서 8월에 3편째를 기록했다.
    • 세 프로덕션 진술은 SID cross-domain, SID+CoT 푸시, ensemble ranking noise robustness로, 알고리즘 계열이 모두 다르다는 점이 특징이다.
    • 앙상블 랭킹의 label noise와 feature noise 이론화를 Kuaishou가 대규모 프로덕션에서 확인한 첫 사례다. 그래서 다목적 랭킹 조합에서 생기는 pxtr 노이즈를 겪는 회사에 참조 자료로 유효하다. X·Meta·Netflix가 모두 여기에 해당한다.

SDF (Google Discover) — 2년 프로덕션 staleness 필터, supersession + decay 이중 학습 모델

  • 무엇: 콘텐츠 피드의 "낡음"을 두 가지 다른 메커니즘으로 분해하고, 메커니즘마다 학습된 필터를 둔다 확인.
    • Supersession은 새 아이템이 이전 아이템을 무효화하는 경우다. 이적이 확정된 소식 이후의 이전 협상 기사가 그런 예다.
    • Supersession 필터는 pairwise classification framework를 쓴다. LLM 파이프라인으로 합성 학습 데이터를 만든 다음, 지식 증류로 학생 모델을 서빙한다.
    • Relevance Decay는 후속 아이템이 없어도 시간에 따라 자연히 감쇠하는 경우다. "오늘 밤 유성우" 안내가 그런 예다.
    • Decay 필터는 텍스트·이미지·비디오로 된 아이템의 멀티모달 콘텐츠를 입력으로 받는다. lifetime visit traffic으로 학습한 multi-horizon PTR(Predicted Traffic Ratio) 회귀 모델이다.
    • 두 필터를 disjunction(OR)으로 결합해 ranking 이전의 upstream candidate pruning 단계에 배치한다 확인.
  • 왜 주목: Google Discover에 2년 동안 프로덕션 배포했고, user-filed staleness reports가 배포 전 기준선(pre-deployment baseline) 대비 54.9% 감소했다. DAU는 수억 명, MAU는 수십억 명이다.
    • supersession filter 단독으로는 64.0%, decay filter 단독으로는 34.4%다.
    • Engagement-neutral 제약 아래에서 튜닝했고, 인위적으로 aggressive하게 자르면 지표는 더 좋아지지만 engagement가 떨어져서 배제했다 확인 4.2절.
    • X의 IS_STALE_POST14D bool feature와 대조되는 완전한 학습 기반 접근이다. X의 이 feature는 14일 시간 규칙 기반에 count zero stamp를 더한 것이다.
    • staleness를 ranking 이전에 아예 제거하는 위치여서, X의 "랭커에게 명시적 라벨을 준다"는 위치와 근본적으로 다르다.
  • 근거: 확인 arXiv 2608.15780, 2026-08-16 제출, CIKM Applied Research Track 2026 accepted (DOI 10.1145/3799682.3840082).
    • 저자 6명은 전원 Google LLC 소속이다. HTML 판에서 affiliation 표기와 @google.com 도메인을 확인했다.
  • 상태: 관찰 중이다. Google Discover가 아직 canon의 추적 서비스가 아닌 이유는 retrieval·ranking·다양성 등 나머지 스택을 공개하지 않았기 때문이다. 두 번째 컴포넌트가 공개되면 정본 등록을 다시 검토한다.
    • 두 번째 회사의 유사한 진술이 나오면 topics/에 staleness 절을 신설할 후보가 된다.
    • Netflix Foundation Model과 Meta ConnectionMind가 stale item을 어떻게 처리하는지는 확인하지 못했다.

Tlow (WeChat/Tencent) — flow-based item tokenizer가 RQ-VAE 대안으로 프로덕션 CTR +10.32%

  • 무엇: Semantic ID(SID) 라인의 item tokenizer에서, 표준 방법인 RQ-VAE의 알려진 세 가지 문제를 normalizing flow로 접근한다. tokenization의 codebook 활용률과 semantic locality 두 축에서 RQ-VAE보다 낫다고 주장한다 확인.
    • item tokenizer는 각 아이템의 의미 임베딩을 discrete token ID 시퀀스로 변환하는, SID 라인의 핵심 컴포넌트다. RQ-VAE는 Residual-Quantized VAE다.
    • 세 문제는 codebook collapse, quantization 오류의 residual 축적, 그리고 비슷한 아이템이 완전히 다른 token 시퀀스로 매핑되는 불연속성이다.
    • codebook collapse는 대부분의 code slot이 죽고 소수만 활용되는 현상이다.
    • Flow는 invertible neural network로 임베딩 공간을 학습 가능한 분포로 변환하고 다시 역변환한다 확인.
  • 왜 주목: China's largest social media platform인 WeChat(Tencent)에서 프로덕션 A/B를 돌렸다고 abstract에 명시했다. token ID 기반 retrieval model은 user CTR +10.32% globally, +11.64% for new items를 기록했다.
    • 신규 아이템에서 개선폭이 더 큰 것은 콜드스타트에 특히 강하다는 점을 시사한다. semantic tokenization 라인의 핵심 이점을 프로덕션 지표로 확인한 셈이다.
    • 지금까지 SID 라인은 대체로 "RQ-VAE + downstream 모델" 조합이었다. tokenizer 층을 flow 기반으로 대체해도 프로덕션 유효 지표가 개선된다는 첫 진술이다.
    • RQ-VAE의 codebook collapse가 실제 서빙에서 문제였다는 방증이기도 하다 추정. Tencent가 이 문제를 겪고 대안을 내놓았다고 해석한다.
  • 근거: 확인 arXiv 2608.24176, 2026-08-25 v1. 저자 소속은 Tencent WeChat rec 그룹이다.
    • Chonggang Song·Nian Li 등의 저자 명단과 WeChat 프로덕션 진술로 소속을 확정했다.
  • 상태: 관찰 중이다. SID/generative retrieval 스레드에 새 축이 생겼다. tokenizer 아키텍처 자체가 프로덕션에서 갈리기 시작했다.
    • 관전 포인트는 두 가지다. 하나는 code와 상세한 flow structure의 후속 공개이고, 다른 하나는 두 번째 회사(Kuaishou/ByteDance/Xiaohongshu)에서 비슷한 tokenizer 대안 진술이 나오는지다.
    • Tencent WeChat rec은 최근 조용한 편이었다. 이 논문 이후에 Weixin Video Channels 등 다른 지면의 진술이 이어질지 지켜볼 가치가 있다.

TAGR — 익명 대형 e-commerce live-stream 광고 플랫폼, revenue +16.1%

  • 무엇: 빠르게 바뀌는 라이브 스트리밍 광고에 맞춘 Temporally Adaptive Generative Recommendation을 제안한다. 구체적인 시간축 adaptation 메커니즘(tokenizer 재학습 주기인지, online update인지)은 abstract에 공개하지 않았다 확인.

HEGM (VK 러시아) — 짧은 비디오 watch-time 분포 예측, 프로덕션 A/B 상세 수치 공개

  • 무엇: 짧은 비디오 랭킹의 핵심 회귀 타깃인 watch time 조건부 분포를 예측하는 HEGM(Hierarchical Exponential-Gaussian Mixture)을 제안한다. 기존 SOTA인 EGMN의 세 가지 실패 모드를 반복해서 재현하면서 대응책을 마련했다 확인.
    • watch time 조건부 분포는 near-zero-inflated·long-tailed·multimodal이다.
    • EGMN(Exponential-Gaussian Mixture Network)은 Gaussian mixture로 밀도 전체를 모델링한다. 그래서 단일 point estimate가 아니라 CDF 임계 이벤트 예측을 지원한다.
    • 첫째 실패 모드인 variance collapse는 σ_k(x)→0이 되어 특정 샘플에 likelihood spike가 생기는 현상이다.
    • 둘째 실패 모드인 component redundancy는 여러 Gaussian이 μ_i≈μ_j·σ_i≈σ_j로 수렴하는 현상이다.
    • 셋째 실패 모드인 inactive components는 대부분의 mixture weight가 0으로 붕괴하는 현상이다.
    • HEGM에서는 sigmoid gate가 skip 확률 p_skip(x) = σ(W_skip h + b_skip)를 예측한다. skip이면 exponential 컴포넌트로, 아니면 Gaussian mixture로 밀도를 결합한다.
    • 이 계층적 skip-watch decomposition은 "quick skip = 무관심"과 "engaged viewing = 실제 시청"을 판정 층에서 분리한다.
    • 그 밖에 KL 기반 variance regularization을 넣고 structured initialization을 적용하며, forced Gaussian shift와 entropy regularizer를 제거한다 확인.
  • 왜 주목: VK(러시아의 대형 소셜 플랫폼)의 대규모 short-video 지면에서 프로덕션 A/B를 돌렸다. session depth는 +9.26%, shares는 +14.59%, dislikes는 −8.34%였다.
    • 시청 길이별 결과는 deep watch(≥10s) +5.75%, non-short watch(≥3s) +4.59%, skips(<3s) −6.23%다.
    • 1.5개월(1개월 forward와 2주 reverse swap) 테스트에서 처리군과 대조군에 각각 5% 트래픽을 배정했고, 하루에 각 그룹당 ~11M 요청을 처리했다 확인 HTML 판.
    • Kuaishou DrEM에 이어 짧은 비디오 프로덕션 랭킹 논문에서 또 다른 회사(VK)가 낸 진술이다. 특히 watch-time 조건부 분포 예측(EGMN 라인)이 별도의 계보로 진화하고 있음을 확인해 준다.
    • 저자는 전원 AI VK와 Lomonosov Moscow State University를 겸직한다. Yandex Music Gryphon-v2/Sona 라인과는 다른 회사인 러시아 리서치 소스가 프로덕션 진술을 잇달아 쌓고 있다.
  • 근거: 확인 arXiv 2608.23356, 2026-08-24 제출. 코드와 모델은 github.com/rw404/HEGM에 공개했다.
  • 상태: 관찰 중이다. VK 말고 두 번째 회사에서 EGMN 계열 프로덕션 논문이 나오면 topics/multi-task-ranking.md에 절을 신설할 후보가 된다.
    • Netflix Foundation Model의 watch-time head, X의 랭킹 모델 Phoenix의 quantile head 5분위(4세대+4)와 대비할 수 있는 자료다.
    • HEGM은 회귀 자체를 분포 예측으로 처리하므로, point estimate와 quantile을 조합하는 Netflix·X와는 다른 각도다.

User Behavioral Densing Law (Ant/Alipay) — 3번째 회사의 스케일링 법칙 확인

  • 무엇: tokenization의 최소 충분 용량과 데이터 스케일 사이의 densing law를 이론과 실험으로 도출하고, 이를 근거로 variable-length 방식인 ALGN을 제안한다 확인.
    • 유저 행동 시퀀스 데이터가 billion-scale로 커지면 raw 텍스트 스케일링만으로는 성능이 diminishing return에 걸리고, tokenization이 필요해진다는 문제를 다룬다.
    • 최소 충분 용량 C*와 데이터 스케일 s의 관계는 단일 차원에서 ln C*(s) = β + α ln(s/s_0)이고, 다차원에서 ln C*(s) = β + Σ_i α_i ln(s_i / s_{i,0})이다.
    • ALGN은 데이터 스케일에 따라 tokenization capacity를 적응적으로 조절한다 확인.
  • 왜 주목: Meta HSTU·Wukong·GEM 계열과 Netflix Foundation Model의 스케일링 확인에 이어, Ant Group(Alipay) 데이터로 스케일링 법칙을 형식화했다. 다만 offline 벤치마크만 있고, 프로덕션 A/B 진술은 없으며 배포 상태도 공개하지 않았다.
    • 이번에는 파라미터 스케일이 아니라 tokenization capacity 스케일의 법칙이라는 새 각도다.
    • LLM 도메인의 Densing Law(arXiv 2412.04315)가 쓴 명명과 수식 구조를 추천 도메인의 tokenization으로 그대로 옮긴 접근이다.
    • offline 벤치마크는 0.5M user held-out set과 3개 downstream task(classification, text retrieval, user-to-user retrieval)로 이뤄진다.
  • 근거: 확인 arXiv 2608.23392, 2026-08-24 제출. DeepFind Team @ Ant Group과 Zhejiang University의 협업이다.
  • 상태: 관찰 중이다. 스케일링 법칙 스레드에 tokenization capacity 스케일링이라는 세 번째 각도를 더한다. Ant Group의 다른 프로덕션 진술(예: 이 densing law를 Alipay 서빙 스택에 반영했다는 후속)이 나오면 topics/sequence-transformer-ranking.md로 승격할 후보가 된다.

Descriptive Reasoning Trace가 Recommendation Effectiveness를 떨어뜨린다 (Spotify Research) — SID+CoT 라인의 첫 반박 진술

  • 무엇: Semantic ID(SID) 기반 generative recommender에 chain-of-thought 재추론 트레이스를 붙이는 최근 흐름(SIDReasoner 등)이 traditional offline 지표를 실제로 개선하는지 통제 실험으로 확인한다. explicit reasoning trace를 도입하면 SFT와 RL 모두에서 traditional offline effectiveness가 감소한다 확인.
    • 설계는 2×2 factorial이다. {SID vs Title 아이템 표현} × {No Reasoning vs Reasoning}을 Amazon 도메인 3개에서 공통 Qwen3-1.7B 백본으로 비교했다.
    • 예를 들어 Office Products와 Titles 조합에서는 R@10이 .1587에서 .1416으로 떨어졌다(−11%). 전체 도메인 범위로는 Titles가 −19% ~ 0%, SIDs가 −9% ~ 0% 저하했다.
    • Title은 SID보다 더 grounded하고 interpretable한 trace를 생성한다. 그런데도 extensive SID alignment는 trace quality만 올릴 뿐, recommendation effectiveness는 살리지 못한다.
    • Richer reward signal이 이 격차를 부분적으로 좁힌다 확인.
  • 왜 주목: Kuaishou PushDualGen은 SID와 skippable copy(CoT-lite)를 조합해 프로덕션 지표를 개선했다고 진술했다. 반면 Spotify Research의 통제 실험은 CoT가 recommendation effectiveness를 오히려 낮춘다는 반대 방향의 관찰을 내놓았다.
    • PushDualGen이 진술한 지표는 effective play rate +8.50%, 불만족률 −37.70%다.
    • 다만 두 자료는 조건이 다르다. Kuaishou는 push 지면에서 실제 카탈로그로 프로덕션 A/B를 돌렸고, Spotify는 offline에서 Amazon reviews와 작은(1.7B) 백본을 썼다. negative result가 어떤 조건에서 유효한지 파악하는 것이 목적이다.
    • Spotify가 "trace를 붙이면 지표가 떨어지고, alignment를 늘려도 안 된다"는 재현 가능한 반박점을 만들었다. 그래서 SID+CoT 라인의 다음 프로덕션 진술을 볼 때는 백본 크기, offline과 online의 차이, reward 설계라는 조건이 관건이 된다.
  • 근거: 확인 arXiv 2608.23154, 2026-08-24 제출. 저자 6명은 전원 Spotify Research 소속이다.
    • 이메일 도메인 @spotify.com으로 HTML 판에서 affiliation을 확인했다.
  • 상태: 관찰 중이다. llm-in-recsys.md에서 SID와 reasoning을 결합하는 갈래에 반증점으로 링크한다. 두 번째 회사에서 비슷한 반박이나 조건부 확인 진술이 나오면 topic에 별도 절(SID와 reasoning trace: production vs benchmark 논쟁)을 신설할 후보가 된다.

GateDiffInt (Xiaohongshu) — 유저 행동 시퀀스에 diffusion 노이즈 제거 + LLM 다중 인텐트 증류를 적용한 CVR 랭커

  • 무엇: 유저 행동 시퀀스의 noise-intent coupling 문제를 diffusion 기반 denoising과 LLM 다중 인텐트 증류라는 두 축으로 풀고, CVR을 예측한다.
    • noise-intent coupling은 노이즈가 참 인텐트를 희석하고, 구조화된 인텐트 prior가 없으면 denoising 타겟도 없다는 문제다.
    • Gate-Mediated Controllable Diffusion은 dual gating이 붙은 controllable forward diffusion 과정으로 행동 시퀀스를 enhance하고 denoise한다.
    • Multi-Intent LLM Distillation은 LLM teacher가 네 종류의 구조화된 인텐트를 lightweight student로 증류하게 한다. 네 종류는 long-term / short-term / latent / conversion이다.
    • 증류한 인텐트는 attention으로 융합해 CVR을 예측한다 확인.
  • 왜 주목: Xiaohongshu의 프로덕션 primary traffic에 배포해 hundreds of millions DAU를 서빙하며, "substantial GMV improvements"를 진술했다. 구체적인 uplift 숫자는 abstract에 공개하지 않았다.
    • OneModel이 유기·광고·상점의 랭커 통합 각도라면, 이쪽은 같은 회사의 행동 시퀀스 인코더와 CVR 헤드 각도로 독립되어 있다.
    • LLM을 서빙에 두지 않고 teacher로만 쓰는 접근이라, offline policy compiler인 MetaStrategy의 사촌 격이다.
  • 근거: 확인 arXiv 2608.18764, 2026-08-19 v1 / 2026-08-20 v2. 저자 이메일 도메인은 xiaohongshu.com이다(PDF 메타에서 확인했다).
  • 상태: 관찰 중이다. 두 번째 회사에서 diffusion을 시퀀스 denoising에 쓰는 프로덕션 랭커 진술이 나오면 topics/sequence-transformer-ranking.md에 절을 신설할 후보가 된다. v3 이후에 구체적인 uplift 숫자를 공개하는지 확인할 예정이다.
    • Xiaohongshu는 짧은 기간에 프로덕션 진술 두 편(OneModel과 GateDiffInt)을 냈다. 둘은 랭커 통합과 시퀀스 인코더라는 서로 다른 계층을 다룬다.

OneModel (Xiaohongshu) — 유기·광고·상점 3개 지면을 하나의 랭커로 통합

  • 무엇: Explore Feed의 유기 추천, Feed Advertising의 광고, Merchant Recommendation의 상점 추천을 하나의 랭커로 서빙한다 확인.
    • 이종 행동을 공유 이벤트 시퀀스로 매핑하고, action-oriented backbone으로 long-context user representation을 만든다.
    • Scenario-aware Information Modulation으로 cross-stream transfer와 stream-specific specialization의 균형을 잡는다.
    • 프로덕션 최적화 항목에는 stratified user representation, multi-objective training, feature decomposition이 있다. user feature prefetching, shared user-tower computation, graph-level inference optimization도 여기에 든다 확인.
  • 왜 주목: 하나의 랭커가 여러 비즈니스 스트림을 통합해서 서빙한다는 세 번째 프로덕션 진술이다. Xiaohongshu 프로덕션 A/B에서 세 지면의 지표를 함께 보고했다.
    • Explore Feed는 Time Spent +0.33%, Engagement +1.25%를 기록했다.
    • Feed Advertising은 value +3.43%, CTR +8.18%를 기록했다.
    • Merchant Recommendation은 DGMV +1.1867%, GPM +2.1585%를 기록했다.
    • 세 진술을 나란히 보면, Netflix FM은 서비스 다양성을 foundation에서 head로 잇는 방식이고 Meta GEM은 광고 domain 안의 지면 다양성을 다룬다. Xiaohongshu OneModel은 광고·유기·상점을 대등하게 통합한다.
    • Meta GEM은 광고 domain 중심인 반면 OneModel은 유기·광고·상점을 대등하게 통합한다는 점이 새 각도다.
  • 근거: 확인 arXiv 2608.18606, 2026-08-19 v2.
  • 상태: 관찰 중이다. Xiaohongshu는 아직 canon의 추적 서비스가 아니고, 서비스 정본(services/xiaohongshu.md)도 새로 만들지 않았다. 두 번째 회사(중국 밖 플랫폼)의 유사한 진술이 나오면 topics/multi-task-ranking.md나 새 unified-multi-scenario topic으로 승격할 후보가 된다.
    • "action-oriented backbone" 아키텍처의 세부와 cross-stream transfer 게이팅 메커니즘이 후속 논문이나 발표에서 나오는지가 지켜볼 포인트다.

Multi-Objective Ranking for Live-Streaming (Twitch) — delayed feedback window

  • 무엇: delayed window collection과 multi-model architecture로 fresh 신호와 delayed 신호를 각기 학습한 뒤 결합한다 확인.
    • 라이브 스트리밍은 즉시 신호와 지연 신호의 시간 스케일이 다르다는 문제를 안고 있다. 즉시 신호는 click, initial watch이고, 지연 신호는 session length, retention이다.
  • 왜 주목: Twitch(Amazon)의 mobile live feed에서 online A/B를 돌려 DAV와 ARPU가 유의미하게 개선됐다고 진술한다.
    • Netflix의 라이브 콜드스타트(RecSys 2025)와 인접하지만, 이쪽은 일반 라이브 피드의 다목적 랭킹이고 segment-aware targeting까지 더한다.
  • 근거: 확인 arXiv 2608.04455, 2026-08-05.
  • 상태: 관찰 중이다. Netflix의 라이브 콜드스타트와 교차 확인하는 자료로 유용하다. 정본 반영은 라이브 지면을 추적하는 서비스가 늘 때까지 보류한다.
