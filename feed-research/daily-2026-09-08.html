1PTDG — Huawei가 MMoE 대체용으로 conversion funnel을 아이템별로 rewiring한 MTL 랭커

자료 Personalized Task Dependency Graphs for Mitigating Signal Erosion in Multi-Task Recommendation — arXiv 2609.04862 v1, 2026-09-04 제출, CIKM 2026 accepted, 저자 11인 전원이 Huawei Technologies(Shanghai / Nanjing / Dongguan / Beijing) 소속임을 HTML 판 affiliation 표기와 @huawei.com 도메인으로 확인했다.

배경 산업 규모 추천 시스템의 랭킹 모델은 여러 목적을 함께 예측하는 multi-task learning(이하 MTL) 구조를 쓴다. Click → Add-to-Cart → Purchase처럼 shallow 상호작용에서 deep conversion으로 이어지는 conversion funnel을 하나의 모델이 계층적으로 학습하는 방식이다. 흔히 쓰이는 MMoE(Multi-gate Mixture-of-Experts)와 그 후속 계열은 이 funnel의 task 간 dependency 구조를 모델 구조로 고정한다: expert가 여러 task 사이에서 gating으로 정보를 공유하고, task-specific head가 각 목적을 예측한다.

이 논문이 지적하는 문제는 rigid inductive bias이다. 즉 트래픽 전반에 걸쳐 dependency 강도가 동일하다고 가정하는 것이다. 광고 아이템은 즉시 클릭 목적이 강하고 게임 아이템은 다운로드→활성 사용까지 이어지는 conversion 경로가 길다는 식으로, 아이템 특성에 따라 task 간 상관이 크게 다른데 정적 funnel은 이 heterogeneity를 반영하지 못한다. 그 결과 conversion funnel의 하위(sparse, deep-funnel objective)로 갈수록 signal erosion, 즉 hierarchical message passing이 누적되면서 신호가 attenuate되는 현상이 관찰된다.

정본에 이미 등장한 여러 스레드와의 관계를 짚어 두면 이해가 빠르다. 스케일링 법칙 스레드의 Meta HSTU/Wukong·Netflix Foundation Model·Alibaba TransRetrieval은 파라미터·시퀀스 축을 확장해서 랭킹 품질을 끌어올리는 접근이었다면, PTDG는 그와 다르게 MTL 아키텍처 안의 dependency 구조 자체를 학습 대상으로 삼는 각도다. Meta GEM 같은 광고 domain foundation model이 시퀀스 인코더를 공유해 다지면을 커버하는 방식이라면, PTDG는 단일 지면 안에서 task 간 신호 라우팅을 personalize한다.

새로 알게 된 것

  • Personalized Task Dependency Graphs(PTDG) — 아이템마다 다른 dependency graph를 low-rank approximation으로 생성해서 dependency pathway의 강도를 rewiring한다. 각 task를 node로, dependency를 edge로 두는 T×T dependency matrix I ∈ ℝ^(T×T)를 아이템 feature에서 예측하되, low-rank 분해로 파라미터를 압축한다 확인.

  • Hard causal masking — Click → Pay 같은 물리적 causal constraint(구매 없이 결제가 있을 수 없다)는 절대 뒤집히지 않도록 dependency graph에 hard mask를 씌운다. GCN-based propagation이 이 mask 아래에서 아이템별 적응적 shortcut을 만든다 확인.

  • Adaptive Progressive Masking(APM) — sparse task와 dense task의 shared parameter를 task sparsity에 따라 decouple해서 최적화를 안정화한다. sparse conversion task(예: 결제)는 dense task(예: 클릭)의 gradient에 압도되지 않도록 파라미터 경로가 분리된다 확인.

  • 오프라인 지표: KuaiRand1K 공개 데이터셋과 자체 industrial dataset에서 sparse conversion task AUC가 baseline 대비 최대 +1.45% 상승, dense task는 comparable 유지 확인.

  • 온라인 A/B: "a mainstream app distribution platform, serving over 100 million daily active users"에 배포. Huawei AppGallery로 추정한다 추정(논문이 회사명은 밝히지만 구체 지면은 익명화). 2주 A/B에서 10% base bucket + 10% experimental bucket + 80% original production model 유지. 일별 aggregate metric에 대한 two-sample t-test(p<0.05).

    "Results show that PTDG achieved statistically significant improvements on core business metrics, with a +1.2% lift in CVR and +1.9% lift in eCPM." — arXiv 2609.04862 v1 §4.5, 2026-09-04

    즉 CVR +1.2%, eCPM +1.9%, baseline은 현재 배포된 MMoE (§4.5 offline 비교 테이블 2와 동일 아키텍처).

  • 저자 소속 — Fuyuan Liu(공동 1저자)와 Tiandeng Wu(교신), Yaqun Fang, Wei Zhou, Zehao Zhou, Wenping Chen, Qishun Mei, Jiaxin Zhou, Heng Chang, Yi Cao, Jiandong Ding의 이메일이 모두 @huawei.com이다.

  • GenAI Usage Disclosure — 논문 말미에 "Generative AI tools assisted with language editing and code debugging. All experimental results were produced by author-written scripts and verified against saved artifacts."라고 명시했다. CIKM/ACM 규정에 맞춘 표기로 최근 산업 논문에서 흔해지고 있다.

정본 반영 radar.md 이번 달 신규 절 최상단에 PTDG 엔트리 추가. Huawei가 canon 추적 서비스가 아니므로 services 정본은 만들지 않는다. 두 번째 회사가 유사한 personalized task dependency 진술(GCN + causal masking + APM)을 내면 topics/multi-task-ranking.md에 절 신설 후보다.

의미 MTL의 아키텍처 축(dependency 구조 자체)을 학습 대상으로 삼는 접근은 정본에서 자주 다뤄 온 스케일링 축(파라미터·시퀀스·데이터)이나 loss 축(pxtr 노이즈 보정, 다목적 디코딩)과는 다른 자리다. 특히 Xiaohongshu GateDiffInt가 CVR head의 입력 시퀀스(diffusion + LLM intent 증류)를 재설계했다면 PTDG는 CVR head 사이의 dependency 구조를 재설계한 셈이다. CVR head 자체를 재정의하는 진술이 최근 두 회사에서 겹쳐 나온 것이 관찰되는 패턴이다. 다만 논문에는 CVR/eCPM lift만 있고 dense task(예: click) 개별 지표나 baseline MMoE의 구체 버전, industrial dataset의 sample 수는 공개하지 않았다. CIKM 2026 발표 슬라이드(2026-11-07~11, Rome)에서 이 세부가 나오는지 지켜본다.

arXiv cs.IR triage — 그 외 통과 후보

30건 파싱, 통과 1건(PTDG). 이 아래 세 건은 산업 프로덕션 진술이 있어서 검토했지만 정본 관심사(피드 랭킹/retrieval)와 도메인이 어긋나 스레드에 붙이지 않았다.

  • AlleCompanion(Allegro) — arXiv 2609.05063, RecSys 2026 OARS workshop. Allegro(폴란드 최대 e-commerce)의 complementary product recommendation 프로덕션 배포. Two-tower + Category Adapter로 co-purchase 노이즈를 필터링하고, ComCat(expert rule + human-in-the-loop + LLM reasoning + statistical mining)이 category-level 제약을 만든다. 유효 지표는 abstract 마지막에 잘려서 확인 불가. complementary recommendation은 basket-building 지면(장바구니 아래 carousel 등)의 카테고리 검색 문제라서 유기 피드·홈 지면 랭킹 스레드와 도메인이 다르다. 두 번째 회사(Amazon "Frequently bought together"의 프로덕션 진술 등)가 유사한 category-constrained two-tower 진술을 내면 그때 도메인 스레드를 새로 만드는 것을 검토한다.

  • IGPO(익명 commercial smart-assistant AI search) — arXiv 2609.04813, EMNLP 2026 Industry Track. 프로덕션 배포된 AI search pipeline에서 fine-tuning이나 RL 대신 inventory-grounded policy guideline을 학습하고 서빙 시 프롬프트에 주입하는 training-free 접근. 2026년 5월부터 배포, 14일 A/B에서 CTR +3.17%, audited bad cases −38.9% 확인. AI search(대화형 검색)에 초점이 맞춰져 있고 recsys 피드 랭킹과 도메인이 다르다. 다만 "카탈로그가 자주 갱신되는 조기 배포 단계에서 fine-tuning/RL이 잘 안 된다"는 문제 진술은 recsys 콜드스타트와 부분적으로 겹친다. 두 번째 회사에서 유사한 policy-guideline 진술이 나오면 검토 대상에 다시 올린다.

  • SAM-D2Q(Alibaba/AliExpress) — arXiv 2609.04961, CIKM 2026 Oral Full Paper. AliExpress 프로덕션 검색에 배포된 multimodal Doc2Query. Product title에 시각 신호를 붙여 pseudo-query를 생성하고 RL-based preference alignment로 search business objective(전환)에 정렬한다. e-commerce search의 document expansion 문제라서 피드 랭킹 스레드와 도메인이 다르다. Alibaba 검색 라인의 최신 진술로만 기록한다.

나머지 26건은 도메인 제한(의료·법률·야구·music finance QA·essay grading·programming tutor·multi-omic 시각화·web curation·phonetic encoding), agentic memory 벤치마크, RAG 개선(CAGE·tree-based framework), 학술 SID/multimodal recsys(EPIC diffusion 후속·MURAL uncertainty edge learning·Latent-Aligned VLM 등), embedding surgery, 프로그래밍 튜터 audit, 브랜드 추천 LLM audit이다. 프로덕션 배포·A/B 진술이 있는 후보는 위 4건이 전부다.

다음에 볼 것

  • PTDG의 industrial dataset 규모와 baseline MMoE 버전 — 2026-11 CIKM 발표 슬라이드에서 공개되는지 확인. 특히 Multi-gate Mixture-of-Experts의 어느 후속 변종을 baseline으로 삼았는지가 재현 가치를 판단하는 데 결정적이다.
  • PTDG가 Huawei의 다른 지면으로 확장되는지 — AppGallery 외에 Petal Ads, HiSuite, HUAWEI Music 등 다른 프로덕션 지면에서 유사한 personalized dependency 진술이 나오는지 감시. 회사 차원의 방향인지 팀별 실험선인지가 갈린다.
  • CVR head 재설계 라인의 세 번째 회사 — Xiaohongshu GateDiffInt(diffusion + LLM intent 증류)와 Huawei PTDG(dependency graph rewiring) 이후에 다른 회사(Kuaishou·Meta 광고·Google Discover·Netflix)가 CVR head 자체를 재설계한 프로덕션 진술을 내는지 확인. 두 개는 계열이 다르므로 세 번째 진술의 계열이 결정적이다.
