    Client 측 자료구조. TweetVisibility가 기존 reason: Option<FilteredReason> + safety_labels에 이어 action: Action 필드를 정식 멤버로 갖게 됐다. 즉 판정의 결과가 이제 세 개 튜플이다: (1) 결정론적 판정 Action(Allow / Interstitial / Avoid / Downrank / Drop / Tombstone / NotEvaluated), (2) 로깅·다운스트림 annotation FilteredReason, (3) 라벨 lookup 결과 SafetyLabelMap. 새 helper TweetVisibility::to_visibility_reason()이 action과 reason을 조합해 visibility_reason 필드 값을 유도한다.

    Strato 경로의 action 유도. StratoVfClient::get_result가 Strato에서 받은 FilteredReason으로부터 action_from_strato_reason을 태워 action을 계산한다. 규칙은 세 갈래다:

    fn action_from_strato_reason(reason: &Option<FilteredReason>) -> Action {
    match reason {
        None => Action::Allow,
        Some(FilteredReason::SafetyResult(safety_result)) => match safety_result.action {
            Action::NotEvaluated => Action::Allow,
            _ => safety_result.action.clone(),
        },
        Some(_) => Action::Drop(DropReason {}),
    }
}

    즉 Strato(레거시 VF 스택 [추정], 2026-08-30 4세대+8 canon 주의 목록에서 언급됨)는 SafetyResult가 있으면 그 안의 action을 그대로 쓰고, 그 밖의 non-SafetyResult reason(뮤트·차단·null-cast·exclusive 등)은 무조건 Drop으로 만다. Strato가 NotEvaluated로 리턴하면 client 층에서 Allow로 승격되는데, 이는 Strato가 판정 미실행을 fail-open으로 취급하겠다는 뜻이다.

    gRPC 경로의 action 유도. result_to_visibility가 gRPC 응답의 result.action을 그대로 Action으로 매핑한다. action 필드가 없으면 Action::NotEvaluated. 즉 새 gRPC 경로는 action을 서버가 결정해서 내려주는 것이 표준이다.

    Filter 층의 결정 함수 교체. VFFilter::filter가 이제 candidate.visibility_action의 함수다:

    pub(crate) fn should_drop_action(action: &Action) -> bool {
    match action {
        Action::Allow | Action::Interstitial | Action::Avoid | Action::Downrank => false,
        Action::Drop(_) | Action::Tombstone | Action::NotEvaluated => true,
    }
}

    이전 버전은 FilteredReason variants를 매칭해 SafetyResult면 action == Drop만 통과, 나머지 non-SafetyResult reason(뮤트·차단·null-cast·exclusive 등)은 무조건 drop이었다. 새 버전은 판정 축이 명시적이라 훨씬 읽기 좋다.

    ⚠ 주장 변경 (services/x.md line 392 "fail-closed" 진술). 이전 정본은 "VFFilter는 fail-closed다. SafetyResult 이외의 모든 FilteredReason 변종이 무조건 drop이다"였다. 새 판정 함수는 문법이 완전히 달라졌지만 결과는 대부분 동일하다: Strato 경로에서 non-SafetyResult reason은 client 층에서 이미 Drop으로 변환되고, NotEvaluated도 drop이다. 바뀐 것 하나: 이제 Interstitial이 명시적으로 통과된다(이전 코드도 통과시켰다). Downrank와 Avoid가 명시적으로 통과되는데, 이 두 action은 이전엔 SafetyResult.action으로 오면 drop되고 다른 경로로 오면 통과되는 애매한 상태였다. 즉 fail-closed 성격은 유지되지만 판정 세분화는 훨씬 명확해졌다.

    Ancillary drop 함수도 action 축으로. vf_candidate_hydrator.rs의 should_drop_ancillary도 조상·quoted·retweeted 포스트의 visibility.action을 봐서 drop 여부 결정. 이전 should_drop_reason(reason: &FilteredReason)은 제거되고 filter 층의 should_drop_action을 공유한다.

    URT 엔트리 구조. TimelineEntryContent::Item(TimelineItem { content: TimelineItemContent::Message(MessagePrompt { content: MessageContent::HeaderImagePrompt(HeaderImagePrompt { .. }), impression_callbacks }) }). 즉 URT의 Message 타입 아이템으로 실린다 — 트윗이 아니라 "메시지 프롬프트"라는 별도 타입. MessageContent::HeaderImagePrompt가 이 광고 전용 컨텐츠 variant다.

    HeaderImagePrompt content 필드:

    • header_image: MessageImage — image_variants(URL·width·height) 담긴 이미지
    • header_text: String + header_rich_text: RichText — 두 형태로 함께 담김(plain text와 entity 없는 RichText)

    • primary_button_action: MessageTextAction — 필수
    • secondary_button_action: Option<MessageTextAction> — secondary_button_text가 비어 있지 않을 때만

    MessageTextAction 구조. text: String + action: MessageAction { dismiss_on_click, url, client_event_info, on_click_callbacks, on_click_reactive_trigger }. 각 버튼이 자체 ClientEventInfo(action = "primary_cta" 또는 "secondary_cta")와 자체 callback 리스트를 가진다.
