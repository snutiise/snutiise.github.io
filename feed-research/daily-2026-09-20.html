    batch: Any, merged_embeddings: jax.Array, post_table: jax.Array, dataset_types: jax.Array
):
    recsys_embeddings = _recsys_embeddings_from_merged(
        merged_embeddings, embedding_slices, packed_geometry
    )
    model = model_config.make(sharding_context=make_legacy_sharding_context(mesh))
    results = model.forward(
        batch, recsys_embeddings, post_table, dataset_types,
        retrieval.large_k, target_values,
        dataset_ranges=None,
        use_async_topk=retrieval.use_async_topk,
        use_radix_select_topk=retrieval.use_radix_select_topk,

    flat: list[jax.Array] = []
    for indices, scores in results:

    각 target dataset type마다 두 개의 출력(indices_<name>, scores_<name>)이 나온다. 이 이름 규칙은 RetrievalExport.output_names property에 정의돼 있다.

    _make_export_config에도 two_tower: bool = False와 mesh_devices: int = 1 두 인자가 추가됐다. two-tower일 때에는 서빙 시퀀스 길이 계산 규칙이 다르다:

    def _user_tower_sequence_len(
    *, training_seq_len, training_history_seq_len, num_user_prefix_tokens, history_seq_len,
) -> int:
    prefix_tokens = training_seq_len - training_history_seq_len
    if prefix_tokens != num_user_prefix_tokens:
        raise ValueError(
            f"cannot derive the serving user-tower sequence_len: sequence_len "
            f"{training_seq_len} - history_seq_len {training_history_seq_len} = {prefix_tokens} "
            f"prefix tokens, but the model reserves num_user_prefix_tokens="
            f"{num_user_prefix_tokens}. The user tower is built as prefix + history; if "
            "history_seq_len was overridden for serving, also override "
            "model_config.user_tower_config.model_config.sequence_len to "
            f"{num_user_prefix_tokens + history_seq_len} (prefix + serving history), as the "
            "jax slot does — otherwise the attention kernel cannot be sized for serving"
        )
    return prefix_tokens + history_seq_len

    랭킹 export에서는 서빙 시퀀스가 prefix + history + candidate이지만 retrieval export에서는 prefix + history만이다(candidate 축이 없다 — 유저 임베딩만 낸다). _make_export_config의 overrides도 model_config.model_config.sequence_len 대신 model_config.user_tower_config.model_config.sequence_len을 쓴다.

    세 번째로 새로 등장한 것은 분산 export다. Retrieval bundle은 mesh 위에서 export되어 여러 장치에 분산될 수 있다:

    if not two_tower and mesh_devices != 1:
    raise NotImplementedError(
        "ranking programs are single-device (one executable per GPU); "
        f"mesh_devices={mesh_devices} is only for retrieval bundles"
    )

    이유는 명시적이다. 랭킹은 GPU마다 executable 하나로 서빙되지만, retrieval은 post table을 여러 장치에 나눠 담아야 하므로 SPMD로 export한다. _export_mesh가 export_cfg.parallel_config.mesh_shape()을 확인해 device를 만들고, _retrieval_shardings가 batch/params/post_table/dataset_types에 대한 NamedSharding을 지정한다. 임베딩 rows는 data axis로 분산 파티션되고 params는 replicated된다.

    몇 가지 제약이 명시적으로 걸린다:

    • enable_int8_post_table·enable_bloom_filter·enable_topic_filter는 지원 안 됨(native runtime만 지원, StableHLO export는 bf16 post table + no-per-post-filter).
    • enable_dataset_slice_topk=True는 무시되고 경고가 뜬다(export 프로그램은 항상 mask-then-topk-over-whole-table 경로만 컴파일).
    • using_seqpack + two_tower 조합 금지 — packing이 SPMD 모델과 맞지 않는다.
    • DEBUG_ALLOW_RANDOM_INIT=1이면 export 자체를 거부(마스크 없이 export되면 유효하지 않은 프로그램이 나가므로).

    build_bundle이 이제 두 종류 모델을 모두 받는다:

Retrieval-side를 SPMD로 여러 장치에 분산해 export할 수 있는 인프라까지 함께 붙었기 때문에, Phoenix retrieval의 서빙 스택이 랭킹과 동일한 번들 규격으로 통일되는 것이 방향이다.
