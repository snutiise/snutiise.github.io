배경 X의 공개 소스 4세대 이후 매일 이어지는 후속 커밋 중 스물두 번째다. 이번 커밋은 4세대+21(2d4a03c)에서 wire만 열렸던 광고 구매액 continuous head(ADS_WEB_CT_PURCHASE_VALUE, PurchaseValueBaseline 요청 필드)를 학습 loss까지 잇는 것이 가장 눈에 띄는 변경이다. 그 옆으로 continuous loss type의 종류에 binary가 새로 등장해서 특정 continuous head를 threshold 기준으로 이진화한 뒤 sigmoid + BCE로 학습하는 옵션이 열렸고, 이번 커밋 안에서 default 학습 config가 click_dwell_time 헤드를 threshold=10초의 이진 분류로 학습하도록 flip했다. 세 가지 옵트인 배선(purchase value + binary loss + click_dwell feature)이 함께 들어왔다.

부수적으로 user_gender 카테고리컬 인덱스 매핑이 소리없이 바뀌었고(하드코딩 Male=2·Female=1 → proto enum 그대로), H100 학습 attn 커널 override가 GB300과 동일한 CUTe DSL 계열로 마지막 통일 flip을 마쳤으며, VMRanker gRPC 클라이언트에 DSCP=InferenceCritical 태그가 붙었다. 광고 브랜드 안전 V2 게이트(EnableAdsBrandSafetyVerdictV2) 미러가 true → false로 롤백됐고, grox 리플라이 스팸 분류기는 스레드 팔로워 크기 150k를 기준으로 전용 파인튜닝 모델(oai-gemma4-26b-reply-spam)로 이원 라우팅되기 시작하면서 task 자격 임계도 100k → 180k로 상향됐다.

VF 서브레포에서는 6개 enum(RequestOutcome·SourceOutcome·CacheTier·CacheResult·ManhattanResult·BatchStage·ConnEvent·HydratorOutcome·SafetyLevel·LabelSource·FallbackReason·FailureKind)이 손으로 짠 as_str() 구현에서 strum::IntoStaticStr 매크로로 통일됐다. 관측 라벨 문자열은 snake_case로 그대로 유지되므로 순수 리팩터이고 -180줄. 이 절에서는 이 리팩터의 상세는 다루지 않는다(관측 지표에 관측 가능한 변화 없음).

의미 세 방향이 함께 움직였다.

첫째, 광고 랭킹의 학습 target이 옥션 목적 함수에 더 가까이 왔다. 지금까지의 광고 head들이 대부분 클릭·컨버전 확률을 예측했다면, ADS_WEB_CT_PURCHASE_VALUE는 실제 금액의 회귀 target이면서 광고주의 28일 평균 대비 상대 ratio로 표현된다. Value-optimizing 옥션(Meta VBB, Google tCPA/tROAS)이 동일한 방향의 학습 target을 쓴다. 활성 여부는 purchase_value_loss_weight가 0으로 default라서 다음 커밋의 mparams 등장 시점 관측 필요.

둘째, click_dwell_time 헤드의 학습 시맨틱이 회귀 → 이진 분류로 바뀌었다. Netflix N-tower·YouTube dwell 계열이 "dwell 여부(binary)"와 "dwell time(regression)"을 분리 head로 두는 것과 대비된다 — X는 하나의 head에 이진 분류로 통일한 셈이다. 학습 target이 "정확한 dwell 초 예측"에서 "10초 이상 dwell 확률"로 이동. 다만 서빙 side와의 대칭성이 흔들린다: _rescale_sigmoid_heads_for_inference가 binary 헤드에는 원단위 복원을 명시적으로 skip하기 때문에 이 헤드는 서빙에서 확률 [0,1] 그대로 남는다. ContClickDwellTimeWeight가 미러상 무변화이므로 랭킹 스코어러에서 이 헤드의 실효 기여는 이전(초 단위 예측을 곱하던 때) 대비 최소 60배 축소된다. 배포에 맞춰 가중치가 조정됐다는 근거는 이번 커밋에서 확인되지 않는다.

셋째, user_gender 카테고리컬 인덱스가 소리없이 재매핑됐다. proto Gender enum이 typical 관행(UNKNOWN=0, MALE=1, FEMALE=2)이라면 Male/Female의 임베딩 테이블 인덱스가 이전(Male=2, Female=1)과 swap된다. 재학습 전에는 서빙 시 성별 시그널의 부호가 뒤바뀐다. 또한 이전에 0으로 뭉쳐지던 non-binary 값이 이제 proto 정의대로 별도 인덱스를 갖는다. 이 마이그레이션과 짝지어진 학습 리셋이 없다는 점이 관측 대상. proto Gender 정의를 다음 커밋에서 확인 필요.

XAUC 메트릭이 붙은 이유는 dwell·purchase-value 같은 continuous 헤드에서 magnitude 정확도보다 순서 concordance가 옥션 성능과 직결되기 때문이다(광고 value optimization에서 "매출 예측 절대값의 정확도"보다 "매출 큰 순서를 맞히는 능력"이 옥션 결정에 더 큰 영향을 미친다). Stride 샘플링은 랜덤이 아니라 시퀀스 패킹 순서에 종속된 편향이 있는데, 이는 학습 스텝당 2048² 이상의 pair 계산은 하지 않겠다는 예산 제한이 우선한 것으로 읽힌다.

VMRanker DSCP=InferenceCritical는 4세대+8에서 이 경로가 얇게 정리됐던 것과 짝: VMRanker가 홈 랭킹의 tail latency에 크리티컬하다는 배포 결정이 서 있다는 방증. EnableAdsBrandSafetyVerdictV2 롤백은 4세대+2에서 신설된 후 4세대+7에서 HighRisk 승격까지 갔던 확장 방향이 실측 지표에서 문제를 냈거나 재검토 단계에 있음을 시사한다.

grox 리플라이 스팸의 이원 모델 라우팅은 4세대+21의 coordinated_spam 임계 완화(10k → 30k)와 짝으로 읽으면 높은 팔로워 대역과 낮은 팔로워 대역을 각기 다른 모델·기준으로 처리한다는 방향으로 전체 스팸 파이프라인이 세분화되는 중. 자기 인용(self-QT) 마커는 리치 확대 목적의 자기-부스팅 패턴을 grox 판정기가 시맨틱적으로 인식하도록 프롬프트 층에서 힌트를 준다.

2Meta Facebook Marketplace의 retrieval-stage 다양성 캡핑(PCap)

자료 PCap: Personalized Retrieval-Stage Diversity Capping in Facebook Marketplace — arXiv 2609.16452, 2026-09-15 제출, 저자 11인 전원 Meta(Menlo Park·Boston 소속) @meta.com HTML 판에서 확인. 논문.

배경 후보 생성(retrieval) 단계에서 다양성(diversity)을 확보하는 방식은 지금까지 저장소 코퍼스에서 크게 두 축이 있었다. 랭킹/재순위에서 MMR·DPP 같은 pairwise similarity penalty로 상위 후보를 재배열하는 축(X의 VMRanker DPP·유튜브의 rerank stage)과, 후보 생성기 개수 자체를 늘려 소스 다양성으로 커버리지를 확보하는 축(Netflix multi-source retrieval)이다. PCap은 그 사이에 새 축을 넣는다: retrieval scanning 단계에서 카테고리별 상한(cap)을 걸되, 상한 자체를 유저별로 개인화한다는 접근이다.

논문이 겨냥하는 문제는 waterfall 그리드형 marketplace 지면의 특성이다. Multi-source retrieval에서 각 source가 자기 objective로 카테고리 편향을 갖고 있어서(예: 어떤 source가 electronics를 과대표), 상위 후보 pool이 카테고리 분포에서 편향된다. 종국적으로 유저 참여 카테고리도 좁아지고 유저의 다양성 갈망도가 다양한데도 모든 유저에게 같은 다양성 정책을 적용하면 "좁게 클릭하는 유저"에게는 과도한 다양성이, "넓게 클릭하는 유저"에게는 부족한 다양성이 걸릴 수 있다.

새로 알게 된 것

  • Shannon entropy로 유저 다양성 선호 프록시 계산 확인 — $S(u) = -\sum_{c \in C} p(c|u) \log p(c|u)$, p(c|u)는 최근 클릭 기반 유저 u의 카테고리 c 확률. 카테고리 그룹핑은 **Facebook Product Taxonomy (FPT)**의 수백 개 카테고리를 쓴다. 정규화 후 유저를 6개 다양성 버킷으로 정렬(bucket-1이 가장 좁게 클릭, bucket-6이 가장 넓게 클릭). arXiv 2609.16452 HTML.
  • Multi-source retrieval의 shard-scanning과 aggregation 두 단계에서 카테고리별 상한을 걸어 캡핑 확인 — 상한은 retrieval source fetch count × 튜닝된 multiplier fk × 유저 버킷의 다양성 multiplier mu로 산출된다. Source 세부 이름은 공개 안 됐지만 여러 인덱서 shard와 aggregation stage 존재는 명시. arXiv 2609.16452 HTML.
  • 파라미터 탐색 방법 Parameter Tuning Sequence (PTS) 신설 확인 — sequential range-narrowing A/B 절차로, control arm을 고정한 상태에서 후보 arm을 며칠씩 트래픽 소량에 노출해 온라인 grid search 대체. 여섯 개 버킷 × 다중 파라미터의 고차원 조합 공간을 탐색하는 데 쓴다. arXiv 2609.16452 HTML.
  • Marketplace Feed 프로덕션 A/B 결과 확인 — Phase 1 (uniform cap vs no cap): VPV +0.3088% (p<0.01), PF Latency +8.6 ms. Phase 2 (PCap vs uniform cap): VPV +0.2243%, PDP Clicks +0.2250%, Marketplace Sessions +0.1708% (모두 p<0.01), PF Latency +0.8 ms. 다양성 점수 변화(Pagination Feed): bucket-1 −1.0537%, bucket-6 +0.2469%. Metric 정의: VPV=Viewport Views, PDP=Product Detail Page Clicks, Marketplace Sessions=Marketplace 진입 세션. arXiv 2609.16452 HTML.

"We propose a personalized capping framework (PCap) to improve the diversity in Facebook Marketplace by introducing user-level diversity constraints at the retrieval stage. PCap models individual diversity preferences using Shannon entropy-based scoring, segments users into diversity buckets, and applies personalized category caps during multi-source candidate retrieval." — PCap: Personalized Retrieval-Stage Diversity Capping in Facebook Marketplace, 2026-09-15.

정본 반영 radar.md ## 이번 달 신규 절 최상단에 PCap 엔트리 추가. Facebook Marketplace가 저장소의 정본 서비스가 아니어서(현재 정본은 x·facebook·instagram·threads·netflix로 Marketplace는 없음) 레이더에서 다룬다. 다음 관측이 붙으면 topics/feed-diversity.md 승격 후보.

의미 저장소가 이미 추적하는 topics/feed-diversity.md에 새 각도가 들어온다. 기존 다양성 논의는 MMR·DPP 같은 pairwise 접근(랭킹/재순위)과 multi-source retrieval 대응이 주였다. PCap은 retrieval scanning에 카테고리 상한을 걸되 상한 자체를 유저별로 다르게 세팅하는 방식으로, 두 축의 사이에 있는 새 각도다.

첫째, 지연 팽창이 낮다. Phase 2에서 latency +0.8 ms는 랭킹/재순위 단계 다양성 처리(DPP는 매트릭스 결정식 계산으로 P99에 백 ms 단위로 튈 수 있음)와 대비된다. Scanning 단계에서 counter를 유지하며 카테고리별 상한만 강제하는 접근은 O(n)이라 지연 상한이 뚜렷하다.

둘째, carrier metric까지 함께 올라간다는 점이 크다. Marketplace Sessions +0.17%는 유저가 이 지면에 다시 돌아오는 빈도의 상승이므로, 다양성 개선이 참여의 정체가 아니라 참여의 확장으로 이어졌음을 시사한다. 다양성 처리가 "engagement를 깎는 trade-off"라는 통상적 인식과 대비된다.

셋째, 버킷별 다양성 점수의 반대 방향 변화(bucket-1 −1.05%, bucket-6 +0.25%)가 개인화의 근거로 작동한다. "좁게 클릭하는 유저는 좁게, 넓게 클릭하는 유저는 넓게"의 시맨틱이 다양성 점수 자체에서 관측되고 있다. 다만 이 방향이 실제 참여에 어떻게 매핑되는지는 논문에서 버킷별 참여 지표를 상세히 나누지 않았기 때문에 후속 관측 대상.

넷째, PTS라는 튜닝 방법 자체가 재사용 가능한 자산이다. Sequential range-narrowing으로 range를 좁혀 가는 온라인 grid search는 랭킹 하이퍼파라미터(예: 헤드 가중치)나 다른 retrieval 튜닝에 이식 가능하다. 다음 관측 대상: Meta의 다른 지면(Facebook Feed, Instagram, Reels)에 같은 스택이 확장됐다는 진술이 나오는지, 두 번째 회사가 retrieval-stage cap의 개인화 접근을 채택하는지.

Facebook Marketplace가 이 저장소의 정본 서비스가 아니어서 승격 대상은 아니지만, topics/feed-diversity.md에 다양성 개인화의 새 각도로 붙는 관찰이다.
