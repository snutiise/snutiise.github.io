14세대+41 — 페이지 단위 RL 재순위기, 가중치 2개 1.1배, 선거 필터 축소 — X

자료 xai-org/x-algorithm@17c96bf — xAI 공개 저장소, 2026-10-14 03:41 UTC 커밋, 코드. 파일 53개, diff 기준 약 +7,745/−6,964줄이다.

배경 X의 For You 피드는 Phoenix 모델이 후보마다 행동 확률(좋아요, 답글, 신고 등)을 예측하고, 그 확률에 가중치를 곱해 더한 점수로 정렬한 뒤, VM-Ranker라는 별도 서비스에서 DPP(determinantal point process: 비슷한 아이템이 함께 뽑히면 점수가 깎이도록 집합 단위로 고르는 다양성 기법)로 순서를 다시 조정한다. 이 방식은 아이템마다 점수를 따로 매기므로 "이 아이템을 몇 번째에 놓으면 유저가 페이지를 끝까지 볼까"라는 질문을 직접 다루지 못한다. 슬레이트(slate: 한 번에 보여 주는 아이템 묶음) 단위 강화학습은 이 질문을 다루는 방법이다. 정책(actor)이 슬롯을 하나씩 채우고, 가치 함수(critic)가 "이 시점부터 남은 슬롯에서 받을 보상의 합"을 예측해 정책을 개선한다. 이번 커밋은 X가 이 구조를 실제로 학습하고 있다는 코드다.

새로 알게 된 것 — A. immersive 지면용 페이지 단위 RL 재순위기 page_rl

  • 학습 config immersive_page_rl이 신설됐다 확인 — configs/xrecsys.py:388-417, 477-483. 홈 랭커 base에 page_rl=PageRlConfig(enabled=True)를 켠 것이고, 학습 데이터용 Kafka 토픽도 user_action_sequence_immersive_page_rl로 따로 생겼다.

  • 흐름은 다음과 같다 확인 — page_rl.py:340-391, page_decoder.py:22-34.

    1. Phoenix 헤드 확률로 가중합 점수(behavior score)를 만든다.
    2. 상위 최대 48개를 후보 풀로 자른다(max_steps=48).
    3. 페이지 디코더가 첫 슬롯부터 하나씩 고른다. 서빙에서는 12개 슬롯을 채운다(serve_steps=12).

  • 디코더가 각 단계에서 후보에 매기는 logit은 세 항의 합이다 확인 — page_decoder.py:85-119, 233-247.

    • 지금까지 고른 아이템을 attention으로 요약한 상태와 후보 임베딩의 내적
    • 풀 안에서 표준화한 behavior score(가중 1.0)
    • 이미 고른 아이템과 작성자가 같은지, SID(semantic ID: 아이템을 계층 코드로 표현한 것) 앞자리가 몇 단계 겹치는지에 음수 가중을 곱한 페널티

  • 보상은 슬롯별 체류 시간을 기준으로 한다 확인 — page_rl.py:51-59, 100-158.

    • 3초 이상 본 슬롯에 0.1 × min(체류초, 300) × (1 + min(참여 수, 3))을 준다.
    • 관심 없음·신고·차단·뮤트·덜 보기 중 하나라도 있으면 그 슬롯의 보상은 0이다.
    • 페이지의 모든 슬롯이 노출되고 마지막 슬롯에서 영상 품질 시청(VQV)이 있으면 완주 보너스 1.0을 더한다.
    • 할인율 γ=0.8로 뒤쪽 슬롯 보상을 앞쪽으로 끌어와 return을 만든다.

    — page_rl.py:121-122 (코드), 2026-10-14

  • critic은 두 개를 두고 작은 값을 쓴다(twin critic, 과대평가를 막는 관행). 타깃은 TD(λ=0.9)이고, 탐색 트래픽에서 나온 페이지의 손실에 가중 9.0을 준다. 다음 슬롯까지 넘겼는지를 맞히는 continuation 헤드도 함께 학습한다 확인 — page_critic.py:18-25, 121-139, 174-193.

  • actor 손실은 네 항이다 확인 — page_decoder.py:37-48, 495-592, page_rl.py:80-88.

    • critic Q값 기반 advantage 항. behavior score 최고값과 0.6 이내인 후보만 대상으로 삼는다.
    • 기존 정렬 정책(behavior score의 softmax, τ=0.2)에서 너무 멀어지지 않게 하는 KL 항. 목표 KL 0.35를 두고 계수 β를 0.1~3.0 사이에서 자동 조정한다.
    • 같은 작성자·유사 SID 연속 배치 페널티(가중 0.5).
    • 로그된 실제 노출 순서를 따라 하는 behavior cloning 손실(가중 0.25).

  • 서빙 디코딩은 temperature가 0이면 beam 4개를 만들고 critic 가치 합이 가장 큰 beam을 고른다. temperature가 0보다 크면 Gumbel 샘플링으로 탐색한다 확인 — page_decoder.py:427-477.

  • behavior score 계산에는 홈믹서 미러와 다른 별도 가중치가 config 기본값으로 들어 있다 확인 — page_rl.py:62-77. share 40.0, not_interested −500, report −1000처럼 홈믹서 미러(share 2.0, not_interested −52.272, report −234)와 크기가 크게 다르다. 미러 주석이 없으므로 서빙값인지는 알 수 없다 추정.

  • 서빙 러너에 serve_page_decoder: bool = False가 추가됐고, home-mixer에서 디코더 출력을 쓰는 코드는 없다 확인 — inference/model_runner.py:3984. 다만 학습 데이터에 이미 rl_rerank_prob·rl_decode_prob 같은 로그 확률 필드가 있으므로, 확률적 재순위가 일부 트래픽에서 이미 돌며 로그를 남기고 있다고 본다 추정 — off-policy 학습용 로그 확률은 실제로 서빙된 정책에서만 생긴다.

의미

  • 이전 이해는 "X의 재순위는 점수순 정렬 + 작성자 감쇠 + DPP"였다. 이번 공개로 슬레이트를 RL로 생성하고 다양성 페널티의 크기를 체류 보상과 함께 학습하는 다음 단계가 학습 코드로 존재한다는 것이 확인됐다 확인. 서빙 스위치가 기본 off라서 기존 이해를 뒤집지는 않는다.
  • 보상이 참여 확률이 아니라 체류 시간에 참여 배수를 곱한 값이다 확인. CREAD 체류 손실(10-08), retrieval ld 헤드(10-13)에 이어 체류를 주 목적에 두는 흐름이 재순위 단계까지 이어졌다 추정.
  • 4세대+4(08-19)에 proto로만 나왔던 RewardOutputs·rewardRerankSlotProb의 쓰임새가 두 달 만에 학습 코드로 드러났다 추정 — 이름과 로그 필드가 맞물린다는 정황이 근거다.

2WeGR — WeChat 검색의 SID 생성형 retrieval — 레이더

자료 WeGR: Unified Generative Retrieval for Industrial Search Systems in WeChat — arXiv, 2026-10-12 v1, 논문.

배경 생성형 retrieval은 아이템을 SID 토큰 열로 표현하고 모델이 그 토큰을 순서대로 생성해 후보를 꺼내는 방식이다. 이 저장소는 레이더의 "생성형 retrieval / semantic ID" 스레드에서 이 계열의 프로덕션 진술을 모으고 있고, X도 10-02에 SID retrieval 서비스를 공개했다.

새로 알게 된 것

  • 협업 신호를 넣고 codebook collapse(일부 코드만 쓰이는 현상)를 막는 SID 토크나이저 CoCo-VAE와, SID 정확 일치에서만 보상이 나와 희소해지는 문제를 SID 계층별로 보상 범위를 넓혀 푸는 RL 방법 DHPO를 묶었다 확인(초록).
  • 2개월 온라인 A/B에서 WeChat 전자상거래 검색의 주문 +2.539%, CTR +1.508%, 전환율 +1.381%, CPU·GPU 사용량 −25.5%·−26.1%이고, 여러 검색 지면에 배포됐다고 초록이 밝힌다 확인(초록).

정본 반영 정본 반영 없음. radar.md의 생성형 retrieval / semantic ID 스레드에 추가 근거로 한 줄 넣었다.

의미 검색 지면이라 피드와 거리가 있다. 같은 회사(WeChat/Tencent)의 Tlow에 이은 두 번째 SID 프로덕션 진술이고, "SID 계층별 부분 보상"이라는 RL 설계 축을 추가한다. 본문은 읽지 않았다.
