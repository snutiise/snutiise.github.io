1페이지를 강화학습으로 채우는 재순위기의 학습 코드가 공개됐다 — X

자료 xai-org/x-algorithm@17c96bf — xAI 공개 저장소, 2026-10-14 03:41 UTC 커밋, 코드. 이 노트들은 4세대 공개 뒤의 X 커밋에 차례로 번호를 붙여 부르며, 이 커밋은 4세대+41이다. 바뀐 파일은 53개이고, diff 기준 약 +7,745/−6,964줄이다.

배경 X의 For You 피드에서는 랭킹 모델인 Phoenix가 후보마다 좋아요, 답글, 신고 같은 행동의 확률을 예측한다. 그 확률에 가중치를 곱해 더한 점수로 후보를 정렬한다. 그다음 VM-Ranker라는 별도 서비스가 DPP로 순서를 다시 조정한다. DPP(determinantal point process)는 비슷한 아이템이 함께 뽑히면 점수가 깎이도록 집합 단위로 고르는 다양성 기법이다. 이 방식은 아이템마다 점수를 따로 매기므로 "이 아이템을 몇 번째에 놓으면 유저가 페이지를 끝까지 볼까"라는 질문을 직접 다루지 못한다.

슬레이트(slate: 한 번에 보여 주는 아이템 묶음) 단위 강화학습은 이 질문을 다루는 방법이다. 정책(actor)은 슬롯을 하나씩 채운다. 가치 함수(critic)는 "이 시점부터 남은 슬롯에서 받을 보상의 합"을 예측해 정책을 개선한다. 이번 커밋은 X가 이 구조를 실제로 학습하고 있다는 것을 보여 주는 코드다.

새로 알게 된 것A. 재순위기는 체류 시간 보상으로 학습하는 페이지 디코더와 twin critic으로 이뤄진다

  • 몰입형 지면용 페이지 단위 RL 학습 config가 새로 생겼다 확인 — configs/xrecsys.py:388-417, 477-483.

    • 코드에서 이 재순위기의 이름은 page_rl이다.
    • config 이름은 immersive_page_rl이다. 홈 랭커 base에 page_rl=PageRlConfig(enabled=True)를 켠 것이다.
    • 학습 데이터용 Kafka 토픽도 user_action_sequence_immersive_page_rl로 따로 생겼다.

  • 재순위는 세 단계로 진행된다 확인 — page_rl.py:340-391, page_decoder.py:22-34.

    1. Phoenix 헤드 확률로 가중합 점수(behavior score)를 만든다.
    2. 상위 최대 48개를 후보 풀로 자른다(max_steps=48).
    3. 페이지 디코더가 첫 슬롯부터 하나씩 고른다(autoregressive 디코딩). 서빙에서는 12개 슬롯을 채운다(serve_steps=12).

  • 디코더가 각 단계에서 후보에 매기는 logit은 세 항의 합이다 확인 — page_decoder.py:85-119, 233-247.

    • 지금까지 고른 아이템을 attention으로 요약한 상태와 후보 임베딩의 내적
    • 풀 안에서 표준화한 behavior score(가중 1.0)
    • 이미 고른 아이템과 작성자가 같은지, SID(semantic ID: 아이템을 계층 코드로 표현한 것) 앞자리가 몇 단계 겹치는지에 음수 가중을 곱한 페널티

  • 보상은 슬롯별 체류 시간을 기준으로 한다 확인 — page_rl.py:51-59, 100-158.

    • 3초 이상 본 슬롯에 0.1 × min(체류초, 300) × (1 + min(참여 수, 3))을 준다.
    • 관심 없음·신고·차단·뮤트·덜 보기 중 하나라도 있으면 그 슬롯의 보상은 0이다.
    • 페이지의 모든 슬롯이 노출되고 마지막 슬롯에서 영상 품질 시청(VQV: video quality view)이 있으면 완주 보너스 1.0을 더한다.
    • 할인율 γ=0.8로 뒤쪽 슬롯 보상을 앞쪽으로 끌어와 return을 만든다.

    — page_rl.py:121-122 (코드), 2026-10-14

  • critic은 두 개를 두고 둘 중 작은 값을 쓴다 확인 — page_critic.py:18-25, 121-139, 174-193.

    • twin critic이라 부르는 구성으로, 과대평가를 막는 관행이다.
    • 타깃은 TD(λ=0.9)이고, 탐색 트래픽에서 나온 페이지의 손실에 가중 9.0을 준다.
    • 다음 슬롯까지 넘겼는지를 맞히는 continuation 헤드도 함께 학습한다.

  • actor 손실은 네 항이다 확인 — page_decoder.py:37-48, 495-592, page_rl.py:80-88.

    • critic Q값에 기반한 advantage 항이다. behavior score 최고값과 0.6 이내인 후보만 대상으로 삼는다.
    • 기존 정렬 정책에서 너무 멀어지지 않게 하는 KL 항이다. 기존 정렬 정책은 behavior score의 softmax(τ=0.2)다. 목표 KL 0.35를 두고 계수 β를 0.1~3.0 사이에서 자동 조정한다.
    • 같은 작성자나 유사 SID를 연속으로 배치할 때 주는 페널티 항이다(가중 0.5).
    • 로그된 실제 노출 순서를 따라 하는 behavior cloning 손실이다(가중 0.25).

  • 서빙 디코딩은 temperature 값에 따라 두 방식으로 나뉜다 확인 — page_decoder.py:427-477.

    • temperature가 0이면 beam 4개를 만들고, critic 가치 합이 가장 큰 beam을 고른다.
    • temperature가 0보다 크면 Gumbel 샘플링으로 탐색한다.

  • behavior score 계산에는 홈믹서 미러와 다른 가중치가 config 기본값으로 따로 들어 있다 확인 — page_rl.py:62-77.

    • 홈믹서 미러는 For You 피드를 조립하는 home-mixer 서비스의 프로덕션 기본값을 크론으로 옮겨 적은 파일이다.
    • share 40.0, not_interested −500, report −1000처럼 홈믹서 미러(share 2.0, not_interested −52.272, report −234)와 크기가 크게 다르다.
    • 미러 주석이 없으므로 서빙값인지는 알 수 없다 추정.

  • 디코더를 서빙에 쓰는 스위치는 기본 off이고, home-mixer에서 디코더 출력을 쓰는 코드는 없다 확인 — inference/model_runner.py:3984.

    • 서빙 러너에 추가된 스위치는 serve_page_decoder: bool = False다.

  • 다만 학습 데이터에 이미 rl_rerank_prob·rl_decode_prob 같은 로그 확률 필드가 있으므로, 확률적 재순위가 일부 트래픽에서 이미 돌며 로그를 남기고 있다고 본다 추정.

    • off-policy 학습(서빙된 정책의 로그로 다른 정책을 학습하는 방식)에 쓰는 로그 확률은 실제로 서빙된 정책에서만 생긴다.

2WeChat이 SID 생성형 retrieval을 여러 검색 지면에 배포했다고 밝혔다 — 레이더

자료 WeGR: Unified Generative Retrieval for Industrial Search Systems in WeChat — arXiv, 2026-10-12 v1, 논문.

배경 생성형 retrieval은 아이템을 SID 토큰 열로 표현하고, 모델이 그 토큰을 순서대로 생성해 후보를 꺼내는 방식이다. 이 저장소는 레이더의 "생성형 retrieval / semantic ID" 스레드에서 이 계열의 프로덕션 진술을 모으고 있다. X도 10-02에 SID retrieval 서비스를 공개했다. 이번 논문은 WeChat의 산업용 검색 시스템에 쓰는 생성형 retrieval WeGR을 다룬다.

새로 알게 된 것

  • WeGR은 SID 토크나이저와 RL 방법을 묶었다 확인(초록).
    • SID 토크나이저 CoCo-VAE는 협업 신호를 넣고, codebook collapse(일부 코드만 쓰이는 현상)를 막는다.
    • RL 방법 DHPO는 SID 정확 일치에서만 보상이 나와 희소해지는 문제를, SID 계층별로 보상 범위를 넓혀 푼다.
  • 초록은 2개월 온라인 A/B 결과를 밝히고, 여러 검색 지면에 배포됐다고 적었다 확인(초록).
    • WeChat 전자상거래 검색에서 주문은 +2.539%, CTR은 +1.508%, 전환율은 +1.381%였고, CPU·GPU 사용량은 −25.5%·−26.1%였다.

정본 반영 정본에는 반영하지 않았다. radar.md의 생성형 retrieval / semantic ID 스레드에 추가 근거로 한 줄 넣었다.

의미 WeChat/Tencent에서 Tlow(flow 기반 아이템 토크나이저)에 이어 나온 두 번째 SID 프로덕션 진술이다. "SID 계층별 부분 보상"이라는 RL 설계 축도 추가한다. 다만 검색 지면이라 피드와 거리가 있다. 본문은 읽지 않았다.
