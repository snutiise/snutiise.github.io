Phoenix retrieval two-tower가 카탈로그로 승격됐다. 지금까지 xrecsys_two_tower.py는 파일이 존재하며 여러 커밋에서 소품 수정(4세대+6에서 qk_norm=True·attn_logit_cap=-1·right_anchored_rope=True 3옵션 도입, 4세대+21에서 H100 attn 커널 pallas_ranker_varlen_attn → cutedsl_ranker_varlen_attn flip)이 있었으나 registry 카탈로그 자체는 잠기지 않은 상태였다. 오늘 6개 preset(H100/GB300 × single/combined + immersive-only + nano)이 MODEL_CFGS에 잠기면서 프로덕션 데이터 파이프에 연결되도록 이관됐다 [추정] — 근거는 파일 안의 유일한 in-file dataset이 aggregated_kafka이고 preset이 hardware-aware로 잘 정의돼 있다는 점. 특히 SID-only(포스트 임베딩 대신 6-level codebook hash)·seqpack·H100/GB300 하드웨어 프리셋·Home+Immersive 두 head 공유가 한 파일에 정리됐다는 점이 눈에 띈다. 4세대+13에서 관측된 "DPA 광고 제품에도 sid_codes 배선"과 짝을 이루면 SID 어휘 체계가 유기 post·광고 DPA·retrieval two-tower의 세 사용처를 하나로 묶을 잠재가 커진다.
    3. 광고 conversion 헤드가 web/app 축으로 분화됐다. 4세대+6에서 도입된 delayed feedback split과 4세대+24에서 통합된 ads_head_masking 노브가 오늘 학습 그래프 내부 float multiplier에서 데이터 로더가 미리 계산한 boolean mask로 이동했다. 이는 (a) 그래프가 sample_source에 의존하지 않게 하여 컴파일 안정성 확보, (b) 웹 conversion 헤드와 앱(MMP) conversion 헤드를 분리 학습해 keep_web / keep_app 두 축의 sample subset을 각기 다르게 사용 가능. Mask semantics는 여전히 동일한 late-window twin suppression 로직을 유지하지만 계산 위치만 바꾼 정확한 리팩터. use_seqpack과 상호 배타 assert가 새로 걸린 것은 seqpack이 candidate 슬롯 대응이 무너지기 때문. proto의 ADS_ATTRIBUTED_MACT_MMP_{CLICK, VIEW}_INSTALL = 194, 195 두 액션 신설이 MMP 측 app-install conversion을 정식으로 학습 헤드에 편입할 채널을 만든다.
    4. 홈믹서 cold-start가 프로덕션 파라미터로 세팅됐다. 4세대+30에서 신설된 HOME_COLD=14 채널의 코드 경로 추가에 이어 오늘 파라미터가 잡혔다 — Phoenix cold retrieval 채널이 0에서 200 posts로 열렸고, MaxPostAge가 48h에서 2h로 극단화됐다. FollowerCap이 1000에서 50k로 사실상 해제되어 author 풀이 폭증했고, ImpressionThreshold가 1000에서 200으로 낮아져 cold-start 대상 유저를 5배 넓혔다. Thompson sampling도 켜졌다. cold-start가 지금까지 tracked author나 신규 유저 대상 좁은 exploration이었다면 이 파라미터 세팅에서는 (신선도가 극단적으로 엄격한 2h) × (author 풀이 넓게 열림) 조합이 작동한다. 이 튜닝이 A/B에서 유지되는지가 다음 크론 sync에서 관측할 지점.

    Brazil 2026 election filter의 handle 9개 추가는 리스트 유지보수(로직 변경 없음). Composition.rs 삭제는 candidate-pipeline 공용 라이브러리 재사용으로 인한 중복 제거.

    2. HELIX — TikTok e-commerce 랭킹의 "unified & purified" 아키텍처가 A/B에서 GMV per user +~6%

    자료 HELIX: Purified and Unified - Rethinking Feature Interaction and Sequence Modeling for Large-Scale Recommendation — arXiv 2609.37183 v1, 2026-09-29(arXiv 제출), 논문.

    배경

    산업 추천 랭킹 모델은 대체로 두 축으로 스케일한다: (a) heterogeneous feature interaction(유저 / 아이템 / 컨텍스트 / 크로스 피처를 조합해서 상호작용), (b) sequence modeling(길고 다양한 유형의 유저 behavior 시퀀스를 인코딩). HELIX 저자들은 어느 한 축만 키우면 scaling-law slope가 서브옵티멀임을 관찰하고 두 축을 함께 확장하는 "unified" 랭킹 아키텍처를 제안한다. 저자는 21명이고 v1 HTML은 렌더링 404지만 초록에 "Deployed in TikTok's e-commerce recommendation system"이라는 문구가 있어 소속은 TikTok(ByteDance) [추정].

    새로 알게 된 것

    • 프로덕션 배포 진술과 GMV A/B 수치 [확인](초록 직접 인용).

    "Deployed in TikTok's e-commerce recommendation system, HELIX consistently improves offline CTR AUC, CVR AUC, and other ranking metrics. In online A/B tests, it achieves an approximately 6% increase in e-commerce video GMV per user." — HELIX abstract, 2026-09-29

    • 메커니즘 신규성: feature-interaction 축과 long/multi-type user-behavior sequence 축을 동시에 스케일링하는 "purified and unified" 랭킹 아키텍처. 둘을 함께 확장해야 scaling law가 서브옵티멀에서 벗어난다는 관찰이 논문의 핵심 관점 [확인](초록 문구).
    • 스케일: 명시 사용자·요청 수 없음. GMV per user 지표 사용은 대규모 e-commerce 트래픽 [추정].

    정본 반영 radar.md — "이번 달 신규"에 2줄 포인터 추가. 서비스 정본(X·Meta·Netflix)과 직결되지 않는다.

    의미

    TikTok의 e-commerce recommendation은 그동안 EGA(Elastic Generative Auction, 광고 경매·랭킹) 계열과 GreenLightning(단일 인퍼런스 서비스) 계열 공개가 이어져 왔는데, feature-interaction + long sequence를 함께 스케일링하는 랭킹 아키텍처를 정식으로 이름 붙여 공개한 것은 이번이 처음이다. Scaling law가 두 축의 동시 확장을 요구한다는 관점은 (a) Meta HSTU / GEM 계열의 sequence-only 확장, (b) DCN·xDeepFM 계열의 feature-interaction 확장이 각각 서브옵티멀임을 시사한다. 다만 초록 기반 triage 단계라 세부 아키텍처(어떤 인터랙션 구조, 어떤 sequence 인코더, scaling law slope의 실측치)는 심층 분석 대상이다. 서비스 정본에는 반영하지 않고 radar에 둔다.

    3. GRP v0.1 — Snap의 encoder-decoder 단일 모델이 retrieval · ranking · reward를 통합, 프로덕션 A/B view time +0.82% · shares +2.56%

    자료 GRP v0.1 Technical Report — arXiv 2609.36688 v1, 2026-09-29(arXiv 제출), 논문.

    배경

    산업 추천 시스템은 대체로 retrieval → pre-ranking → fine-ranking → reward 재순위의 다단 cascade로 구성된다. 각 단계를 별도 모델로 학습·배포하다 보니 스택 전체를 함께 교체하기가 어렵다. GRP(Generative Recommendation Platform으로 추정)는 이 다단을 단일 encoder-decoder 모델로 통합하는 프레임워크를 제시한다. Snap Inc.의 v1 HTML 페이지 조직명 렌더링이 있어 소속은 Snap [확인]. multimodal Semantic ID를 생성하고, joint MHP(Multi-Head Prediction)가 후보 스코어링과 RL post-training의 frozen reward를 겸한다.

    새로 알게 된 것

    • A/B 직접 인용 [확인].

    "In a retrieval-only comparison, view time increases by 0.46% and shares by 0.77% relative to production. A separate comparison combining bypass and source replacement yields increases of 0.82% in view time and 2.56% in shares, with neutral platform-level guardrails." — GRP v0.1, 2026-09-29

    • 추가 축: retrieval bypass 조합에서 "+0.24% views, −0.24% view time, +2.30% shares (p<0.05)".
    • 메커니즘 신규성: retrieval · ranking · reward를 단일 encoder-decoder로 통합하는 generative recommendation 프레임워크. multimodal Semantic ID 생성 + joint multi-head prediction(MHP)이 후보 스코어링과 RL post-training(mGRPO — reference-anchored margin)의 frozen reward를 겸한다.
    • 스케일 / 서빙: 명시 사용자·요청 수 없음. serving 최적화로 end-to-end retrieval latency −69%. 26 pages, 11 tables.

    정본 반영 radar.md — "이번 달 신규"에 2줄 포인터 추가. Snap이 추적 서비스 밖이라 서비스 정본에는 반영하지 않는다.

    의미

    이번 달 초부터 관찰해 온 "generative recommendation의 서빙 경로 통합" 각도의 새 진술이다. Kuaishou OneTrans-V2가 retrieval + pre-rank + fine-rank 3단 cascade를 단일 Transformer로 묶어 GMV +9.74%를 얻었고(2026-09-28 radar), Tencent PCG TGR이 랭킹·retrieval·slate 생성·reason token을 한 프레임에 묶어 5개 지면에 배포한 것과 방향이 같다. GRP는 여기에 (a) reward까지 같은 모델 안에서 처리하는 mGRPO joint MHP 축, (b) multimodal Semantic ID 생성 축이 추가된다. 서빙 latency −69%는 다단 cascade 대비 큰 절감으로, encoder-decoder 통합이 latency 예산까지 정당화하는지가 industrial-scale generative recsys 채택의 핵심 기준이라는 신호. 서비스 정본에는 반영하지 않고 radar에 둔다.
