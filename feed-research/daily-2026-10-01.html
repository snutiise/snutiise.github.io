배경 visibility-filtering(VF, X의 트윗 필터 파이프라인)의 hydration 계층은 2026-09-25부터 09-29까지 나흘 사이에 세 번 뒤집혔다. hydration은 판정에 필요한 원본 데이터를 backend 서비스에서 배치로 조회해 채우는 단계다.

  • 4세대+29(2026-09-25, bf7db1b)가 Hydrator enum을 7 → 17 variant로 확장하며, 데이터 기반 plan/execute/sources 3-파일을 신설했다.
  • 4세대+30(2026-09-26, 4c5cfe8)이 그 안의 상태를 store.rs로, 실행을 execute.rs로 분리했다.
  • 어제 4세대+31(2026-09-29, a707cc2)이 retweet.rs를 별도 모듈로 추출하면서, in-batch 소스와 fetched 소스를 두 번-hydrate 패턴으로 병합했다. 두 번-hydrate 패턴은 요청 배치를 hydrate한 뒤 리트윗 소스만 두 번째 hydrate 호출로 따로 채우는 방식이다.

이번 커밋(4세대+32)은 이 두 번-hydrate 패턴을 한 번-hydrate와 in-flight 확장 패턴으로 단순화했다. in-flight 확장은 조회가 진행되는 도중에 먼저 도착한 결과를 보고 요청 목록을 늘리는 방식이다. 또 Store의 8개 Option<HydrationBatch> 필드를 새 Fetcher<V> trait 어레이로 다시 써서, 같은 hydrator를 다시 불러도 이미 클레임된 키는 재요청하지 않게 했다.

동시에 두 축이 별도로 진화했다. Phoenix(X For You의 랭킹 모델 스택, 학습 코드는 4세대에서 공개)의 xrecsys_two_tower.py가 registry에 정식 카탈로그로 편입됐다. 이와 함께 SID(semantic ID) 기반 candidate tower와 sequence packing이 6개 preset으로 잠겼다. SID는 포스트 임베딩 대신 codebook 여러 층으로 hash한 이산 코드다. sequence packing은 여러 유저 시퀀스를 한 배치 행에 이어 붙이는 방식이다. 광고 conversion 헤드 학습에 쓰던 ads_head_masking은 JAX 학습 그래프에서 numpy 데이터 로더로 옮겨지면서, web conversion과 app(MMP, Mobile Measurement Partner) conversion 두 축을 분리 학습할 수 있게 됐다.

  • 홈믹서(home-mixer, For You 피드 요청을 처리하는 서비스)의 cold-start 파라미터 6개가 크론 미러에서 이동했다 확인 — home-mixer/params/param.rs.

2HELIX가 TikTok e-commerce A/B에서 유저당 GMV를 약 6% 높였다 — 레이더

자료 HELIX: Purified and Unified - Rethinking Feature Interaction and Sequence Modeling for Large-Scale Recommendation — arXiv 2609.37183 v1, 2026-09-29(arXiv 제출), 논문. 저자는 21명이다. v1 HTML은 렌더링이 404지만 초록에 "Deployed in TikTok's e-commerce recommendation system"이라는 문구가 있어, 소속은 TikTok(ByteDance)으로 본다 추정.

배경 산업 추천 랭킹 모델은 대체로 두 축으로 스케일한다.

  • heterogeneous feature interaction: 유저 / 아이템 / 컨텍스트 / 크로스 피처를 조합해 상호작용시킨다.
  • sequence modeling: 길고 다양한 유형의 유저 behavior 시퀀스를 인코딩한다.

HELIX 저자들은 어느 한 축만 키우면 scaling-law slope가 서브옵티멀임을 관찰하고, 두 축을 함께 확장하는 "unified" 랭킹 아키텍처를 제안한다.

새로 알게 된 것A. TikTok e-commerce에 배포됐고, 온라인 A/B에서 유저당 GMV가 약 6% 늘었다

  • 초록은 HELIX가 TikTok의 e-commerce 추천 시스템에 배포됐고, 오프라인 CTR AUC·CVR AUC 등 랭킹 지표를 일관되게 개선한다고 밝힌다 확인(초록 직접 인용).
  • 온라인 A/B에서는 e-commerce video GMV per user가 약 6% 늘었다 확인(초록 직접 인용).

"Deployed in TikTok's e-commerce recommendation system, HELIX consistently improves offline CTR AUC, CVR AUC, and other ranking metrics. In online A/B tests, it achieves an approximately 6% increase in e-commerce video GMV per user." — HELIX abstract, 2026-09-29

새로 알게 된 것B. 핵심 관점은 두 축을 함께 키워야 scaling law가 서브옵티멀에서 벗어난다는 것이다

  • HELIX는 feature-interaction 축과 long/multi-type user-behavior sequence 축을 동시에 스케일링하는 "purified and unified" 랭킹 아키텍처다 확인(초록 문구).

3Snap의 GRP가 retrieval·ranking·reward를 한 모델로 합쳤다 — 레이더

자료 GRP v0.1 Technical Report — arXiv 2609.36688 v1, 2026-09-29(arXiv 제출), 논문. v1 HTML 페이지에 Snap Inc. 조직명이 렌더링돼 있어, 소속은 Snap이다 확인.

배경 산업 추천 시스템은 대체로 retrieval → pre-ranking → fine-ranking → reward 재순위의 다단 cascade로 구성된다. 각 단계를 별도 모델로 학습·배포하다 보니 스택 전체를 함께 교체하기가 어렵다. 이번 논문의 GRP(Generative Recommendation Platform으로 추정)는 이 다단을 단일 encoder-decoder 모델로 통합하는 프레임워크를 제시한다. 이 모델은 multimodal Semantic ID를 생성하고, joint MHP(Multi-Head Prediction)가 후보 스코어링과 RL post-training의 frozen reward를 겸한다.

새로 알게 된 것A. retrieval만 비교한 A/B와 bypass·source replacement를 함께 적용한 A/B에서 view time과 shares가 늘었다

  • retrieval만 비교했을 때 프로덕션 대비 view time이 0.46%, shares가 0.77% 늘었다 확인(A/B 직접 인용).
  • bypass와 source replacement를 함께 적용한 별도 비교에서는 view time +0.82%, shares +2.56%였고, 플랫폼 수준 guardrail은 중립이었다 확인(A/B 직접 인용).

"In a retrieval-only comparison, view time increases by 0.46% and shares by 0.77% relative to production. A separate comparison combining bypass and source replacement yields increases of 0.82% in view time and 2.56% in shares, with neutral platform-level guardrails." — GRP v0.1, 2026-09-29

새로 알게 된 것B. retrieval bypass 조합에서는 views와 shares가 늘고 view time은 줄었다

  • retrieval bypass 조합의 추가 축은 다음 수치다: "+0.24% views, −0.24% view time, +2.30% shares (p<0.05)".

새로 알게 된 것C. retrieval·ranking·reward를 encoder-decoder 하나로 통합한다

  • GRP는 retrieval · ranking · reward를 단일 encoder-decoder로 통합하는 generative recommendation 프레임워크다.
  • multimodal Semantic ID를 생성하고, joint multi-head prediction(MHP)이 후보 스코어링과 RL post-training의 frozen reward를 겸한다. RL post-training은 mGRPO(reference-anchored margin)다.

새로 알게 된 것D. 서빙 최적화로 retrieval latency를 줄였다

  • 사용자 수나 요청 수는 명시하지 않았다.
  • serving 최적화로 end-to-end retrieval latency가 69% 줄었다.
  • 논문 분량은 26 pages, 11 tables다.

정본 반영 radar.md의 "이번 달 신규"에 2줄 포인터를 추가했다. Snap은 추적 서비스 밖이라 서비스 정본에는 반영하지 않는다.

의미 GRP는 이번 달 초부터 관찰해 온 "generative recommendation의 서빙 경로 통합" 각도의 새 진술이다.

  • Kuaishou OneTrans-V2는 retrieval·pre-rank·fine-rank 3단 cascade를 단일 Transformer로 묶어 GMV +9.74%를 얻었다(2026-09-28 radar). Tencent PCG TGR은 랭킹·retrieval·slate 생성·reason token을 한 프레임에 묶어 5개 지면에 배포했다. GRP는 이 둘과 방향이 같다.
  • GRP에는 여기에 두 축이 더해진다. 하나는 reward까지 같은 모델 안에서 처리하는 mGRPO joint MHP 축이고, 다른 하나는 multimodal Semantic ID 생성 축이다.
  • 서빙 latency −69%는 다단 cascade 대비 큰 절감이고, encoder-decoder 통합이 latency 예산까지 정당화하는지가 industrial-scale generative recsys 채택의 핵심 기준이라는 신호다.
  • 서비스 정본에는 반영하지 않고 radar에 둔다.

↑ 목차

레이더

  • HELIX(TikTok [추정])는 feature-interaction과 long user-behavior sequence 두 축을 함께 스케일링하는 unified 랭킹 아키텍처다(arXiv 2609.37183). TikTok e-commerce에 배포되어 A/B에서 GMV per user +~6%를 얻었다. 지표는 확인, 소속은 추정이다(v1 HTML 렌더링 404, 초록 문구 기반). radar.md 이번 달 신규에 편입했다.
  • GRP v0.1(Snap)은 retrieval · ranking · reward를 단일 encoder-decoder로 통합하는 generative recommendation 프레임워크다(arXiv 2609.36688). 구성 요소는 multimodal Semantic ID, joint MHP, mGRPO다. 프로덕션 A/B에서 view time +0.82%, shares +2.56%를 얻었고, serving latency는 −69%다. 소속과 지표는 확인이다. radar.md 이번 달 신규에 편입했다.
