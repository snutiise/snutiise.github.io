    배경

    X의 For You 피드는 여러 후보 소스가 포스트를 모으고, Phoenix(Grok 기반 Transformer 랭커)가 좋아요·답글·영상 열기 같은 행동마다 확률을 예측한다. 그다음 value model이 이 확률들을 가중합해서 순서를 정한다. 마지막 단계의 블렌더는 광고, 팔로우 추천(Who-to-Follow, WTF), 프롬프트 같은 비(非)포스트 모듈을 정해진 자리에 끼워 넣는다.

    이번 커밋은 변경량이 1만 5천 줄이지만, 상당 부분은 서드파티 GPU 커널 유틸(CuTe DSL quack, 약 3,000줄)과 안전 계층(visibility filtering, VF) 내부 코드다. 피드 동작과 관련된 변경은 세 가지다: 블렌더에 들어갈 새 모듈, 랭커 학습 손실의 기본값 변경, 후보 생성 모델(two-tower)의 새 옵션이다. 예산 가드에 따라 이 세 가지를 중심으로 분석하고, 나머지는 "다음에 볼 것"에 남긴다.

    새로 알게 된 것 — A. For You에 세로 영상 캐러셀 모듈이 생겼다 (기본 off)

    • 새 파라미터 세 개가 프로덕션 기본값 미러(param.rs, 매일 X 내부 feature switch 기본값을 복사한 파일)에 들어왔다 [확인] — home-mixer/params/param.rs: EnableVideoCarousel = false, VideoCarouselFatigueMinutes = 60, VideoCarouselPosition = 6. 미러 sync 시각은 2026-10-07T16:00:42Z이고, 미러에서 바뀐 것은 이 세 개뿐이다.

    • 켜지는 조건은 세 가지다: For You 요청이고, 플래그가 켜져 있고, 직전 캐러셀 노출 후 60분이 지났어야 한다 [확인] — home-mixer/util/video_carousel.rs:7-11, query_hydrators/served_history_query_hydrator.rs:52-57, 110-126. 피로도(fatigue)는 유저가 같은 모듈을 너무 자주 보지 않게 하는 쿨다운으로, WTF 모듈(시간 단위)과 피드 설문(분 단위)에 이미 쓰던 장치를 그대로 재사용했다.

    • 후보를 고르는 경로는 두 단계다 [확인] — selectors/top_k_score_selector.rs:10-27, filters/video_carousel_filter.rs, params/config.rs:17-19, 35-36:

      1. 랭킹 직후 선택 단계는 원래 점수 상위 50개만 남긴다. 캐러셀이 켜지면 탈락한 후보 중에서 영상이고, 답글이 아니고, video_open 예측값이 있는 포스트를 video_open 확률 순으로 최대 30개 더 살려 둔다. 이 후보들에는 video_carousel_extra 표시가 붙는다.
      2. 살린 후보도 VF 필터와 대화 중복 제거 필터를 똑같이 거친다. 마지막 필터 VideoCarouselFilter가 extra 후보를 본 피드에서 빼낸다. 그다음 "상위 50개 중 36위 이하 + 빼낸 extra" 풀에서 세로 영상(가로/세로 비 < 1.0)만 골라 video_open 순으로 최대 5개를 캐러셀에 담는다. 3개가 안 되면 모듈을 만들지 않는다.

    새로 알게 된 것 — B. 체류 시간 헤드의 학습 손실이 CREAD로 바뀌었다 (기본 on)

    dwell_time 헤드는 유저가 포스트에 머문 초를 예측하는 회귀 헤드다. value model은 이 값에 ContDwellTimeWeight를 곱해 점수에 더한다. 체류 시간은 대부분 몇 초에 몰려 있고 긴 꼬리가 있어서 평균 제곱 오차 같은 단순 회귀로는 학습이 불안정하다. 그래서 X는 지금까지 Tweedie 손실(긴 꼬리가 있는 양수 값에 맞춘 분포 손실)과 MAE(절대 오차)를 함께 써 왔다.

    CREAD는 Kuaishou가 영상 시청 시간 예측을 위해 발표한 방법이다(CREAD: A Classification-Restoration Framework with Error Adaptive Discretization for Watch Time Prediction in Video Recommender Systems, 2024-01, 논문). 시간을 직접 회귀하지 않고, 여러 임계값마다 "이 시간을 넘었는가"를 이진 분류로 학습한다. 그런 다음 확률들을 이어 붙여 기댓값을 복원한다.

    • 홈 기본 학습 config _home_direct_packed_base()에서 Tweedie와 MAE 가중치가 0.0이 되고 CREAD 두 개가 0.1로 켜졌다 [확인] — phoenix/xrex/configs/xrecsys.py:272-275, 687-742. 이전에는 Tweedie(power 1.5)와 MAE가 각각 0.1로 하드코딩돼 있었다.
    • 두 CREAD 손실은 지면별로 나뉜다 [확인](같은 파일):
      • 일반 지면용: 상한 120초이고 갤러리 지면(PRODUCT_SURFACE_GALLERY_PAGE)을 제외한다.
      • 몰입형용(dwell-time-cread-immersive): 상한 240초이고 갤러리 지면만 대상이다. 갤러리 지면은 사진·영상을 전체 화면으로 넘겨 보는 화면으로 보인다 [추정] — 메트릭 이름이 immersive이고, 체류 상한을 두 배로 잡았다.
    • 임계값은 2초부터 상한까지 로그 간격으로 30개다. 상한이 120초이면 2.0, 2.3, 2.65 … 90.5, 104.2, 120초가 된다 [확인] — phoenix/xrex/models/loss_recsys.py cread_log_thresholds. 각 임계마다 sigmoid 이진 교차 엔트로피를 계산한다. 복원값은 "임계를 넘을 확률 × 구간 폭"의 합이고, 이 값과 실제 초의 Huber 손실(δ=5초, 가중 0.5)을 더한다 [확인] — 같은 파일 cread_loss_compute, recsys_model.py _decode_cread.
    • 논문은 구간 경계를 오차가 작아지도록 데이터에 맞춰 정하는 것(error adaptive discretization)이 핵심 기여인데, X 구현은 고정 로그 간격을 쓴다 [확인]. 이름과 분류-복원 구조만 가져온 셈이다.
    • 같은 임계 체계가 입력 피처에도 쓰인다. 유저 히스토리의 각 포스트에 대해 과거 체류 시간을 버킷 임베딩으로 넣는 enable_dwell_bucket_table=True가 기본 on이 됐다(상한 240초, 임계 30개, 인접한 두 버킷 사이를 선형 보간) [확인] — models/recsys_feature_prep.py:180-184, 885-910, configs/xrecsys.py:301-304. 지금까지는 히스토리의 체류 시간이 어떤 형태로 입력되는지 정본에 기록하지 않았다.

    새로 알게 된 것 — C. two-tower retrieval에 Mixture-of-Logits 옵션 (기본 off)

    two-tower retrieval은 유저 벡터 하나와 포스트 벡터 하나의 내적으로 수억 개 중 후보를 빠르게 찾는 구조다. 유저 관심이 여러 갈래일 때 벡터 하나로는 다 담기 어렵다는 한계가 알려져 있다. Mixture-of-Logits(MoL)는 유저 쪽과 아이템 쪽 벡터를 여러 개 두고, 그 조합 점수들을 작은 gate 네트워크로 가중합해서 이 한계를 줄이는 방법이다.

    • user_query_heads=K이면 유저 시퀀스 출력을 학습된 query 벡터 K개로 attention pooling해서 유저 벡터를 K개 만든다 [확인] — phoenix/xrex/models/recsys_two_tower_model.py:1629-1665. head마다 최근 행동에 더 무게를 두는 감쇠 계수가 따로 학습된다.
    • mol_item_components=L이면 포스트 임베딩에 저랭크 어댑터를 적용해 성분 벡터 L개를 만든다. K×L개 코사인을 MLP gate(softmax)로 섞어 최종 점수를 낸다 [확인] — 같은 파일 523-598행 MolScorer.
    • 서빙용 CUDA 커널도 함께 공개됐다. 지원 조합은 (K×L, gate hidden) ∈ {(4,32), (8,16), (8,32), (16,16)}이고 요청당 유저는 512명까지다 [확인] — phoenix/xrex/cuda/mol_epilogue/__init__.py:11-12.
    • 학습 손실 옵션도 네 개가 추가됐다 [확인] — 같은 파일 2194-2224행: 고정 temperature, 배치 안의 같은 포스트가 negative로 잡히는 false negative 마스킹, 유저가 부정 행동을 한 포스트에 대한 logit offset, positive 수 기반 유저 가중이다.
    • 기본값은 모두 0 또는 False이고, 공개된 프리셋 6개 어디에서도 켜지 않는다 [확인](configs 디렉터리 grep). 프로덕션 retrieval이 이미 MoL인지는 이 코드로 판단할 수 없다 [추정] — 실험 config는 공개되지 않는다. 다만 서빙 커널까지 만들어 둔 것은 실험 단계를 넘어 배포를 준비하는 신호로 읽힌다 [추정].

    의미

    • 지금까지 For You의 모든 포스트 슬롯은 value model 가중합으로 순서가 정해졌다. 캐러셀은 video_open 단일 헤드 확률로 채우는 첫 포스트 모듈이다 [확인]. 본 랭킹에서 아깝게 탈락한 세로 영상을 별도 목적 함수로 다시 노출하는 구조다. Reels·Shorts식 세로 영상 소비를 피드 안으로 끌어오려는 시도로 보인다 [추정] — 정본이 기록한 비디오 전용 Thunder 경로(is_video_request)와 같은 방향이다.
