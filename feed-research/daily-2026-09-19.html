    한 줄 요약X 4세대+24가 광고 랭킹 학습에서 세 개의 delayed feedback 관련 플래그(condition_conversion_on_click·train_view_through_heads·split_head_training_by_source)를 단일 ads_head_masking으로 통합하면서 sample source를 fresh/early-relabel/late-split 3-stream으로 분기하고, 광고 매출액 loss는 early-relabel 슬라이스로만 학습되도록 좁혀졌으며, wire proto에 유저 광고 참여 이력의 시간창 카운트(EngagementCounts)와 검색 랭킹의 렉시컬 매치(SearchLexicalMatch) 신호가 추가됐다.

    1. X 4세대+24 — c279172, 30개 파일, +1491/−154 — X

    자료 xai-org/x-algorithm@c279172 — GitHub 커밋, 2026-09-18 (커밋 메시지 Open-source X Recommendation Algorithm, 정규 일일 미러 릴리스), 코드.

    배경. X의 오픈소스 미러가 매일 밤 x.com 프로덕션 스냅숏의 재편된 커밋 하나를 공개한다. 4세대+24는 4세대+23(2026-09-17, FavHoldoutFilter 신설 등)의 다음 릴리스이며 크게 세 방향의 변경이 몰려 있다: (a) 광고 랭킹 학습 파이프라인이 delayed feedback을 sample-source 축의 3-stream으로 재정의하고 (b) Phoenix wire proto가 유저 광고 참여 이력의 시간창 카운트와 검색 렉시컬 매치 두 개의 새 채널을 뽑았으며 (c) grox 안전 파이프라인이 참조 영상 번들에 대해 VLM으로 후보 영상을 비교하는 새 spam-clone 탐지 흐름을 붙였다. 그 외 다수의 소규모 정리가 함께 왔다.

    Delayed feedback이라는 용어부터 풀어 쓰면, 광고 노출 후 며칠에 걸쳐 관측되는 컨버전(구매·설치·리드 폼 완료 등)을 학습 라벨로 취급할 때 라벨이 시점상 밀려서 도착하는 조건을 말한다. X는 4세대+6(2026-08-21)에서 광고 컨버전 액션을 20개 확장하면서 이 문제를 다루는 세 개의 config 플래그(condition_conversion_on_click·train_view_through_heads·split_head_training_by_source)를 처음 붙였고, 4세대+23(2026-09-17)에서 지연 창을 3-tier(원본·tier 2·tier 3)로 세분화했으며, 이번 4세대+24가 이 세 플래그를 단일 ads_head_masking 플래그와 3개의 sample-source 스트림 ID로 통합했다.

    새로 알게 된 것

    A. ads_head_masking — 세 플래그 통합 + sample-source 3-stream

    파일 phoenix/xrex/models/recsys_model.py(+50/−55), 신규 phoenix/xrex/models/ads_head_masking.py(67줄), phoenix/xrex/data/recsys/constants.py [확인].

    RecsysAggregatedModelConfig에서 condition_conversion_on_click·train_view_through_heads·split_head_training_by_source 세 필드가 통째로 삭제되고 자리에 ads_head_masking: bool = False 하나가 들어왔다. 새 상수 세 개:

    FRESH_STREAM_ID = 0
EARLY_RELABEL_STREAM_ID = 1
LATE_SPLIT_STREAM_ID = 2

    ads_head_masking=True일 때 loss 마스크는 ads_head_masking_factor(targets, source_id, num_actions) 함수가 조립한다. 함수는 (batch, seq, num_actions) 크기의 실수 텐서를 반환하는데, 각 액션 인덱스에 대해 다음 규칙으로 켜진다.

    • Engagement 헤드(num_actions에서 CT·VT·twin 인덱스를 뺀 나머지) — FRESH_STREAM_ID 샘플에서만 1
    • CT(click-conditioned) 헤드(CLICK_CONDITIONED_ACTION_INDICES) — EARLY_RELABEL_STREAM_ID 샘플에서 클릭이 있었으면 1
    • VT(view-through) 헤드(VIEW_THROUGH_ACTION_INDICES) — EARLY_RELABEL_STREAM_ID 샘플에서 클릭이 없었으면 1
    • Twin(late-window delayed) 헤드(신규 목록 ADS_LATE_WINDOW_TWIN_HEAD_INDICES) — LATE_SPLIT_STREAM_ID 샘플에서 클릭이 있었고 early counterpart가 없을 때만 1

    Twin 헤드는 phoenix/xrex/data/recsys/ads_late_window.py(29줄 신규)에 명시된 10개다. 각각 ADS_ATTRIBUTED_KEY_CLICK_CONVERSION_DELAYED·ADS_ATTRIBUTED_CLICK_CONVERSION_DELAYED·ADS_PURCHASE_CONVERSION_DELAYED·ADS_MID_FUNNEL_CONVERSION_DELAYED·ADS_ADD_TO_CART_CONVERSION_DELAYED·ADS_UPPER_FUNNEL_CONVERSION_DELAYED·ADS_WEB_CONVERSION_DELAYED·ADS_SEARCH_CONVERSION_DELAYED·ADS_SIGN_UP_CONVERSION_DELAYED·ADS_CHECKOUT_INITIATED_CONVERSION_DELAYED(action index 204-213, 4세대+6에서 신설). 이번 커밋은 이 base tier 10종에만 twin 로직을 붙였다. 어제 4세대+23에서 신설된 tier 2(214-223)·tier 3(224-233)은 아직 이 목록에 편입되지 않았다.

    동시에 함께 신설된 ADS_LATE_WINDOW_TWIN_SUPPRESSOR 딕셔너리가 twin 헤드마다 그것을 억제하는 fresh-stream 카운터파트 인덱스를 매핑한다.

    ADS_LATE_WINDOW_TWIN_SUPPRESSOR = {
    ADS_ATTRIBUTED_KEY_CLICK_CONVERSION_DELAYED: ADS_ATTRIBUTED_KEY_CLICK_CONVERSION,
    ADS_ATTRIBUTED_CLICK_CONVERSION_DELAYED:     ADS_ATTRIBUTED_CLICK_CONVERSION,
    ADS_PURCHASE_CONVERSION_DELAYED:             ADS_PURCHASE_CONVERSION,
    ADS_MID_FUNNEL_CONVERSION_DELAYED:           ADS_MID_FUNNEL_CONVERSION,
    ADS_ADD_TO_CART_CONVERSION_DELAYED:          ADS_ADD_TO_CART_CONVERSION,
    ADS_UPPER_FUNNEL_CONVERSION_DELAYED:         ADS_UPPER_FUNNEL_CONVERSION,
    ADS_WEB_CONVERSION_DELAYED:                  ADS_ATTRIBUTED_CLICK_CONVERSION,
    ADS_SEARCH_CONVERSION_DELAYED:               ADS_SEARCH_CONVERSION,
    ADS_SIGN_UP_CONVERSION_DELAYED:              ADS_SIGN_UP_CONVERSION,
    ADS_CHECKOUT_INITIATED_CONVERSION_DELAYED:   ADS_CHECKOUT_INITIATED_CONVERSION,
}

    — phoenix/xrex/data/recsys/ads_late_window.py, 2026-09-18

    ads_head_masking_factor 안에서 no_early_counterpart = 1 - targets[:, :, suppressor_index]로 이 억제자를 조회한 뒤 late-split twin 헤드 마스크에 곱한다. 즉 같은 (유저·광고) 샘플에서 fresh stream의 카운터파트 컨버전이 이미 잡혀 있으면 late-split의 twin 헤드는 학습에서 제외돼서 이중 계산을 피한다. 특기할 점은 ADS_WEB_CONVERSION_DELAYED의 카운터파트가 ADS_WEB_CONVERSION이 아니라 ADS_ATTRIBUTED_CLICK_CONVERSION으로 매핑돼 있다는 점이다. 웹 컨버전이 attributed-click 컨버전의 지연 관측으로 간주된다는 뜻으로 읽힌다 [추정].

    메트릭 슬라이스도 함께 재정의된다. build_metric_masks가 condition_conversion_on_click·split_head_training_by_source 두 파라미터를 잃고 대신 ads_head_masking 하나만 받는다. 새 슬라이스 late_split_no_early(= mask × late × click × no_early)가 등장했고, 기존 fresh·delayed_clicked·delayed_non_clicked는 유지된다.

    의미. delayed feedback 라벨링을 프로덕션 학습 파이프라인에서 3-스트림으로 명확히 나눠 처리한다는 결정이다. Chapelle 2014 이후의 delayed feedback 문헌이 대체로 "라벨 관측 창을 기다린다 vs 예측치를 상시 갱신한다" 축에서 논의됐고, X는 후자에 가깝게 "fresh(즉시)·early(짧은 창)·late(긴 창)" 세 관측 시점을 각각 sample source로 명시한다. train_view_through_heads=False 기본으로 view-through 헤드를 꺼 두던 이전 관행은 사라졌다: 4세대+6에서 도입된 VT 헤드 8종이 이번엔 ads_head_masking=True이면 자동으로 EARLY_RELABEL 슬라이스에서 (클릭이 없을 때) 학습에 편입된다. 배포 시점은 이 config가 mparams에 "ads_head_masking": True로 설정되는 커밋에서 확인이 가능하다.

    B. Purchase-value loss가 EARLY_RELABEL 슬라이스로만 학습되도록 좁혀졌다

    phoenix/xrex/models/loss_recsys.py(+75/−10) [확인].

    purchase_value_valid_mask의 조건이 sample_source > 0에서 sample_source == EARLY_RELABEL_STREAM_ID로 좁혀졌다. 4세대+22(2026-09-16)에서 구매액 loss가 정식 배선됐을 때는 "delayed(=fresh가 아닌 것) 샘플" 전체를 유효로 봤지만, 이번엔 오직 early-relabel 스트림만 유효로 취급한다. 즉 late-split 스트림에서는 구매액 회귀를 학습하지 않고 twin 헤드의 분류만 학습한다는 배선.

    동반해서 loss stat 이름들도 전부 purchase-value-*에서 purchase-value_delayed_clicked-*로 변경됐다. 이는 위 마스크 조건과 이름을 맞춘 것으로, 이 헤드가 학습되는 실효 슬라이스가 "delayed sample 중 clicked"라는 부분집합임을 스탯 이름 자체에 담았다.

    새 함수 purchase_value_smoothed_stats가 EMA 스무딩된 loss·ratio-mae·target-ratio·baseline-mean-usd·usd-mae·calib을 발행한다. 기본 스무딩 창은 (1 << 28, 1 << 30) — 각각 2^28 ≈ 2.68억 샘플, 2^30 ≈ 10.7억 샘플 크기의 지수 이동 평균. trainer_recsys.py가 이 창 두 개에 대해 shape=(10,) 텐서를 EMA state로 유지하도록 훅 _purchase_value_ema_keys를 추가했고, 체크포인트 리로드 시점에서 shape 불일치가 나면 zeros로 재초기화한다.

    USD MAE(purchase-value_delayed_clicked-usd-mae)와 calibration(purchase-value_delayed_clicked-calib, 예측 ratio 총합 대비 실제 ratio 총합)도 새로 발행된다. 광고 매출 예측이 옥션에서 어떻게 재조정되는지에 관해서는 이번 커밋에 실 배선이 없고, purchase_value_loss_weight=0.0 기본은 유지된다.

    의미. 4세대+22에서 붙었던 광고 매출 회귀 loss가 "지연 관측 창 안"이면 무조건 학습에 들어가던 관행에서 "지연 관측이 조금(early) 발생한 슬라이스에만" 학습에 들어가는 관행으로 좁혀졌다. Late-split 슬라이스는 이제 twin classification 헤드만 학습하고 구매액 회귀는 하지 않는다. 즉 X의 광고 랭킹이 (a) 짧은 시차 관측에는 구매액을 회귀로 학습하고 (b) 긴 시차 관측에는 컨버전 여부만 분류로 학습하는 두 갈래 학습 스택으로 정착 중.

    C. Phoenix wire proto에 유저 광고 참여 이력의 시간창 카운트 채널 신설 (EngagementCounts)

    phoenix/crates/serving/xai-recsys-proto/proto/recsys.proto(+22)와 phoenix/python/common/xai-proto/proto/recsys.proto(+22) [확인].

    message EngagementCountRow {
  int32 action = 1;
  repeated uint32 counts = 2;
}

message EngagementCounts {
  bool present = 1;
  repeated uint32 window_secs = 2;
  repeated EngagementCountRow rows = 3;
  int64 updated_at_ms = 4;
  int64 window_end_ms = 5;
}

    두 슬롯에 배선됐다.

    • PredictNextActionsRequest.user_ads_engagement_counts = 24 — 유저 컨텍스트에 광고 참여 이력의 시간창 카운트 매트릭스.
    • AdInfo.engagement_counts = 23 — 각 후보 광고 자체가 갖는 참여 이력 시간창 카운트.

    즉 (action × time window) 이차원 카운트 매트릭스가 요청 페이로드에 실려 서빙 랭커로 들어간다. window_secs가 시간 창의 길이 리스트고, rows의 각 원소가 특정 액션 인덱스에 대해 그 창들에서 관측된 카운트를 나열한다. updated_at_ms·window_end_ms가 이 매트릭스의 시간 기준점.

    이 필드를 소비하는 서버 측 학습·배치 인코딩은 이번 커밋에 반영되지 않았다. Proto 층만 열렸고 xrex/data/recsys/*에는 관련 파싱 없음.

    의미. 4세대+9(2026-08-26)에서 ConvAssetIds가 유저의 최근 광고 크리에이티브 노출 이력을 요청에 실은 데 이은 후속. 이번엔 크리에이티브 asset이 아니라 액션 단위의 시간창 카운트가 대상이다. 각 광고 후보의 자체 engagement 이력과 유저의 광고 engagement 이력이 대칭적으로 열렸다는 점이 특징. 광고 랭킹에서 유저·아이템 페어의 최근 참여 통계가 명시 피처로 진입한다는 신호로, YouTube/Meta 계열의 "user × item time-window count" 표준 피처와 방향이 같다 [추정].

    D. Phoenix wire proto에 검색 렉시컬 매치 신호 신설 (SearchLexicalMatch)

    같은 두 proto 파일에서 TweetInfo에 새 필드가 붙었다.

    message TweetInfo {
  // ... 기존 필드 37개 ...
  SearchLexicalMatch searchLexicalMatch = 38;
}

message SearchLexicalMatch {
  float matchedWordFraction = 1;
  bool exactPhrase = 2;
}

    matchedWordFraction은 검색 쿼리 단어 중 트윗에 등장하는 비율, exactPhrase는 쿼리 문자열이 완전 일치로 등장했는지 여부. 검색 랭킹 config xrecsys_search에서 소비될 것으로 보이나 학습·서빙 소비 지점은 이번 커밋에 없다.

    의미. X의 오픈소스 미러 4세대 이후로 검색 랭킹 라인은 대체로 (a) xrecsys_search config가 별도로 돌고 (b) EarlyBird 스타일 렉시컬 매치는 후보 생성 단계에서 흡수되던 관행이 유지되어 왔는데, 이번엔 렉시컬 매치를 후보 자체의 wire 필드로 승격했다. 즉 렉시컬 매치가 후보 생성 신호에서 랭킹 신호로 통과할 채널이 열렸다. Elasticsearch/Lucene 계열의 BM25 스코어 대신 (fraction, exact_phrase) 두 축의 단순 통계를 넘기는 방식으로, X 특유의 짧은 텍스트·해시태그·핸들이 섞인 쿼리 도메인에서는 이 두 축이 오히려 노이즈에 강할 수 있다.

    E. grox 안전 파이프라인 신규 흐름 — 참조 영상 번들과 후보 영상을 VLM으로 비교하는 spam-clone 탐지

    grox/flows/ptos/plan_safety_ptos_media_injected_adult_infrared_video_spam_detection.py(44줄 신규) + task_safety_ptos_media_injected_adult_infrared_video_spam_detection.py(188줄) + task_safety_ptos_media_injected_adult_infrared_video_spam_detection_filter.py(55줄) + grox/core/data_loaders/media_reference_bundle.py(146줄 신규) [확인].

    Grox의 PTOS(Post Task Ordered Sequence)에 새 흐름이 붙었다. 이름이 길다: safety_ptos_media_injected_adult_infrared_video_spam_detection. Kafka 토픽 safety-ptos-media-injected-adult-infrared-video-spam-detection을 소스로 하는 streaming task generator가 이 흐름을 트리거한다.

    Eligibility 필터(TaskSafetyPtosMediaInjectedAdultInfraredVideoSpamDetectionFilter)는 다음 조건을 모두 요구한다.

    • 유저가 있음
    • 포스트나 인용된 포스트에 비디오가 있음
    • fav count가 media_hydration.deluxe_fav_count_threshold 이상(고참여 포스트)
    • 이미 NSFW로 플래그된 포스트가 아님

    통과한 포스트는 MediaReferenceBundleLoader.current("media_injected_adult_infrared_video_spam")으로 blobstore에서 참조 영상 번들을 가져온 뒤, VLM에 참조 영상 스토리보드와 후보 영상 스토리보드를 함께 넘긴다.

    번들 loader의 규격:

    • Blobstore URI(blobstore://<namespace>/<subpath> 형식)에서 manifest.json을 읽어 최대 10개의 참조 영상 스펙을 로드
    • 각 영상은 최대 10 프레임, 프레임 크기 최대 2 MiB
    • 15분 주기 리프레시(refresh_interval_s=900 기본), 최초 로드 실패 시 60초마다 재시도
    • 번들 identity를 위해 매니페스트 + 프레임 바이트의 SHA-256 digest 12자를 유지
