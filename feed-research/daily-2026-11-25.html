1영상 캐러셀 전용 인기 영상 소스가 생겼다 — X

자료 xai-org/x-algorithm@e005f95 — xAI, 2026-11-24, 코드. 이 노트들이 붙인 번호로는 4세대+70이다(4세대+N은 2026-08-13 4세대 공개 뒤의 커밋에 이 노트들이 차례로 붙인 번호다).

배경 X For You에는 피드 6번째 자리에 세로 영상 3~5개를 묶어 넣는 영상 캐러셀이 있고, 이 모듈은 2026-10-08 신설 뒤 지금까지 기본 off다. 캐러셀 후보는 메인 피드 후보 가운데 영상에서 고르는데, 최근 커밋들은 캐러셀만을 위한 후보 경로를 따로 만들고 있다. 2026-11-20 커밋은 Phoenix MoE retrieval(Phoenix 랭커 계열의 mixture-of-experts 후보 검색) 소스를 캐러셀 전용으로 켜는 스위치를 만들었다. 2026-11-21 커밋은 48시간 안에 조회 1만 회와 좋아요 100개를 넘긴 영상만 모으는 인기 영상 인덱스를 만들었다. 이번 커밋은 home-mixer(For You 요청을 받는 서비스)에 캐러셀 전용 인기 영상 소스를 추가하고, teacher 점수 캐시와 자동 제재 서비스도 고쳤다.

새로 알게 된 것A. 인기 영상 소스의 후보는 캐러셀에만 쓰이고, 소스는 기본 off다

  • home-mixer에 Phoenix retrieval 클러스터 하나에서 영상 후보를 최대 100개 받아 오는 인기 영상 소스가 생겼다 확인 — home-mixer/sources/popular_video_source.rs

    • 소스는 스위치가 켜지고, 캐러셀이 켜진 요청이고, Following 전용 요청이 아니고, 캐시된 후보를 다시 쓰는 요청이 아닐 때만 돈다.
    • 받아 온 후보에는 새 served type(후보가 들어온 경로를 나타내는 라벨) ForYouPhoenixRetrievalPopularVideo가 붙는다.

  • 소스 스위치와 클러스터 이름, 최대 개수는 크론 미러(프로덕션 feature-switch 기본값을 매일 동기화한 파라미터 파일)에 새로 들어갔고, 소스는 기본 off다 확인 — home-mixer/params/param.rs:1544-1567

  • 이 소스에서만 나온 후보는 항상 메인 피드 상위 선택에서 빠지고 캐러셀 후보로만 남는다 확인 — home-mixer/util/video_carousel.rs

    • 판정 함수 is_carousel_only는 후보의 모든 served type이 인기 영상이면 참이다. MoE 후보는 2026-11-20 커밋의 MoE 캐러셀 전용 스위치가 켜졌을 때만 참이다.
    • 다른 소스로도 들어온 영상은 메인 피드 경쟁에 그대로 남는다.
    • 테스트 popular_video_posts_are_carousel_only는 점수가 1000인 인기 영상 후보가 상위 선택에 들지 않고, 점수 없이 캐러셀 여분 후보로 붙는 것을 고정한다.

  • 캐러셀 후보를 인기 영상 소스의 영상으로만 한정하는 스위치도 생겼고, 기본 off다 확인 — home-mixer/util/video_carousel.rs

    • 2026-11-21 커밋의 MoE 한정 스위치와 함께 켜면 두 소스 가운데 하나로 들어온 영상만 캐러셀 후보가 된다.

  • 이 소스가 조회하는 클러스터가 2026-11-21 커밋의 인기 영상 인덱스라고 본다 추정.

    • 근거는 소스 이름과 served type 이름뿐이다. 클러스터 이름 "Experiment26Fou"를 인덱스 설정과 이어 주는 코드는 공개 레포에 없다.

새로 알게 된 것B. teacher 점수 캐시가 3시간을 버티고 다음 페이지 포스트도 담는다

  • teacher 점수(실제로 나간 포스트에 대해 프로덕션 Phoenix가 낸 행동별 확률을 학습 라벨로 남긴 것)의 캐시 보관 시간 기본값이 3,000초에서 10,800초로 늘었다 확인 — home-mixer/params/param.rs:1306-1311
    • 50분이 3시간이 된 것이다. 이 경로는 2026-11-19 커밋부터 기본 on이므로 실제 동작이 바뀐다.
  • 캐시된 후보를 다시 쓰는 다음 페이지 요청도 이제 teacher 점수를 남긴다 확인 — home-mixer/side_effects/teacher_score_side_effect.rs:127-190
    • 다음 페이지는 새 항목을 만들지 않고, 같은 예측 요청 ID의 첫 페이지 항목이 남아 있을 때만 그 항목에 포스트를 덧붙인다(append_if_exists_ex).
    • 첫 페이지 항목이 이미 만료됐으면 결과를 no_entry로 기록하고 아무것도 쓰지 않는다.
    • 테스트는 요청 7의 첫 페이지 포스트 1과 다음 페이지 포스트 2가 한 항목에 담기고, 첫 페이지가 없던 요청 8은 항목이 생기지 않는 것을 고정한다.
  • 보관 시간을 늘린 이유는 다음 페이지가 붙을 시간을 벌려는 것으로 본다 추정. 근거는 두 변경이 같은 커밋에 함께 들어왔다는 점뿐이다.

새로 알게 된 것C. 부모 포스트에서 멘션받아 단 답글은 자동 조치에서 빠진다

  • abuse-enforcement-service(모델 스코어로 계정과 포스트에 라벨·챌린지·정지 조치를 내리는 서비스)가 답글 포스트를 처리할 때 부모 포스트를 읽어, 부모 본문이 답글 작성자를 멘션했으면 조치를 건너뛴다 확인 — abuse-enforcement-service/service-lib/src/safety_checks.rs
    • 새 안전 검사는 invited_reply("the reply's parent post mentions the reply's author in its own text")와 invited_reply_unknown이다.
    • 멘션은 부모 포스트의 보이는 본문 범위(visibleTextRange) 안에 있는 것만 센다.
    • 이 범위 조건은 답글 앞에 자동으로 붙는 멘션 접두를 빼려는 것으로 본다 추정. 근거는 검사 설명의 "in its own text"라는 문구뿐이다.
    • 부모 조회 결과는 10분, 실패는 30초 동안 메모리에 캐시하고, 조회 시간 한도는 기본 3초다 — invited_reply.rs.
  • 부모 포스트를 읽지 못한 경우에도 조치를 건너뛴다 확인 — 같은 파일
    • 조회 실패를 제재 쪽이 아니라 건너뛰는 쪽으로 처리하는 fail-open 설계다.
  • 이 검사에는 스위치가 없고, 규칙이 이미 조치를 고른 경우에만 그것을 건너뛰기로 바꾼다 확인 — service-lib/src/rules.rs
    • 팔로워 수가 많아 건너뛰는 등 규칙이 이미 건너뛰기를 골랐으면 원래 이유를 유지한다. 테스트 invited_replies_stop_post_decisions_last_on_both_paths가 이를 고정한다.

정본 반영 services/x.md ## 한 줄 요약의 기준 커밋을 e005f95로 고쳤다. ## 피드 지면 캐러셀 항목에 인기 영상 소스 불릿을 추가했다. ### 학습·서빙 인프라에서는 teacher 보관 시간을 3시간으로, 실행 조건 문장을 다음 페이지 덧붙이기로 고치고 절 변경 이력에 한 줄을 더했다. 안전성 절의 abuse-enforcement-service 불릿 아래에 초대 답글 건너뛰기를, grox PtOS 불릿 아래에 클러스터 대표 포스트 판정 변경을 적었다. ## 출처의 git 로그 기준과 커밋 표, 변경 이력 요약표에 한 행씩 추가했다.

의미 X가 영상 캐러셀을 메인 피드와 다른 후보 공급원으로 채우려는 준비를 계속하고 있다. 2026-11-20 커밋부터 MoE 소스, 인기 영상 인덱스, 인기 영상 소스가 차례로 캐러셀 전용으로 들어왔지만 캐러셀과 이 소스들은 모두 기본 off다. 반면 teacher 캐시 변경과 초대 답글 건너뛰기는 스위치 없이 기본 동작을 바꾼다.

2LLM 에이전트가 추천 모델 가중치를 직접 고쳤다 — Pinterest

자료 Weight Coding: Evolving Web-Scale Recommenders through Direct Weight Edits with LLM Agents — Pinterest, 2026-11-22, 논문.

배경 대형 추천 모델은 보통 재학습이나 fine-tuning으로 개선하고, 한 번 개선해 출시할 때 오르는 지표는 작다. 2026-11-19에는 Meta가 LLM 에이전트로 광고 랭킹 모델의 피처를 고르는 A-MLE를 발표했고, 이 레이더는 에이전트가 모델 개발을 맡는 흐름을 지켜보고 있다. 이번 논문은 에이전트가 학습을 거치지 않고 학습된 가중치를 직접 고치는 방법을 Pinterest 프로덕션 모델에 적용한 결과를 보고한다.

새로 알게 된 것A. 가중치를 직접 고친 retriever가 온라인 A/B에서 저장을 최대 10.7% 늘렸다

  • LLM 에이전트가 모델 구조와 파라미터를 살펴 가설을 세우고 가중치를 고친 뒤, 평가 결과를 보고 다음 수정을 정하는 루프를 돈다 확인 — arXiv 2611.29613
    • 역전파 없이 순전파 평가만 빠르게 돌리는 캐시 엔진을 쓴다.
    • 수정은 국소 변경에서 시작해 표적 탐색과 조합으로 넓혀 간다.
  • 주 사례는 Pinterest Image Search의 147M 파라미터 two-tower retriever(유저와 아이템을 각각 임베딩하는 두 탑으로 후보를 찾는 모델)다 확인 — HTML 판
    • held-out recall@10이 프로덕션 모델보다 최대 15.0포인트(상대 +24%) 올랐고, 전체 post-training finetune의 약 1/4 GPU 시간이 들었다.
    • 13.6M 파라미터 interaction 모듈을 무작위로 다시 초기화한 뒤 혼합·정규화 파라미터 2,448개만 탐색해도 프로덕션보다 9.8포인트 높았다고 쓴다.
  • 서빙 변경 없이 배포했고, 온라인 A/B에서 고친 retrieval 소스의 유저당 closeup이 최대 7.6%, 저장이 최대 10.7% 늘었다 확인 — 같은 HTML 판
    • 오프라인 개선은 dense retrieval, 생성형 retrieval, 랭킹에 걸쳐 있고, 최대 1.37B 파라미터 모델까지 다룬다고 쓴다.

"Online A/B tests of the edited two-tower retriever increase closeups by up to 7.6% and saves by up to 10.7% per user for the edited retrieval source, with engagement and exposure changes aligned with the objectives." — Weight Coding (HTML), 2026-11-22
