1클릭 없이 늦게 일어난 광고 전환도 학습 대상이 됐다 — X

자료 xai-org/x-algorithm@6258a15 — xAI 공개 저장소, 2026-10-24 03:22 UTC 커밋, 코드. 이 노트들이 붙인 번호로는 4세대+49다. 4세대+N은 이 노트들이 4세대 공개(2026-08-13) 뒤의 X 커밋에 차례로 붙인 번호다. 크론 미러(프로덕션 feature-switch 기본값을 매일 동기화해 공개하는 파일)의 sync 시각은 2026-10-23T16:00:34Z다. 바뀐 파일은 56개이고, 41개는 Phoenix 학습 코드(phoenix/xrex)다.

배경 광고 전환(구매, 장바구니 담기, 가입처럼 광고주가 원하는 행동)은 광고를 본 지 며칠 뒤에 일어나기도 한다. 이렇게 늦게 도착하는 라벨을 delayed feedback이라고 부르고, 학습 시점에 아직 전환이 오지 않은 샘플을 음성으로 잘못 학습하는 문제가 생긴다. X의 Phoenix 랭커(유저 이력과 후보를 한 시퀀스에 넣어 행동 확률을 예측하는 트랜스포머)는 2026-09-18 커밋(4세대+24)부터 샘플을 신선 스트림, 이른 재라벨, 늦은 창의 세 출처로 나누고, 늦은 창에서만 학습하는 twin 헤드(기존 전환 헤드와 짝을 이루는 지연 전환 전용 예측 헤드)를 두었다. 그런데 지금까지 twin 헤드는 광고를 클릭한 뒤의 지연 전환만 다뤘다. 이번 커밋은 클릭 없이 광고를 본 것만으로 귀속되는 view-through 지연 전환 6종을 같은 방식으로 학습하게 한다.

새로 알게 된 것A. view-through 지연 전환 6종이 늦은 창 twin 헤드로 학습된다

  • 늦은 창 twin 헤드 목록이 클릭 기반 목록과 별도로 하나 더 생겼고, view-through 지연 전환 6종이 들어갔다 확인 — ads_late_window.py:18-25

    • 목록 이름은 ADS_LATE_WINDOW_VT_TWIN_HEAD_INDICES다.
    • 6종은 귀속 key view, 귀속 view, 구매, 장바구니, 결제 시작, 가입의 view-through 지연 전환이다(예: ADS_PURCHASE_CONVERSION_VIEW_THROUGH_DELAYED).
    • 이 행동들은 2026-10-13 커밋(4세대+40)에서 proto에 먼저 생겼고(234-251번 18개), 학습에 쓰이는 것은 이번이 처음이다.

  • 새 twin 헤드는 늦은 창 샘플이면서, 클릭이 없고, 같은 전환이 이른 창에 이미 관측되지 않은 후보에서만 학습한다 확인 — ads_head_masking.py:73-89

    • 클릭 기반 twin과 비교하면 조건 하나가 반대다: 클릭 twin은 click을, 새 twin은 ~click을 요구한다.
    • 웹 전환 학습을 유지하라는 비트(keep_web)가 켜진 후보만 쓴다.

  • 각 twin은 짝이 되는 신선 스트림 헤드를 가리키고, 이른 창에 그 짝이 이미 발화했으면 늦은 창에서 다시 학습하지 않는다 확인 — ads_late_window.py:27-44

    • 예를 들어 ADS_PURCHASE_CONVERSION_VIEW_THROUGH_DELAYED의 짝은 ADS_PURCHASE_CONVERSION_VIEW_THROUGH다.
    • 같은 전환을 두 번 양성으로 세지 않으려는 장치로 본다 추정. 짝 매핑의 변수 이름이 suppressor(억제자)라는 점이 근거다.

  • 이 경로는 학습 config의 광고 헤드 마스킹 옵션이 켜졌을 때만 동작하고, 옵션 기본값은 off다 확인 — ads_head_masking.py:41-53

    • 옵션은 ads_head_masking: bool이고, 기본 False는 4세대+24 때 확인한 값이다.
    • 픽셀 발화 매핑과 학습 메트릭 그룹에도 새 6종이 등록됐고, 메트릭 슬라이스 late_split_non_clicked_no_early가 생겼다.
