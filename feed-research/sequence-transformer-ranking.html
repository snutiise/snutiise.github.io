유저의 행동 이력을 토큰 시퀀스로 놓고, 점수를 매길 후보들을 같은 시퀀스 뒤에 붙여서 한 번의 forward pass로 전부 채점하는 랭킹 구조다. 전통적인 "피처 벡터 → MLP/DCN/MaskNet" 랭커와 대비된다.

이 노트는 X(Phoenix)와 Meta(HSTU 계보 / ads 계보) 둘을 함께 다룬다. 두 회사가 독립적으로 같은 결론에 도달한 부분(후보를 시퀀스에 넣고 마스크로 격리해서 점수를 캐시할 수 있게 만든다)과 갈라진 부분(Meta는 계보가 둘인데 서로를 인용하지 않는다), 이 두 가지가 이 노트를 관통하는 기준이다.

왜 이 구조인가

  • 피처 엔지니어링을 어텐션으로 대체한다. 유저×아이템 cross feature를 손으로 만드는 대신, 후보 토큰이 이력 토큰을 직접 어텐션으로 참조한다. 추정 — X가 "hand-engineered feature를 전부 없앴다"고 주장하는 근거가 이 구조다.
  • 후보 N개를 한 시퀀스에 담으면 이력 인코딩 비용을 N개가 공유한다. 후보마다 따로 forward를 돌리는 것보다 비용이 적다. 추정 — 어텐션 마스크 설계상 그렇게 되며, X가 후보 블록을 시퀀스에 넣는 이유로 달리 설명하기 어렵다.

↑ 목차

핵심 설계 요소

1. 시퀀스 레이아웃

[user] + [history × S] + [candidates × C] 를 하나의 flat 시퀀스로 만드는 것이 X의 방식이다. 확인 xai-org/x-algorithm, 2026 — phoenix/recsys_model.py:617-624

2. 어텐션 마스크 — 설계에서 가장 중요한 부분

후보끼리 서로 볼 수 있게 하느냐가 pointwise 랭킹이냐 slate 최적화냐를 가른다.

X는 후보 블록에서 대각선만 남긴다(self-attend only). 확인 — phoenix/grok.py:39-71, 유닛테스트 phoenix/test_recsys_model.py:94-121

        user  h1  h2  c1  c2  c3
user  [  1    0   0   0   0   0 ]
h1    [  1    1   0   0   0   0 ]
h2    [  1    1   1   0   0   0 ]
c1    [  1    1   1   1   0   0 ]
c2    [  1    1   1   0   1   0 ]
c3    [  1    1   1   0   0   1 ]

결과적으로 후보 점수는 같은 배치에 무엇이 들어왔는지와 무관하다. 그래서 점수를 캐시할 수 있고, 리스트를 잘라 여러 번 호출해도 결과가 같다. X가 README에서 명시적으로 목표라고 밝힌 성질이다. 확인 — README.md:328

주의할 점이 세 가지 있다.

  • 유저 토큰(position 0)은 causal mask 때문에 자기 자신만 본다. 이력을 요약하는 토큰이 아니라 다른 토큰이 읽어가는 prefix/bias 토큰이다. 확인 — test_recsys_model.py:105-107
  • X의 phoenix/README.md:158은 "User + History: Full bidirectional attention among themselves"라고 쓰는데 코드는 strictly causal이다. README와 코드가 정면으로 어긋난다. 확인 — grok.py:62 (jnp.tril) vs phoenix/README.md:158
  • 마스크가 배치 독립성을 보장해도 RoPE가 깨뜨린다. right_anchored_rope=False(기본값)면 후보 슬롯 0과 슬롯 40이 서로 다른 회전을 받아 점수가 달라진다. 이를 고치는 헬퍼(right_anchored_rope_positions)가 코드에 있는데, 공개된 파이프라인은 그 헬퍼를 켜지 않는다. 확인 — grok.py:88-109, recsys_model.py:362, run_pipeline.py:132-162

3. 파라미터가 어디에 있는가

X Phoenix의 경우 99.8%가 ID 임베딩 테이블이고 트랜스포머는 0.8M에 그친다. 추정 — 공개 mini config(128-dim, 4-layer, vocab 1M×3)로 계산한 값이며, 체크포인트가 Git LFS에 있어서 직접 세어 보지는 못했다. 근거 수치는 phoenix/README.md:222-230이 밝힌 파일 크기(model_params.npz 3MB, embedding_tables.npz 1.4GB)와 일치한다.

이것이 함의하는 바는 다음과 같다. 임베딩 테이블은 별도 서비스나 호스트 메모리에 두고 트랜스포머만 가속기에서 돌리는 서빙 구조가 자연스럽다. 실제로 공개 코드는 임베딩 lookup을 모델 바깥에서 numpy fancy-indexing으로 처리한다. 확인 — recsys_model.py:103-116, run_pipeline.py:292-297

4. 콘텐츠는 들어가지 않는다

X Phoenix에는 텍스트도 이미지도 들어가지 않는다. 토큰은 해시된 ID + 소수의 categorical/scalar 채널뿐이다. 확인 — recsys_model.py:238-250, :307-314

들어가는 것은 post ID 해시 2개, author ID 해시 2개, 행동 multi-hot, product surface(16종), post age 버킷, dwell time이다. 들어가지 않는 것은 팔로워 수, 참여 수, 작성자 평판, 텍스트/토픽/언어, cross feature다.

↑ 목차

"hand-engineered feature 제거" 주장의 실제 범위

X README는 "We have eliminated every single hand-engineered feature and most heuristics from the system"이라고 쓴다. 확인 — README.md:55

문자 그대로는 거짓이다. 모델 안에 손으로 만든 것이 다음과 같이 남아 있다.

  • post age 버킷은 4800분(80시간) 지평, 60분 granularity, overflow/missing 센티널까지 전부 사람이 고른 값이다. 확인 recsys_model.py:33-55
  • dwell 정규화는 30초에서 clip하고 선형으로 스케일한다. 확인 recsys_model.py:58-90
  • product surface는 16-way categorical이고, 그 값은 Rust 쪽 if문이 정한다. 확인 home-mixer/scorers/phoenix_scorer.rs:73-77
  • ID 해싱은 직접 만든 linear-congruential 해시를 쓰고, entity당 해시가 2개이며, magic offset은 pad = 65이다. 확인 run_pipeline.py:76-129
  • 행동 어휘 19종과 2x-1 signed 인코딩도 사람이 정했다. 확인 recsys_model.py:425

정확한 표현은 **"콘텐츠·작성자 피처를 없앴다"**이다. 시간·표면·해싱 처리는 그대로 남아 있다. 그리고 이것은 모델 안의 이야기이고, 그 바깥 서빙 레이어에는 필터 17개와 손으로 튜닝한 상수가 많이 있다. x.md를 참조하라.

↑ 목차

Meta — 트랜스포머 계보가 하나가 아니라 둘이다

"Meta의 시퀀스 모델"을 단수로 말하면 틀린다. 유기(organic) 쪽 HSTU 계보와 광고 쪽 DHEN→GEM 계보가 따로 있으며, 아래에서 확인한 대로 서로를 인용하지 않는다.

↑ 목차

계보 A (organic) — HSTU → ULTRA-HSTU

확인 Actions Speak Louder than Words: Trillion-Parameter Sequential Transducers for Generative Recommendations, ICML 2024 (arXiv 2024-02)

X의 Phoenix가 "기존 랭커를 트랜스포머로 바꾼다"라면 HSTU는 문제 정의 자체를 바꾼다.

(1) 피처 전체를 하나의 시계열로 합친다

"In GRs, we consolidate and encode these features into a single unified time series." 확인

방법도 구체적으로 밝혀져 있다. 카테고리 피처는 가장 긴 시계열(주로 유저가 engage한 아이템)을 main time series로 삼고, 천천히 변하는 것(데모그래픽, 팔로우한 크리에이터)은 "keeping the earliest entry per consecutive segment" 로 압축해 병합한다. 확인

(2) numerical feature를 버리는 근거가 명시되어 있다

X README의 "hand-engineered feature를 전부 없앴다"는 주장(위 절 참조)과 겉보기가 비슷한데, HSTU는 왜 버려도 되는지를 논증한다:

"the categorical features (e.g., item topics, locations) over which we perform these aggregations are already sequentialized and encoded in GRs. Hence, we can remove numerical features in GRs given a sufficiently expressive sequential transduction architecture coupled with a target-aware formulation ... can meaningfully capture numerical features as we increase the overall sequence length and compute" 확인

즉 counter/ratio는 카테고리 시퀀스의 집계값이니 시퀀스가 충분히 길면 모델이 재구성한다는 논리다. 그리고 검증도 함께 붙어 있다. DLRM에 GR과 같은 피처만 주면 *"the performance of DLRMs is significantly degraded"*라는 결과가 나온다. 확인 추정 X의 동일 주장에는 이런 ablation이 없다. 같은 문장이라도 뒷받침하는 근거의 양이 다르다.

(3) retrieval과 ranking이 같은 시퀀스 위의 다른 태스크가 된다

  • retrieval: 다음 아이템 예측 p(Φ_{i+1}|u_i)
  • ranking: 아이템과 액션 토큰을 번갈아 끼워서 p(a_{i+1}|Φ_0, a_0, Φ_1, a_1, ..., Φ_{i+1})

interleaving을 하는 이유는 X의 마스크 설계가 다루는 문제와 정확히 같은 종류다. 논문의 설명은 다음과 같다: "'interaction' of target ... and historical features needs to occur as early as possible, which is infeasible with a standard autoregressive setup where 'interaction' happens late (e.g., via softmax after encoder output)". 확인

(4) softmax를 버린다 — 두 가지 이유가 명시되어 있다

HSTU는 *"pointwise aggregated (normalized) attention"*을 쓴다. 비선형 함수로는 SiLU를 쓴다. 확인

  • "the number of prior data points related to target serves as a strong feature indicating the intensity of user preferences, which is hard to capture after softmax normalization". 즉 softmax는 정규화 때문에 "몇 번 봤는가"라는 정보를 지운다. dwell/time-spent 같은 강도를 예측하는 것이 목표라면 치명적이다.
  • "while softmax activation is robust to noise by construction, it is less suited for non-stationary vocabularies in streaming settings" 확인

(5) 상대 위치 bias가 위치와 시간을 모두 담는다

rab^{p,t}는 "relative attention bias that incorporates positional" 항이며, 시간 항도 함께 담는다. 확인 X는 이 자리를 RoPE로 처리했고, 그것이 배치 독립성을 깨는 원인이 되었다(위 주의할 점 3). 같은 슬롯을 두 회사가 다르게 채웠고, 부작용도 다르다. 추정

(6) M-FALCON — X의 후보 블록 마스크와 같은 문제를 다르게 푼다

*"M-FALCON (Microbatched-Fast Attention Leveraging Cacheable OperatioNs)"*을 쓴다. 후보 m개를 b_m개씩 마이크로배치로 나누고 어텐션 마스크와 bias를 조정한다: "modifying attention masks and rab^{p,t} biases such that the attention operations performed for b_m candidates are identical". 그리고 캐시를 이렇게 활용한다: "leverage encoder-level KV caching ... either across forward passes to reduce cost, or across requests to minimize tail latency". 확인

여기가 이 노트에서 제일 중요한 교차점이다. X는 후보 블록을 대각선 마스크로 격리해 점수를 캐시 가능하게 만들었고, Meta는 후보 마이크로배치 + KV 캐시로 이력 인코딩 비용을 상각했다. 두 회사가 독립적으로 "후보를 시퀀스에 넣되 후보끼리는 격리한다"에 도달했다. 추정 — 근거는 두 문헌의 마스크 설명이 기능적으로 같은 성질(후보 간 독립 + 재사용 가능한 prefix)을 목표로 한다는 것이다.

성과 수치 확인: 8192 길이에서 FlashAttention2 기반 Transformer 대비 **5.3×–15.2×**이고, DLRM 대비 285× 복잡한 모델을 1.50×–2.99× 높은 QPS로 처리하며, 프로덕션 지표는 12.4% 개선되었다.

⚠ 지면이 익명화되어 있다. 논문은 *"a large internet platform"*이라고만 쓴다. Facebook Feed에 적용되었는지는 확인하지 못했다. facebook.md의 열린 질문 5를 보라.

ULTRA-HSTU (2026) 확인 arXiv 2602.16986, 2026-02-19. 후속작인데 직전 세대를 비판하면서 시작한다: "many recent approaches rely heavily on cross-attention mechanisms to address the quadratic computational bottleneck in sequential modeling, which can limit the representational power gained from self-attention." 결과로는 "over 5x faster training scaling and 21x faster inference scaling", "serving billions of users daily", *"4% to 8% consumption and engagement improvements"*를 제시한다.

추정 cross-attention 비판은 DV365처럼 "미리 압축해서 덧붙이는" 접근을 견제하는 말로 읽힌다. 같은 회사 안에서 초장기 히스토리를 처리하는 두 전략이 경쟁하고 있다는 뜻이다. 다만 논문이 DV365를 직접 지목하지는 않는다.

계보 B (ads) — DHEN → Wukong → InterFormer → GEM, 서빙은 MARM

광고 쪽은 피처 상호작용(feature interaction) 계보에서 출발해 뒤늦게 시퀀스를 추가했다. HSTU와 출발점이 다르다. 추정 — 아래 표의 발표 순서(2022 DHEN·2024 Wukong은 interaction, 2024 InterFormer부터 시퀀스)가 근거다.

연도 이름 무엇을 푸는가 출처
2022 DHEN 이종 interaction 모듈의 계층적 앙상블. NE 0.27%, 학습 throughput 1.2× 확인 arXiv 2203.11014
2024 Wukong stacked factorization machine만으로 scaling law 성립. 100 GFLOP/example 이상까지 확인 arXiv 2403.02545
2024 InterFormer 시퀀스 학습과 cross-feature를 interleaving. early summarization 회피 확인 arXiv 2411.09852
2025 GEM 위 둘을 포함하는 ads foundation model 확인 GEM 블로그, 2025-11-10
2026 LLaTTE GEM의 시퀀스 파트. 2-stage + 비동기 upstream user model 확인 arXiv 2601.20083, 2026-01-27
2026 MARM 요청별 라우팅 서빙. O(1T) 파라미터 확인 MARM 블로그, 2026-03-31
2026-02 Kunlun GDPA·HSP·Sliding Window Attention + CompSkip·Event-level Personalization. B200에서 MFU 17% → 37%, "deployed in major Meta Ads models" 확인 arXiv 2602.10016, 2026-02-10 (v3 2026-06-05)
2026-08 GEM training 훈련 인프라: 12개월 E2E MFU 2배, 총 FLOPs 4배. 커스텀 커널(JFA·GDPA·BlockAttention) + MXFP8 + 5D 병렬 확인 GEM Training 블로그, 2026-08-03
2026-10 GEM 2026 세대 백본이 InterFormer → Kunlun으로 교체. 도메인별 모델을 단일 중앙 모델로 통합, 하위 모델 전이는 LoopFM·distillation·Solaris 확인 GEM 2026 블로그, 2026-10-13

GEM 블로그가 계보를 직접 밝힌다 확인: "GEM enhances the Wukong architecture to use stackable factorization machines with cross-layer attention connections", "Our design, InterFormer, employs parallel summarization with an interleaving structure that alternates between sequence learning ... and cross-feature interaction layers."

LLaTTE가 이 노트에서 중요한 이유 확인 (블로그 From User Sequences to Scaling Laws, 2026-08-05 + arXiv 2601.20083):

  • 시퀀스 모델을 랭커 안에 두지 않고 비동기 upstream user model로 빼낸다: "a two-stage architecture that offloads the heavy computation of large, long-context models to an asynchronous upstream user model". Instagram DV365와 같은 전략이며, 이는 아래에서 다시 다룬다.
  • ⚠ **어제(2026-08-09) 정본이 인용한 "Deployed as the largest user model at Meta", "4.3% conversion uplift on Facebook Feed and Reels"는 2026-08-05 블로그 본문에 없다 관찰 2026-08-10 원문 재확인. 논문에서 인용한 문장일 가능성이 있으나 아직 재검증하지 못했다. 블로그 본문의 실측 A/B 수치는 *"a cumulative lift of 6% in conversions on Instagram, 3% in conversions on Facebook and 3.5% in ad clicks on Facebook"*이다. 여기에는 "cumulative"와 "broader model innovations" 포함이 명시되어 있어서 LLaTTE 단독 효과가 아니다 확인
  • 핵심 정식화 (블로그 원문): "(1) a multi-stage sequence model that decouples heavy offline user modeling from lightweight online ranking tasks and (2) a learning technique based on dense tokenization and target-aware attention that efficiently learns feature interactions directly from data". 스케일링 법칙을 "prerequisite"라는 표현으로 확인하려면 논문을 봐야 한다(위 재검증 항목).
  • "semantic features bend the scaling curve: they are a prerequisite for scaling". 이것은 의미 피처 없이는 스케일링 자체가 되지 않는다는 주장이다. HSTU가 "raw categorical engagement feature만으로 간다"고 한 것과 방향이 반대다. ⚠ 이 인용도 블로그 본문에는 없다 관찰 2026-08-10, 논문을 다시 확인해야 한다. 블로그의 대응 문장은 *"Semantic content features from foundation models complement traditional collaborative filtering... especially helpful in cold-start scenarios"*이고, 이는 "prerequisite"보다 완화된 표현이다. LLM에서 유래한 피처 이야기는 llm-in-recsys.md에 있다.
  • 블로그 본문: "This unified platform for sequence modeling is a core component of Meta's Generative Ads Recommendation Model (GEM)". 이 문장으로 LLaTTE ⊂ GEM 관계는 1차 출처로 확정된다.

GEM training 인프라 — 2026-08-03 블로그가 들어가는 자리 확인 Training GEM at LLM Scale, 2026-08-03:

  • GEM의 규모 정의: "the foundation model behind ads recommendations across Instagram and Facebook, now trains at LLM scale on several thousand of the latest-generation GPUs". 하이브리드 아키텍처는 *"trillions of sparse embedding parameters and billions of dense parameters"*로 설명한다.
  • 12개월 결과 명시: "we doubled GEM's E2E training efficiency to 20-25% MFU while scaling total training FLOPs 4x over the past 12 months". 여기서 baseline은 GEM 초기 공개(2025-11) 이전이고, metric은 end-to-end Model FLOPs Utilization이다.
  • 커스텀 커널이 필요한 이유가 흥미롭다: "AI infrastructure optimized for LLM training (kernels, parallelism, low precision recipes etc.) does not directly transfer". LLM 스택을 그대로 재사용하지 못한다는 뜻이다. 추천 시스템의 sparse embedding과 jagged tensor, 이질적인 attention이 그 원인이다.
  • Compute efficiency: JFA (Jagged Flash Attention), GDPA (Generalized Dot-Product Attention), BlockAttention + MXFP8 attention·MLP. Scaling efficiency: 2D FSDP + Expert Parallelism (dense) + Fully Sharded 2D Model Parallelism (sparse) + SM-free collectives로 통신 오버헤드를 줄인다.
  • DHEN의 위치가 명확해진다. 블로그 본문에 *"Deep Hierarchical Ensemble Network experts"*가 GEM의 expert 모듈로 남아 있다. 대체가 아니라 흡수다. 계보 표의 "GEM = Wukong·InterFormer 통합"은 유효하고, DHEN도 그 안에 있다.
  • 함의: 이 글로 계보 표의 GEM 항목이 처음으로 훈련 인프라 쪽에 구체적 수치를 갖게 된다. 지금까지 GEM은 아키텍처 통합(Wukong+InterFormer)만 알려져 있었다.

GEM 2026 세대 — 2026-10-13 블로그가 바꾼 것 확인 Meta's Generative Ads Model (GEM): Scaling the Central Model and Compute Engine for Frontier Ads AI, 2026-10-13 (블로그, 저자 표기 없음):

  • ⚠ 주장 변경: 백본이 InterFormer에서 Kunlun으로 바뀌었다. 위 표의 "GEM = Wukong·InterFormer 통합"은 2025-11 세대 설명이다. 블로그는 Kunlun을 *"the previous version (Interformer)"*와 비교한다.

    "Compared to the previous version (Interformer), Kunlun delivers 2x performance gains with the same computation scaling."

    Kunlun은 2026-02 논문(arXiv 2602.10016)으로 먼저 나왔고, 논문 초록도 *"Kunlun is now deployed in major Meta Ads models"*라고 쓴다. CompSkip(일부 구성요소를 건너뛰는 계산 생략)은 *"reduce FLOPS by 43% with negligible quality loss"*로 설명된다.

  • 도메인별 모델을 하나로 합쳤다. 블로그 표현은 *"The 2026 generation of GEM shifts from isolated per-domain optimizations — such as Facebook, Instagram, Reels — to a single central foundation model."*이다. 공유 expert와 도메인 전용 expert를 함께 두고, 지면별 데이터를 물리적으로 합치지 않고 가상으로 섞어 학습한다.

  • 시퀀스 길이: 프로덕션에서 장기 참여 이력 길이를 2배로 늘렸고, 25배까지 늘릴 수 있는 역량을 확인했다고 쓴다. 모델 복잡도는 이전 GEM 대비 2.5배다.

  • 하위(vertical) 모델로 지식을 옮기는 방법이 세 가지로 정리됐다. (1) LoopFM은 GEM의 내부 표현과 장기 이력 메모리를 하위 모델에 넘기는 post-training 기법이고, *"2x of transfer effectiveness beyond knowledge distillation"*이라고 주장한다. (2) soft label distillation을 함께 쓴다. (3) Solaris는 다음 요청에 필요할 user-ad 쌍의 GEM 임베딩을 미리 계산해 두는 방식이다.

    "It speculatively precomputes foundation model embeddings for the user-ad pairs a future request is likely to need, and delivers them just-in-time on the serving hot path."

  • 성과 수치(블로그): "18.9% conversion improvement and 12% ad click-through rate (CTR) improvement across Meta's ad surfaces and objectives", 그리고 *"5.8%, 4.1%, and 1.6% conversion uplift on Facebook, Instagram, and off-site conversion for targeted users over the past year"*다. 앞의 두 수치는 기간과 기준선을 밝히지 않았고, 뒤의 세 수치는 "지난 1년" 누적이다. A/B 설계는 공개하지 않았다 확인(본문에 설계 서술이 없다).

  • 유기 피드와의 관계: 지금은 광고 데이터만 학습한다. 앞으로 *"extend GEM to learn from all of Meta's platform data, capturing behavior across organic and ads engagements"*라고 쓴다. 계보 A(HSTU)와 계보 B가 데이터 수준에서 합쳐질 수 있다는 첫 공식 진술이다 추정 — 계획 진술이지 배포 사실이 아니다.

  • Solaris는 LLaTTE의 "비동기 upstream user model"과 같은 방향이다. 무거운 계산을 요청 경로 밖에서 미리 해 두고 랭커는 결과만 읽는다 추정 — 두 블로그가 서로를 인용하지 않으므로 같은 시스템인지는 알 수 없다.

  • 같은 주(2026-10-12)에 나온 Turning Opportunistic AI Inference Capacity Into Better Ads Recommendations(블로그)는 유휴 추론 용량이 생길 때 랭킹 후보를 더 많이 평가하거나(Rank More Ads) 더 큰 모델로 요청을 보내는(Serve Better Models) 방식을 설명한다 확인. 효과 수치는 공개하지 않았다.

MARM은 GEM을 서빙한다고 말하지 않는다. MARM 블로그 본문에 GEM은 등장하지 않는다 (사이드바 "Related Posts" 링크에만 있다. 2026-08-09 전문 확인). 자기 규정은 "replaces a 'one-size-fits-all' inference approach with intelligent request routing" + O(1T) 파라미터 스케일링이다. "MARM이 GEM을 서빙한다"는 그럴듯하지만 1차 출처가 없다. 추정 — 근거는 같은 조직, 같은 시기, 같은 광고 지면이라는 정황뿐이다.
