In the service I currently operate, important logs are written separately to the DB, but all other logs (nginx, worker, talk, etc.) are managed only through syslog.

The logs grew to tens of GB per day, so analysis took a long time. (I am actually still using GoAccess!)

As the logs keep growing, I built a separate log server stack to store and manage them.

I decided to build the server with the ELK stack, which is the most popular and has plenty of references.

<img src="{{ "/assets/img/2020-11-13-1.png"}}" alt="Elastic Stack overview diagram. The Beats, Logstash, and Kibana icons are connected to the Elasticsearch gear in the center" loading="lazy" decoding="async" width="746" height="451">

For nginx logs, I planned to store them on a dedicated server through rsyslog (on the advice of a senior developer, who said it is needed for attaching directly to the server and running tail and grep!) and then send them to logstash. All other logs would go to logstash directly through filebeat. Logstash would then load the parsed format into elasticsearch.


First, I checked the latest compatible version on the official website.

<a href='https://www.elastic.co/kr/support/matrix'>https://www.elastic.co/kr/support/matrix</a>

The current server uses CentOS 7, so I installed version 7.9, the latest as of the day I did the build!

The column headers are cut off, and each cell has a supported check mark or an X" loading="lazy" decoding="async" width="1133" height="212"></a>

First, add the es PGP key to rpm.

{% highlight bash %}
# Import the Elasticsearch PGP Key
$ rpm --import https://artifacts.elastic.co/GPG-KEY-elasticsearch
{% endhighlight %}

Then create the repo information...

{% highlight vim %}
# vim /etc/yum.repos.d/elasticsearch.repo
[elasticsearch]
name=Elasticsearch repository for 7.x packages
baseurl=https://artifacts.elastic.co/packages/7.x/yum
gpgcheck=1
gpgkey=https://artifacts.elastic.co/GPG-KEY-elasticsearch
enabled=0
autorefresh=1
type=rpm-md
{% endhighlight %}

Install es!

{% highlight bash %}
# install elasticsearch
$ yum install --enablerepo=elasticsearch elasticsearch
{% endhighlight %}

If the installation went well, configure the settings file in etc to fit your environment.

{% highlight bash %}
$ vim /etc/elasticsearch/elasticsearch.yml
{% endhighlight %}

Be sure to include the security-related options in the settings!

{% highlight bash %}
# generate p12
$ bin/elasticsearch-certutil cert -out config/elastic-certificates.p12 -pass ""
{% endhighlight %}

Create the p12 certificate and enable the security options in the settings file as shown below!

<img src="{{ "/assets/img/2020-11-13-3.png"}}" alt="Security settings. Set xpack.security.enabled and xpack.security.transport.ssl.enabled to true, verification_mode to certificate, and keystore.path and truststore.path to /etc/elasticsearch/elastic-certificates.p12" loading="lazy" decoding="async" width="659" height="86">

The certificate is needed for TLS communication with other es nodes!

Once the certificate is set up, generate the ID and password as well.

{% highlight bash %}
# generate id / passwrod
$ bin/elasticsearch-setup-passwords auto
{% endhighlight %}

It asks whether to generate them automatically or enter them manually, and I chose automatic generation because I was lazy! (It makes nice long ones for you!)

Keep the ID and password generated this way in a safe place.

Now start elasticsearch.

{% highlight bash %}
# start elasticsearch
$ systemctl start elasticsearch
{% endhighlight %}

Once the installation is complete, edit the settings file.

Filebeat has to connect to logstash, so edit the host of output.logstash and enable it.

{% highlight bash %}
$ vim /etc/filebeat/filebeat.yml
{% endhighlight %}

If you use filebeat.config.modules,

you can check the list as shown below.

{% highlight bash %}
$ filebeat modules enable system
$ filebeat modules list
{% endhighlight %}

In filebeat.inputs you can configure the input that serves as the source. We use various kinds of sources on several nodes, so I edited each one separately.

{% highlight bash %}
filebeat.inputs:
- type: log
  paths:
    - /var/log/system.log
    - /var/log/wifi.log
- type: log
  paths:
    - "/var/log/nginx/*"
  fields:
    service: nginx
  fields_under_root: true
{% endhighlight %}

As in the example above, you can add type and fields according to the source you want.

Once filebeat is installed correctly, all that remains is writing the logstash pipeline!

Some steps were repeated during installation. If you install everything on a single server, you can skip some of them, for example adding the PGP key.

The last task, the logstash pipeline, has endless possibilities depending on the incoming source.

{% highlight shell %}
input {
  beats {
    port => 5044
    host => "0.0.0.0"
  }
}
filter {
  if [fileset][module] == "nginx" {
    if [fileset][name] == "access" {
      grok {
        match => { "message" => ["%{IPORHOST:[nginx][access][remote_ip]} - %{DATA:[nginx][access][user_name]} \[%{HTTPDATE:[nginx][access][time]}\] \"%{WORD:[nginx][access][method]} %{DATA:[nginx][access][url]} HTTP/%{NUMBER:[nginx][access][http_version]}\" %{NUMBER:[nginx][access][response_code]} %{NUMBER:[nginx][access][body_sent][bytes]} \"%{DATA:[nginx][access][referrer]}\" \"%{DATA:[nginx][access][agent]}\""] }
        remove_field => "message"
      }
      mutate {
        add_field => { "read_timestamp" => "%{@timestamp}" }
      }
      date {
        match => [ "[nginx][access][time]", "dd/MMM/YYYY:H:m:s Z" ]
        remove_field => "[nginx][access][time]"
      }
      useragent {
        source => "[nginx][access][agent]"
        target => "[nginx][access][user_agent]"
        remove_field => "[nginx][access][agent]"
      }
      geoip {
        source => "[nginx][access][remote_ip]"
        target => "[nginx][access][geoip]"
      }
    }
    else if [fileset][name] == "error" {
      grok {
        match => { "message" => ["%{DATA:[nginx][error][time]} \[%{DATA:[nginx][error][level]}\] %{NUMBER:[nginx][error][pid]}#%{NUMBER:[nginx][error][tid]}: (\*%{NUMBER:[nginx][error][connection_id]} )?%{GREEDYDATA:[nginx][error][message]}"] }
        remove_field => "message"
      }
      mutate {
        rename => { "@timestamp" => "read_timestamp" }
      }
      date {
        match => [ "[nginx][error][time]", "YYYY/MM/dd H:m:s" ]
        remove_field => "[nginx][error][time]"
      }
    }
  }
}
output {
  elasticsearch {
    hosts => localhost
    manage_template => false
    index => "%{[@metadata][beat]}-%{[@metadata][version]}-%{+YYYY.MM.dd}"
  }
}
{% endhighlight %}

As in the example above, if you used the nginx module, you can branch on the incoming module information.

You can also branch on the fields coming from filebeat, as shown below.

{% highlight shell %}
# vim /etc/logstash/conf.d/nginx-pipeline.conf
filter {
...
    if [service] == "nginx"{
        grok {
        }
    }
...
{% endhighlight %}

For the logs parsed by the pipeline to be loaded into elasticsearch, you must also provide the ID and password created earlier.

Add the user and password fields to the elasticsearch output.

{% highlight shell %}
output {
  elasticsearch {
    hosts => "elasticsearch:9200"
    user => "user"
    password => "pass"
    action => "index"
    manage_template => false
    index => "%{[@metadata][target_index]}"
  }
}
{% endhighlight %}
